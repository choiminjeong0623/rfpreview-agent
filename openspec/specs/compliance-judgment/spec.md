# compliance-judgment Specification

## Purpose
요구값과 우리 제품값을 코드로 비교해 판정 5종으로 나누고(지키기), 요구보다 나은 정도(여유)를 함께 계산해 강점 후보의 바탕을 만든다 (FR-07).

## Requirements

### Requirement: 판정 5종
시스템은 묶음 A·B 문서의 요구값마다 준수 / 일탈 후보 / 질의 후보 / 확인 필요 / 보증값 작성 중 하나로 판정하고, 비교 제품 행·제품값·규칙 ID·사유를 남겨야 한다(SHALL). 판정은 코드만 한다(CR-01). 묶음 C·D는 판정하지 않는다(CR-09).

#### Scenario: 요구를 넘는 제품
- **WHEN** 요구 주모선 4,000 A(230 kV GIS)를 제품 GIS-245-50 최대 3,150 A와 비교하면
- **THEN** 일탈 후보이다

#### Scenario: 묶음 C 문서
- **WHEN** 묶음 C 문서의 요구사항을 판정하려 하면
- **THEN** 판정을 만들지 않는다

### Requirement: 확인 필요로 보내는 경우
시스템은 제품값이 없거나, 단위가 다르거나, 규격 위임이거나, 요구 "<"와 제품 "≤"가 같은 숫자에서 만나면 "확인 필요"로 판정하고 여유를 계산하지 않아야 한다(SHALL). 맞는 정격 행이 없으면 "확인 필요 — 기준값 없음"이다.

#### Scenario: 제품값 없음
- **WHEN** 요구 "<0.5 %"를 GIS-145(누설값 없음)와 비교하면
- **THEN** 확인 필요이고 여유는 계산하지 않는다

#### Scenario: 단위가 다름
- **WHEN** 단위가 다른 요구값과 제품값을 비교하면
- **THEN** 확인 필요이고 여유는 계산하지 않는다

### Requirement: 시간 조건
시스템은 같은 값이면 제품 시간이 요구 시간 이상일 때 준수로 판정해야 한다(SHALL) [결정]. 다른 조건 차이는 확인 필요이다.

#### Scenario: 40 kA 1초 요구, 3초 제품
- **WHEN** 요구 "40 kA (1초)"를 제품 GIS-145 "40 kA (3초)"와 비교하면
- **THEN** 준수, 비교 제품 GIS-145, 여유는 시간 3배, 방향은 강점이다

### Requirement: 비교 제품 선택과 바꿔 보기
시스템은 요구 정격(전압·주파수·규격 체계)으로 product_master에서 비교 제품을 고르고, 설계 사례 카드는 기본으로 고르지 않아야 한다(SHALL). 엔지니어가 비교 제품을 바꾸면 다시 판정하고 이전 판정은 현재가 아님으로 남겨야 한다(SHALL). 비교 제품은 화면에 보여야 한다.

#### Scenario: 비교 제품에 따라 바뀌는 판정
- **WHEN** 요구 3,000 A·50 Hz(115 kV GIS)를 GIS-145(최대 3,150 A·50/60 Hz)와 비교한 뒤 GIS-145-P7로 바꾸면
- **THEN** 처음에는 준수 2건, 바꾼 뒤에는 일탈 후보 2건이고 이전 판정은 현재가 아님으로 남는다

### Requirement: 여유와 강점 방향
시스템은 준수일 때만 여유(차이 또는 배수)를 계산하고, 비교 방향 사전의 강점 방향과 같으면 "강점", 반대이거나 "강점 아님"이면 "강점 아님"으로 표시해야 한다(SHALL). [제안] 강점 방향 초안은 팀 확인 전이다.

#### Scenario: 강점이 아닌 여유
- **WHEN** 강점 방향이 "강점 아님"인 항목(무게 등)이 준수이고 여유가 있으면
- **THEN** 여유 방향은 강점 아님이다
