## MODIFIED Requirements

### Requirement: 머리글 사용자 고르기
화면은 로그인한 사용자의 이름과 역할을 머리글에 보여 주고, 모든 화면의 권한을 그 역할로 정해야 한다(SHALL). 로그인하지 않았거나 세션이 끝났으면 로그인 화면으로 보내야 한다(SHALL). 사용자 칩 겹창에는 로그아웃과 "다른 사용자로 로그인"을 두어, 누르면 서버 세션을 끝내고 로그인 화면으로 가야 한다(SHALL). 화면은 사용자를 브라우저에 따로 기억하지 않아야 한다(MUST NOT).

#### Scenario: 로그인한 사용자 보이기
- **WHEN** 기본 승인자로 로그인해 홈을 열고 새로 고치면
- **THEN** 머리글에 기본 승인자와 승인자 역할이 계속 보인다

#### Scenario: 사용자 바꾸기
- **WHEN** 엔지니어로 로그인한 사용자가 사용자 칩에서 "다른 사용자로 로그인"을 누르고 기본 승인자로 로그인하면
- **THEN** 엔지니어 세션은 끝나고 머리글에 기본 승인자와 승인자 역할이 보이며 새로 고쳐도 유지된다

#### Scenario: 로그아웃
- **WHEN** 기본 승인자로 로그인한 사용자가 사용자 칩에서 로그아웃을 누르면
- **THEN** 로그인 화면으로 가고, 뒤로 가기로 홈을 열어도 로그인 화면으로 돌아간다

#### Scenario: 세션 없이 화면 열기
- **WHEN** 로그인하지 않은 브라우저로 검토 목록 주소를 열면
- **THEN** 로그인 화면이 보이고, 로그인하면 검토 목록으로 간다

### Requirement: 예시 화면
시스템은 백엔드 기능이 없는 메뉴 화면(입찰 이력·상세, 표준 문구, 팀 현황, 공지사항, 시스템 공지, 자료실, 설정)을 목업 레이아웃 그대로 고정 예시 데이터로 보여야 하고(SHALL), 맨 위에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠를 보여야 한다(SHALL). 예시 화면의 동작은 저장하지 않아야 하며(MUST NOT) 다시 열면 처음 상태다. 입찰 금액과 가격 평가는 가린다. 로그인(`add-session-auth`), 사업 현황·상세(`add-project-status`)와 정답지·채점(`add-evaluation`)은 실제 화면이다. 로그인 화면은 앱 틀 밖이라 띠를 두지 않는다.

#### Scenario: 예시 띠
- **WHEN** 왼쪽 메뉴에서 "입찰 이력"을 열면
- **THEN** 목업과 같은 입찰 이력 표와 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보이고 서버의 검토 API를 부르지 않는다

#### Scenario: 저장하지 않음
- **WHEN** 예시 화면에서 값을 바꾸는 동작(예: 공지 읽음, 설정 바꾸기)을 하고 화면을 다시 열면
- **THEN** 처음 상태로 보인다

#### Scenario: 금액 가림
- **WHEN** 입찰 이력이나 입찰 상세를 열면
- **THEN** 금액 칸은 숫자 대신 "영업 권한 필요"로 보인다

#### Scenario: 실제 로그인 화면
- **WHEN** 로그인 화면에서 틀린 비밀번호를 넣으면
- **THEN** "아이디 또는 비밀번호가 맞지 않습니다." 안내가 보이고 화면은 로그인 화면에 머문다
