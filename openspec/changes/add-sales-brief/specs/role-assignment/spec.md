## ADDED Requirements

### Requirement: 영업 요약
시스템은 담당자 확인 단계부터 검토 하나의 영업 요약(머리 정보·제출 마감·결재 상태, 판정 수와 팀 가정·직접 작성할 칸 수, 일탈 후보 최대 10건, 질의 후보 최대 5건, 비용 조건 종류별 한 줄, 위험 조건 확정·미확인 수, 회신 안 한 협조 요청 부서별 수)을 이미 있는 결과만으로 코드가 만들어 JSON과 Word 한 장으로 내야 한다(SHALL). 값은 원문 그대로, 원문 위치가 없는 줄은 넣지 않고, 언어 모델은 부르지 않는다(CR-01·02·10). 처리 중·실패 검토는 거절한다. [제안 11-23]

#### Scenario: 영업 요약 만들기
- **WHEN** 일탈 후보 2건과 지체상금 비용 조건이 있는 담당자 확인 단계 검토의 영업 요약을 요청하면
- **THEN** 일탈 2건이 항목·요구 값·제품 값·원문 위치와 함께, 상업 조건에 "지체상금" 한 줄이 원문 값과 함께 들어 있고 머리에 "결재 전 초안"이 있다

#### Scenario: 일탈이 많으면 자름
- **WHEN** 일탈 후보가 12건인 검토의 영업 요약을 만들면
- **THEN** 일탈은 10건만 들어가고 "외 2건"이 적힌다

#### Scenario: 같은 입력 같은 요약
- **WHEN** 바뀐 것이 없는 검토의 영업 요약을 두 번 만들면
- **THEN** 두 결과의 내용이 같다

#### Scenario: 처리 중 영업 요약 거절
- **WHEN** 처리 중인 검토의 영업 요약을 요청하면
- **THEN** 409로 거절한다

## MODIFIED Requirements

### Requirement: 인계 패키지
시스템은 결재가 승인된 검토의 인계 패키지(영업 요약 Word, 일탈 목록·질의서 초안 Word, 제출본 v1 기준 TBE 준수표, 판정이 있는 데이터시트 전부, 담은 것과 뺀 것을 적은 목록 파일)를 zip 한 개로 내려받게 해야 하고(SHALL), 엔지니어가 보내면 그 zip을 붙인 메일을 영업 주소로 한 통 보내고 넘긴 기록과 이력을 남겨야 한다(SHALL). 영업 요약은 zip의 첫 파일이고 목록 파일과 메일 본문에 먼저 볼 파일로 적는다. 승인 전 검토는 만들지 않는다. 담을 것은 기존 내보내기와 같은 파일이다. [결정]

#### Scenario: 패키지 내려받기
- **WHEN** 일탈 후보가 있고 질의 후보가 없는 승인된 검토의 인계 패키지를 내려받으면
- **THEN** zip에 영업 요약 Word, 일탈 목록 Word, TBE 엑셀, 데이터시트 엑셀, 목록 파일이 있고 질의서는 없으며 목록 파일에 "질의 후보 없음"이 적힌다

#### Scenario: 승인 전 패키지
- **WHEN** 담당자 확인 단계인 검토의 인계 패키지를 요청하면
- **THEN** "결재 승인 뒤에 만들 수 있습니다"로 거절한다

#### Scenario: 패키지 영업에 보내기
- **WHEN** 엔지니어가 승인된 검토의 인계 패키지를 영업에 보내면
- **THEN** 영업 주소로 zip 1개를 붙인 메일 1통이 나가고 넘긴 기록 1건이 남는다
