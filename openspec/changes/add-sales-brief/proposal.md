# Proposal

## Why

영업 담당자는 인계 패키지 zip 안의 Word 2개와 엑셀 여러 개를 모두 열어 봐야 "이 입찰에 참여할지, 어디서 협상할지"를 판단할 수 있다. 일탈·질의 수, 지체상금·책임 한도 같은 상업 조건, 남은 협조 요청과 빈 작성 칸이 화면 여러 곳(판정 탭, 상업 조건 탭, 협조 요청, 데이터시트)에 흩어져 있고, 참여 판단은 결재 전에 시작되는데 지금 영업이 받는 것은 결재 뒤 패키지뿐이다.

관련: FR-11 영업 인계(add-submission-package), FR-16 비용 조건(add-cost-conditions), 요약 상자(add-screen-summary, 코드가 틀에 채움), 인계 패키지 미리 보기(add-package-preview). CR-01·02·04·06·08·10·11.

## What Changes

- 코드가 이미 있는 결과만 모아 "영업 요약" 한 장을 만든다. AI를 부르지 않는다(CR-01·07).
  - 머리: 검토 번호·사업·검토명·고객사·국가, 제출 마감(D-n), 결재 상태(승인이면 결재자·승인 시각, 아니면 "결재 전 초안")
  - 숫자 한 줄: 준수·일탈·질의·확인 필요 판정 수, 팀 가정 판정 수, 직접 작성할 칸 수
  - 협상할 일탈: 반려하지 않은 현재 일탈 후보, 판정 번호 순 최대 10건(항목, 요구 값·제품 값 원문 그대로, 첫 원문 위치, 팀 가정). 넘치면 "외 n건"
  - 고객에게 물을 것: 질의 후보 최대 5건(같은 모양)
  - 상업 조건: 비용 조건 요약(FR-16)의 조항 종류마다 한 줄(값 원문 그대로, 계약상대자 부담·책임 한도 없음·가격 조정 없음 꼬리표, 첫 원문 위치, 같은 종류 n곳)
  - 위험 조건: 사람이 위험으로 확정한 수와 아직 확인하지 않은 수
  - 남은 일: 회신 받지 않은 협조 요청 부서별 수, 데이터시트 빈 작성 칸 수, 확인 필요 판정 수
  - 바닥 안내: "코드가 만든 요약입니다. 금액은 계산하지 않았고 후보·확인 필요는 그대로입니다."
- API: `GET /api/runs/{id}/sales-brief`(JSON), `GET /api/runs/{id}/sales-brief/docx`(Word 한 장 `영업요약_<검토 번호>.docx`). 담당자 확인 단계부터(처리 중·실패는 409).
- 인계 패키지 zip 맨 앞 파일로 영업 요약 Word를 넣고 목록 파일·메일 본문에 "먼저 볼 파일"로 적는다.
- 화면: 검토 상세 내보내기 ▾에 "영업 요약 (Word)", 인계 패키지 미리 보기 창 첫 탭 "영업 요약"(표지 앞).
- 마이그레이션 없음.

## Non-Goals

- 입찰 참여 여부 추천·점수는 만들지 않는다(판단은 사람).
- 금액·가격 계산, 단위 환산, 경쟁 제품 비교는 범위 밖(CR-10, 5장).
- AI 문장 요약은 쓰지 않는다. PDF·엑셀 형식도 만들지 않는다.
- 영업 담당자 전용 메일을 새로 보내지 않는다(인계 패키지 메일에 들어감).
