# Design: update-eval-threshold-items

## 결정

지표 재료(`by_source`)에 문항 단위 칸 두 개를 더한다.

```
short     = 이 지표가 모자란 문항 수   (up 지표: num < den, down 지표: num > 0)
questions = 이 지표가 있는 문항 수     (den > 0)
```

반복을 합칠 때 최솟값을 낸 반복의 `short`를 `min_short`로 남기고, 기준선 요약에도 `short`·`questions`를 쓴다.

```
lost    = max(0, 이번 min_short − 기준선 short)
allowed = max(1, 문턱 %p × questions / 100)
회귀     = 값이 떨어짐 and lost > allowed
```

- 도우미 근거 줄 재현율 8문항, ast-001 하나만 빠짐 → lost 1, allowed max(1, 0.4) = 1 → 회귀 아님.
- 도우미 근거 번호 통과율 11/11 → 7/10(한 문항에서 문장 3개 버림) → 값은 30 %p 떨어졌지만 lost 1 → 회귀 아님.
- 유형 30문항, 문턱 5 → allowed 1.5. 모자란 문항이 2개 늘면 회귀 — 예전 %p 규칙과 같음.
- 문항 재료가 없는 예전 기준선: 분모로 어림(`lost = round(drop × den / 100, 1)`, 같은 allowed).

## 버린 대안

- **분모로 문항 수 어림(첫 구현)**: 문항 하나에 분모가 여럿인 지표(근거 번호: 문장마다 하나)에서 한 문항의
  문장 3개가 빠지면 3문항으로 센다. 두 번째 재측정에서 근거 번호 통과율 100 → 70 %로 실제로 회귀가 나왔다.
- **문턱을 max(5 %p, 100/n)으로(%p 그대로)**: 같은 문제에 더해 0.1 단위 반올림 때문에 17문항의 1문항(5.9 %p)이
  5.88 %p보다 커서 회귀가 된다.
- **3번 중 2번 이상 떨어져야 회귀**: 반복마다 기준선과 비교해야 하는데 기준선에는 최솟값만 있다.
- **도우미 문항을 20개로 늘리기**: 근본 해결에 가깝지만 정답을 새로 만들어야 하고(지금은 모두 Claude 초안),
  평가셋 판이 바뀐다. 다음 개선으로 남긴다.

## 위험

- 작은 지표에서 진짜 한 문항 회귀를 놓친다. 대신 "기준선에서 맞았는데 이번에 틀린 문항" 목록은 그대로 보인다.
- 한 문항 안에서 더 나빠진 것(문장 1개 → 3개 버림)은 문항 수가 같아 회귀로 보지 않는다. 값은 보고서에 그대로 보인다.
