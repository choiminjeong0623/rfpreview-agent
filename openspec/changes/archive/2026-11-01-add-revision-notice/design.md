# Design

## 1. 어디에 남기나

`review_run.graph_state`(jsonb)에 둔다. 새 표·마이그레이션 없음.

- 문서 추가(`doc_add.prepare_add`)가 `revision_pending = {files}`를 남긴다.
- 판정 단계(`_judge_node`)가 이어받기 뒤 `record_revision`을 부른다. `revision_pending`이 있을 때만 `revision = {no, at, files, changed: [id], added: [id], removed: n}`로 바꾸고 표시를 지운다. 문서 추가가 판정 전에 실패해 다시 시도해도 표시가 남아 있어 그때 쓴다. 판정 뒤 단계에서 실패해 그 단계부터 이어 가면 판정 단계를 다시 돌지 않으므로 두 번 세지 않는다.
- `no` = 이전 `revision.no` + 1.

## 2. 바뀜·추가·사라짐

- 같은 줄 = `doc_add.JUDGMENT_KEY` (요구사항, 값, 비교 제품, 비교 규칙). 문서를 더해도 처리한 문서는 다시 쓰여 id가 그대로라 같은 열쇠가 된다.
- 바뀜 = 두 쪽에 다 있고 판정 값(`result`)이 다름(이어받기 뒤 값으로 비교: 사람이 수정한 줄은 수정 값이 옮겨져 바뀌지 않음). 추가 = 새 쪽에만. 사라짐 = 이전 쪽에만(줄 수만, 줄은 이미 지금 판정이 아님).
- 정정본이 같은 항목의 값을 바꾸면 값 id가 달라져 "사라짐 1 + 추가 1"로 센다. [제안] 값이 바뀐 같은 항목을 "바뀜"으로 묶는 것은 항목 짝짓기 규칙이 필요해 다음에.

## 3. 응답

- 요약·목록: 줄 id 대신 수(`changed`, `added`, `removed`)만 낸다.
- 판정 줄 `revised`: 마지막 개정의 바뀜·추가 id에 들면 CHANGED·ADDED. 그 뒤 비교 제품을 바꿔 다시 판정하면 줄 id가 바뀌어 표시가 사라진다(개정 띠의 수는 남음).
- `revised=true` 거르기는 `past=differs`와 같은 id 거르기를 쓴다(둘 다면 둘 다 맞는 줄).

## 4. 화면

- 띠는 목업 `.revbar`(Detail.css에 이미 있음). 닫기는 브라우저 저장(`s2w.revbar.<run>.<no>`), 저장이 막혀도 이번에는 닫힌다. 바뀐 줄만 보는 중에는 닫기 단추를 숨긴다.
- 주소 `?rev=1`로 바뀐 줄만 보기(판정 상세 ↔ 판정 탭이 같은 거르기를 씀). 홈 문서 추가 줄의 [바뀐 줄 보기]가 이 주소로 간다.
