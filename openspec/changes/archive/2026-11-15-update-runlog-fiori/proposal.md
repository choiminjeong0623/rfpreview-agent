# Proposal

## Why

실행 기록 상세 화면(update-runlog-detail)을 SAP Fiori 원칙으로 살펴보니(11-15, 사용자 요청) 사용자가 헷갈리는 곳이 있었다.
- 단계별 시간이 "처음 처리"·"흐름 기록"·AI 시간 막대 세 곳에 서로 다른 숫자로 나왔다. "처음 처리"는 위험 조건 찾기 0.0초·제품 비교 판정 1분 4초, 흐름 기록은 반대였다. 원인은 단계 시각을 `now()`(트랜잭션 시작 시각)로 적어, 앞 단계에서 열린 트랜잭션이면 그 시간이 다음 단계로 밀린 버그다.
- 병목 단계를 사용자가 직접 찾아야 했다.
- 구역 구분 없는 긴 세로 목록이었다.
- 단계·역할 칩이 이름표 없이 섞였고, 거른 결과가 없으면 표 머리만 남았다.
- "—"(분석 밖 호출), "l2" 같은 판 코드, "흐름 저장 시각 기준"·"원문 없이 해시만 저장" 같은 개발자 말이 그대로 보였다.

## What Changes

- 단계 시각을 `clock_timestamp()`로 적어 시간이 다음 단계로 밀리지 않게 한다.
- 상세 화면을 Fiori 객체 화면처럼: 머리글 KPI에 "가장 오래 걸린 단계"(전체의 %), 구역 이동(단계별 처리 · AI 호출 · 프롬프트 판), 구역마다 카드.
- "단계별 처리" 한 표: 단계 · 걸린 시간(막대) · 그중 AI 시간 · 바뀐 것. 가장 오래 걸린 줄 강조. 사람 동작·멈춘 자리는 표 아래. 다시 시도한 검토는 회차를 고른다.
- AI 호출: 이름 붙은 거르기(단계 ▾, 역할 ▾), 느린 순, [초기화], "m / n건", 결과 없음 안내. 처리 단계 없는 호출은 "분석 밖 (협조 요청·도우미 등)".
- 프롬프트 판은 접는 구역(역할·판 표), 기술 설명은 ⓘ 말풍선.

## Non-Goals

- API 모양·마이그레이션은 바꾸지 않는다. 이미 저장된 예전 단계 시간은 다시 계산하지 않는다(새 실행부터 바름).
