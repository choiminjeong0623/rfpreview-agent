# Proposal

## Why

화면 문구 정리 1단계(update-ui-wording)에 이어, 화면 곳곳에 남은 번역투 개수 단위·상태 이름·동사를 업무 용어로 맞춘다. 판정·요구사항 개수를 "줄"로 세고("판정 45줄", "2줄 선택"), 협조 요청 상태를 "안 보냄·메일 보냄·회신 받음"으로, 동작을 "판정 바꾸기·유형 고치기·검토 정보 고치기·버림·빼기"로 써서 실제 업무 화면과 다르게 읽힌다.

관련: 모든 화면, update-ui-wording, CLAUDE.md "글쓰기".

## What Changes

- 개수 단위: 판정·요구사항·목록 개수의 "줄" → "건"(원문 위치 "행"은 그대로). 예: "판정 45건", "2건 선택", "n건 표시", "판정 2건 변경 · 1건 추가 · 1건 삭제", "확정 항목만", "조건에 맞는 판정이 없습니다".
- 상태 이름: 안 보냄 → 미발송, 메일 보냄 → 메일 발송, 회신 받음 → 회신 완료, 협조 끝남 → 협조 완료, 다시 연락 필요 → 재요청 필요, 만듦 → 생성. 회신 받음 표시·되돌리기 → 회신 완료 처리·취소.
- 동사: 판정 바꾸기 → 판정 변경, 유형 고치기 → 유형 수정, 검토 정보 고치기 → 검토 정보 수정, 버림·버리기 → 제외·제외하기, 목록에서 빼기 → 목록에서 제외, 뺌 → 제외.
- 일괄 확정 알림: "판정 n건을 일괄 확정했습니다. m건은 제외했습니다(…). 개별 확인 후 확정하세요."
- 스펙 요구사항 문장 중 이 화면 문구를 적은 곳을 같은 말로 고친다(시나리오 이름은 테스트·추적표 연결 때문에 그대로).

## Non-Goals

- 동작·API·백엔드 변경 없음. 백엔드가 저장하는 사유 문자열(예: 이력 사유 "검토 정보 고치기")은 그대로.
- 버튼 "제안대로 확정"은 한 건 확정의 뜻이 분명해 그대로 둔다.
