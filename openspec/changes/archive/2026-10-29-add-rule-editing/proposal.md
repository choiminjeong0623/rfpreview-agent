# Proposal

## Why

판정 규칙 화면(SCR-17)은 읽기 전용이라, 규칙 하나를 고치려 해도 `data/seed`의 CSV를 고치고 `rfp-db setup`을 다시 돌려야 한다.
입찰 기술 검토 엔지니어가 검토 중에 새 위험 표현, 새 문서 이름 형식, 새 RFP 표기를 찾으면 바로 사전에 넣을 수 있어야 한다.
2026-10-29 minjeong 요청: 판정 규칙 화면에서 직접 추가·수정·삭제하는 단추와 기능.

## What Changes

- 판정 규칙 화면의 네 사전(비교 방향, 위험 표현, 항목 이름, 문서 종류)에 추가·수정·삭제 단추와 입력 창. 사유는 필수.
- 고친 내용은 DB에 바로 저장되고 다음 검토부터 쓰인다. 진행 중이거나 끝난 검토 결과는 바뀌지 않는다.
- 규칙 고침 이력 표: 누가, 언제, 어느 사전의 어느 줄을, 무엇에서 무엇으로, 왜 바꿨는지. 화면의 "마지막 수정"과 펼친 줄 "수정 이력"에 보인다.
- 사전 판(CR-11): 판 번호 = 사전 CSV 내용 + 화면 고침 이력. 같은 규칙이면 같은 판, 하나라도 고치면 새 판이라 문서를 다시 처리한다.
- `rfp-db setup`(사전 다시 적재)은 CSV를 넣은 뒤 화면 고침을 순서대로 다시 적용해 고친 내용을 잃지 않는다. 고침을 버리려면 `rfp-db seed-rules --reset-edits`.
- 고칠 수 있는 사람: 엔지니어와 승인자. 다른 역할은 단추가 꺼져 있다. [제안]
- 쓰이고 있는 표준 항목(판정·비교 방향·제품표 연결이 가리키는 것)은 지울 수 없다.

## Non-Goals

- 수정 요청 → 승인 흐름(나중에 더할 수 있다).
- 화면 고침을 CSV 파일에 다시 쓰기.
- 제품표 고치기, 단위 사전(CR-10).

## Impact

- 명세 `reference-data`: "규칙 사전 고치기", "규칙 고침 이력", "고친 규칙의 사전 판", "규칙 사전 다시 적재 때 고침 유지" 추가.
- 명세 `review-workspace`: "판정 규칙 화면" 수정(고치기 동작).
- 마이그레이션 0013(rule_edit), API `POST/PUT/DELETE /api/rules/{dictionary}…`, `GET /api/rules/edits`.
