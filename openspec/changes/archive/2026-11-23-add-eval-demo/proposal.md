# Proposal: 판정 정답지와 재현 가능한 채점 명령 (add-eval-demo)

## Why

2026-11-22 포트폴리오 점검에서 평가 항목은 14/20이었다. 깎인 이유는 세 가지다.

1. **K5·K6(판정 정확도·일탈 재현율)는 사람이 확정한 판정으로만 잰다.** 사람이 판정을 고르지 않은 검토는 잴 수 없고, 남이 저장소를 받아 같은 숫자를 다시 낼 방법이 없다. 정답지 종류에 판정(JUDGE)이 없다.
2. **합성 RFP 28을 공개본만으로 다시 만들 수 없다.** 파일 28은 파일 24 → 25 → 26 → 27 → 28 순서로 만드는데, 파일 25(부록 B 일탈 후보 데이터시트)를 만드는 스크립트가 공개본에 없다. 그래서 정답지 채점 테스트(`test_synthetic_rfps.py`)가 CI에서 늘 건너뛰어진다.
3. **숫자에 표본 크기와 불확실성이 없다.** 65줄 중 65줄과 4줄 중 4줄이 똑같이 "100 %"로 보인다.

관련: 기획서 2-2 K지표, 명세 `evaluation`, 점검 P0 계획 2-1·2-2.

## What Changes

1. **파일 25 만드는 스크립트** — `generate_deviation_rfp.py`: 파일 24에 부록 B 데이터시트 표(TS-170-GIS, D-01~D-11)를 더한다. 표 줄 값은 합성 RFP 28 요구사항 정답지 40~50번 줄에서 가져왔다. 이제 공개본만으로 파일 24~28을 모두 만든다.
2. **판정 정답지(JUDGE)** — 정답지 종류에 판정을 더한다(마이그레이션 0048: 종류 `JUDGE`, 정답 줄 `product_code`, 채점 기록 `judge_key_id`). CSV(번호, text, expected 판정, product_code, ambiguous, note)를 `rfp-db load-answer-key --kind JUDGE --doc`로 넣는다. 합성 RFP 28 판정 정답지(`synthetic_rfp28_judge.csv`, 30줄)는 Claude 초안이고, 문서의 요구값과 제품표 값을 비교해 정했다(시스템 결과로 만들지 않음).
3. **판정 정답지로 채점** — 판정 정답지를 고르면 K5-정답지(정답지 줄 중 시스템 판정이 같은 비율)와 K6-정답지(정답이 일탈 후보인 줄 중 시스템도 일탈 후보), 판정별 정답·시스템 표(혼동표)를 코드로 잰다. 사람 확정 기준 K5·K6는 그대로 둔다.
4. **95 % 신뢰 구간** — 비율 지표마다 윌슨 구간(아래·위)을 함께 낸다. API `EvalMetric`에 `ci_low`·`ci_high`, 채점 화면 값 아래 "95 % 구간 a–b %".
5. **재현 채점 명령** — `rfp-db eval-demo [--create] [--report 파일]`: AI를 끈 채 새 DB에 시연 준비(파일 28 검토 1건)와 판정 정답지를 넣고 세 정답지로 채점해, 지표·분자/분모·95 % 구간·목표 표를 출력한다. 같은 저장소면 누가 돌려도 같은 표가 나온다.
6. **CI에서 합성 RFP 테스트** — backend 작업이 pytest 전에 파일 24~28을 만들어, 지금 건너뛰던 합성 RFP 테스트가 CI에서 돈다.
7. **문서** — `docs/05-evaluation.md`에 재현 방법과 표, 정답지 확인 전이라는 한계.

## Non-Goals

- 정답지를 사람이 확인하는 일(사용자 몫). 확인 시트만 만든다.
- 실제 고객 RFP 측정, AI 켠 측정.
- 비교 제품을 바꾼 뒤의 판정을 정답지로 재는 것(바꿔 보기는 기존 테스트가 본다).

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `evaluation`: 판정 정답지 넣기·채점, 신뢰 구간, 재현 채점 명령을 더하고, "시연용 합성 RFP 정답지"의 숫자를 공개본으로 다시 만든 파일 28 기준으로 바꾼다.
- `reference-data`: "시연용 합성 RFP"에 공개본 스크립트로 파일 24~28을 만들 수 있어야 한다는 것을 더한다.
- `review-workspace`: 정답지·채점 화면에 판정 정답지 고르기와 구간 표시.

## Impact

- 마이그레이션 0048. API `POST /api/eval/score` 본문 `judge_key_id`, 응답 `EvalMetric.ci_low/ci_high`, `EvalMetrics.judgments`. 화면 `Eval.tsx`.
- CI backend 작업에 합성 문서 만들기 한 단계.
