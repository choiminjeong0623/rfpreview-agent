# Design

## 결정

### 1. 목업 v4.96 CSS는 새로 쓰인 규칙만 덧붙인다

`mockup/Detail.css`(v4.57)를 v4.96 파일로 통째로 바꾸면 아직 v4.57 모양인 탭 화면 규칙이 함께 바뀐다. v4.96 Detail CSS에서 이번에 쓰는 클래스(`.ttl1` `.ttl2` `.exw` `.mm` `.hc` `.hf` `.hc-kv` `.dpb` `.pgtabs2` `.more` `.ftb`) 규칙만 원본 그대로 `mockup/DetailV496.css`에 옮겨 Detail.css 뒤에 붙인다. 탭 화면을 v4.96으로 옮길 때 파일 전체를 바꾸고 이 파일을 지운다.

### 2. 건수는 머리글이 한 번 모아 탭·아래 줄과 나눈다

`useHeadCounts`가 판정 건수·데이터시트 빈칸·손실 환산·위험 조건·읽기 점검·상업 조건을 한 번에 부르고, 판정을 고치면(`tick`) 다시 부른다. 꼭 볼 것 = 일탈 후보 + 질의 후보 + 확인 필요. 작성할 칸 = 데이터시트 표들의 빈칸 합, 전체 = 표 줄 합.

### 3. 비교 제품은 정보 묶음 밖에 그대로 둔다

목업은 "검토" 묶음 안에 설비마다 고르기 칸을 두지만, 실제 RFP는 설비 묶음이 10개가 넘어 묶음 칸이 길어진다. 지금 접히는 비교 제품 줄(`ProductSeg`, update-detail-layout)을 정보 묶음 바로 아래에 둔다. `SCR-08_공유.md`에 적는다.

### 4. "준수 모두 확정"은 머리글과 아래 줄 두 곳, 같은 함수

`components/bulk.ts`의 `confirmAllComply`(확정 안 한 준수 id를 쪽마다 모아 `POST /actions/bulk`)를 판정 진행 "묶어서 확정"과 아래 줄 "모두 확정"이 같이 쓴다. 뺀 줄 알림 문장(`bulkMessage`)은 판정 탭 "고른 줄 확정"과 같다. 결과는 공통 알림(`useToast`)으로 보인다.

### 5. 내보내기 메뉴의 TBE·데이터시트는 화면 이동

TBE 준수표·데이터시트 채우기 명세의 "검토 상세 머리의 단추"는 내보내기 메뉴 안의 항목이 된다(같은 화면을 연다). 명세 문장은 그대로 둔다.

## 위험

- 머리글이 부르는 API가 6개 늘어 검토 상세를 열 때 요청이 많아진다 → 모두 가벼운 목록·건수 응답이고, 판정을 고칠 때만 다시 부른다.
