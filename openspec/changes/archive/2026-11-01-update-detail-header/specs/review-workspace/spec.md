## MODIFIED Requirements

### Requirement: 검토 상세 요약 칸과 탭
화면은 처리를 마친 검토 상세의 제목 줄 아래에 정보 3묶음과 탭 줄을 목업 v4.96 순서대로 보여야 한다(SHALL). "검토"는 제출 마감·D-day, 상신 권장일(마감 2일 전), 문서 수·묶음·규격 체계, 담당·결재자, "사업"은 사업명·고객사·국가·고객 입찰 번호·영업, "판정 진행"은 꼭 볼 것(일탈·질의·확인 필요 합과 각 수), 준수 수, 작성할 칸(빈칸·전체), 손실 환산(조항이 있을 때)이다. 탭은 판정·위험 조건·문서 읽기 점검·상업 조건·이력과 "더 보기"(손실 환산 (참고)·입찰 영향·지난 RFP 비교·제출본)이고, 판정 탭 옆에 꼭 볼 것 수를 보인다. 예시 띠는 없다. 확인 필요 비율과 뺀 직접 작성할 칸 수는 결재 상신 창에만 보인다. [결정]

#### Scenario: 요약 칸
- **WHEN** 일탈 후보가 있는 검토 상세를 열면
- **THEN** 정보 묶음 검토·사업·판정 진행이 보이고, 판정 진행에 꼭 볼 것·준수·작성할 칸이 보이며 예전 요약 칸(확인 필요 비율 칸)은 없다

#### Scenario: 꼭 볼 것
- **WHEN** 일탈 후보 2·질의 후보 2·확인 필요 8·준수 45줄인 검토 상세를 열면
- **THEN** 판정 진행에 "꼭 볼 것 12줄"과 "일탈 2 · 질의 2 · 확인 8", "준수 45줄"이 보이고 판정 탭 이름 옆 수가 12다

#### Scenario: 사업 묶음
- **WHEN** 사업이 연결된 검토 상세를 열면
- **THEN** 사업 묶음에 고객 입찰 번호와 영업 담당 이름이 보인다

#### Scenario: 상신 권장일
- **WHEN** 제출 마감이 6일 남은 검토 상세를 열면
- **THEN** 검토 묶음의 상신 권장에 마감 2일 전 날짜가 보인다

#### Scenario: 더 보기 탭
- **WHEN** "더 보기"에서 손실 환산 (참고)를 고르면
- **THEN** 손실 환산 탭 내용이 보이고 탭 줄 끝에 "손실 환산 (참고)"가 선택된 것으로 붙는다

#### Scenario: 직접 작성할 칸 표시
- **WHEN** 직접 작성할 칸이 3개인 검토에서 결재 상신 창을 열면
- **THEN** 확인 비율 줄에 "직접 작성할 칸 3개는 뺌"이 보인다

#### Scenario: 탭으로 내용 바꾸기
- **WHEN** 검토 상세에서 "이력" 탭을 누르면
- **THEN** 이력 표가 보이고 탭 줄에서 이력 탭이 선택된 것으로 보인다

#### Scenario: 예시 탭
- **WHEN** 마지막 예시 탭이던 "지난 RFP 비교" 탭을 열면
- **THEN** 예시 띠가 보이지 않는다

### Requirement: 목록 초안 내려받기와 문장 고치기
시스템은 검토 상세 머리의 "내보내기"에서 "일탈 목록 초안 (Word)"·"질의서 초안 (Word)"를 고르면 진행 화면을 보인 뒤 Word 파일을 내려받고 "<파일 이름>를 만들었습니다." 알림을 보여야 한다(SHALL). 내보내기에는 TBE 준수표와 데이터시트 채우기도 있어 그 화면을 연다. 일탈·질의 문장은 판정 패널·판정 상세 창(위험 조건에서 나온 문장은 위험 조건 줄을 펼친 곳)에서 보이고, 엔지니어는 담당자 확인 단계에서 문장을 확정하거나, 사유를 적어 고치거나 목록에서 뺄 수 있다(SHALL).

#### Scenario: 내보내기 묶음
- **WHEN** 검토 상세 머리의 "내보내기"를 열면
- **THEN** 일탈 목록 초안 (Word) · 질의서 초안 (Word) · TBE 준수표 · 데이터시트 채우기 네 가지가 보인다

#### Scenario: 일탈 목록 초안 내려받기
- **WHEN** 엔지니어가 내보내기에서 "일탈 목록 초안 (Word)"를 고르면
- **THEN** 진행 화면이 보였다가 "일탈 목록 초안_<검토 번호>.docx" 파일이 내려받아지고 만들었다는 알림이 보인다

#### Scenario: 사유 적어 문장 고치기
- **WHEN** 엔지니어가 판정 패널의 질의 문장을 고치면
- **THEN** 사유 칸이 나오고 사유가 비면 문장 저장 단추가 눌리지 않으며, 사유를 적어 저장하면 고친 문장이 "확정" 상태로 남는다

### Requirement: 판정 탭 한꺼번에 확정
검토 상세 판정 탭은 줄 고르기 칸과, 고른 줄이 있으면 "n줄 선택 · 제안대로 확정" 띠를 보여야 한다(SHALL). 확정하지 않은 준수 판정이 있으면 화면 아래 행동 줄에 "준수 n줄은 모두 확정"을, 판정 진행 묶음의 준수 칸에 "묶어서 확정"을 보이고, 누르면 확정하지 않은 준수 판정을 모두 제안대로 확정한다(SHALL). 담당자 확인 단계의 엔지니어가 아니면 보이지 않는다.

#### Scenario: 고른 줄 확정
- **WHEN** 엔지니어가 판정 2줄을 고르고 "제안대로 확정"을 누르면
- **THEN** 두 줄이 확정됨으로 바뀌고 "판정 2줄을 제안대로 확정했습니다." 알림이 보인다

#### Scenario: 준수 모두 확정
- **WHEN** 확정하지 않은 준수 판정이 있는 검토에서 아래 행동 줄의 "모두 확정"을 누르면
- **THEN** "판정 n줄을 제안대로 확정했습니다" 알림이 보이고 "모두 확정"이 사라지며 준수 판정은 모두 확정됨이다

## ADDED Requirements

### Requirement: 검토 상세 아래 행동 줄
시스템은 처리를 마친 검토 상세 화면 아래에 늘 보이는 행동 줄을 두어야 한다(SHALL). 담당자 확인 단계에서는 확정 안 한 판정 수, 확정 안 한 준수가 있으면 "준수 n줄은 모두 확정"(엔지니어만), 데이터시트 빈칸이 있으면 그 수와 "데이터시트 채우기", "결재 상신"(엔지니어가 아니면 잠근 채 이유)을 보인다. 다른 단계에서는 확정·상신 단추 없이 단계 이름과 결재자를 한 줄로 보이고, 승인된 검토는 잠긴 "제출본 v1 확정"을 보인다. [결정]

#### Scenario: 아래 행동 줄로 한꺼번에 확정
- **WHEN** 담당자 확인 단계에 확정 안 한 준수 45줄이 있는 검토에서 엔지니어가 아래 줄의 "모두 확정"을 누르면
- **THEN** "판정 45줄을 제안대로 확정했습니다" 알림이 보이고 아래 줄에서 "모두 확정"이 사라진다

#### Scenario: 단계별 아래 줄
- **WHEN** 엔지니어가 승인된 검토 상세를 열면
- **THEN** 아래 줄에 "승인됨"이 보이고 "결재 상신"과 "모두 확정" 단추가 없다
