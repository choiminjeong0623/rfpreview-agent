# 문서 종류별 추출 규칙 (C조 C1 이어서)

## 왜

- C1 처리기는 AI 질문 설명과 점검만 종류별이고, 추출 규칙(어떤 줄을 요구사항 후보로 뽑나)은 모든 종류가 같다.
- 실제 RFP를 규칙만으로 돌려 보니(외부 전송 없음) 종류마다 다른 문제가 있었다.
  - **공급사 답안**(RFP18 Electric Distribution): 답안 표의 조항 줄 중 shall·must도, C/D/E 표시도 없는 줄은 버린다("short circuit current rating: 200 kaic."). 요구사항 정답지(공급사 답안 표시 줄, B1) 기준 **K1 66.5 %**(200줄 중 133줄).
  - **입찰 서식**(Bidding Forms): 표 밖 문장 62줄 중 19줄이 "Each Bidder must fill out this form" 같은 서식 작성 안내인데 요구사항으로 남는다.
- 2026-11-01에 "K1·K2를 다시 재야 해서" 미뤘던 일이다. 이제 정답지 채점(K1·K2)이 있어 전후를 잰다.

## 무엇

- 처리기마다 **종류별 추출 규칙**을 더한다(공통 규칙은 그대로, 코드 규칙, CR-01).
  - 공급사 사양서: 문서에 C/D/E 표시 줄이 하나라도 있으면, 표의 조항 줄(15자 이상, 소문자가 있는 칸)은 표시가 없어도 공급사 답안 후보로 뽑는다. 표시는 있으면 남기고 없으면 비운다(CR-04).
  - 입찰 서식: 표 밖 문장 중 서식 작성 안내 표현(fill out/in, this form, following table, [Note:, typewritten, in print form)이 든 문장은 작성 규칙으로 둔다. 위험 표현이 든 문장은 바꾸지 않는다(위험 조건 찾기에서 빠지지 않게, FR-06).
  - 요구 사양서·시험 사양서·구매 요청서·물량표·일반: 공통 규칙만.
- 로컬 측정(규칙만, AI 없음): RFP18 K1 66.5 % → 100 %, K2 93.5 % → 95.6 %. 정답지가 "답안 표의 조항 줄"이라 규칙과 정의가 같다는 한계를 함께 적는다.

## 하지 않음

- 보증 기술 특성표(파일 1 "Comment Update … GIS": 머리글 없는 항목·값·단위 표, 표시 없음) 읽기: 공급사 보증값을 요구사항으로 볼지 결정이 필요하다 [확인 필요].
- 요구 사양서·시험 사양서 전용 규칙: 정답지가 없어 전후를 잴 수 없다.
- AI 질문·점검 변경.
