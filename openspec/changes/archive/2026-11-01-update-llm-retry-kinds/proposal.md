# AI 오류를 종류별로 처리 (B조 B6)

## 왜

- AI 기술 활용성 추가 개발 항목 B6. minjeong "B조를 시작합니다."
- 지금은 어떤 오류든 같은 질문을 2번 더 묻는다(`llm/client.py`). 답의 형식이 틀린 경우(번호 겹침, 빈 claims)는 temperature 0이라 같은 답이 나오기 쉬워 재시도 2번이 돈과 시간만 쓴다.
- 키가 틀렸거나 모델 이름이 없으면 몇 번을 다시 물어도 안 되는데, 3번 묻고 "처리 실패 — 다시 시도"를 띄워 사람이 다시 시도를 누르게 만든다.
- 위험 조건 설명 하나의 형식이 틀리면 검토 전체가 실패한다.

## 무엇

- 오류를 셋으로 나눈다. ① 연결·시간 초과·서버 오류·요청 많음(429): 지금처럼 2번 더 묻는다. ② 형식 오류(JSON이 아님, 검사 실패): 다시 묻지 않는다. ③ 키·권한·모델 설정 오류(400·401·403·404): 다시 묻지 않고 "AI 키 또는 모델 설정 오류 — 설정 확인"으로 멈춘다.
- 형식 오류 뒤 처리: 묶음 질문(문장 구분·유형)은 바로 반으로 나눠 묻는다. 위험 조건 설명은 버리고 이유 "형식 오류"(FORMAT_ERROR)를 남긴다. 문장 초안은 그 묶음만 코드 기본 문장으로 바꾼다. 검토는 멈추지 않는다.
- 마이그레이션 0025: 버린 이유에 FORMAT_ERROR 추가.

## 하지 않음

- 재시도 횟수(2) 그대로. 다시 시도·취소(add-run-control) 그대로.
