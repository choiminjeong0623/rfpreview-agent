# Design

## 결정

- **쪽 단위는 요청 줄.** 묶음 단위로 자르면 요청이 많은 검토 하나가 한 쪽을 넘칠 수 있어, 담당별과 같이 요청 줄 수로 자른다. 대신 거른 요청을 검토 묶음 순서(첫 요청 순서 = 최근 검토 먼저)로 다시 늘어놓은 뒤 잘라, 한 검토의 줄은 이어진 쪽에만 있다.
- **쪽 크기 상태를 보기마다 따로.** 담당별 기본 5건, RFP별 기본 10건. 보기를 바꾸면 1쪽으로.
- **머리 숫자는 전체로.** 쪽에 보이는 줄만 세면 "회신 1 / 2"처럼 검토 전체 진행과 다른 숫자가 나와 헷갈린다.
- **쪽 번호 줄은 공통 `Pager`.** 담당별과 같은 모양·동작.

## 대안

- 검토 묶음 10개씩 자르기: 묶음 크기가 들쭉날쭉해 한 쪽 길이를 예측할 수 없어 버림.
