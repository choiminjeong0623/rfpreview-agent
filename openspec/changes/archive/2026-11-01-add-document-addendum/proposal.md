# Proposal

## Why

입찰 중에는 발주처가 정정본이나 추가 문서(Addendum)를 자주 낸다. 지금은 분석을 마친 검토에 문서를 더할 길이 없어,
검토를 새로 등록하고 이미 확정·수정·반려한 판정을 처음부터 다시 봐야 했다. 수백 줄을 다시 확인하는 일은 사람의 시간을 가장 많이 쓴다.
통합 개발 목록 3장 '다음 단계'에서 "검토에 문서 추가"를 골랐고(2026-11-01), 사용자가 "같은 줄은 확정 이어받기"로 정했다.

관련: FR-01 ⑤⑥, FR-10 ⑤, NFR-05(처리한 문서 다시 쓰기), CR-08(확정은 사람), CR-11, `review-run` "검토 다시 시도", `review-workspace` "검토 상세 문서 표".

## What Changes

- 담당자 확인 단계(결재 상신 전) 검토에 엔지니어가 docx를 더하면, 처음 파일과 더한 파일로 같은 검토를 다시 분석한다. 처리한 문서는 다시 쓴다(AI를 다시 부르지 않음).
- 사람이 확정·수정·반려한 판정은 같은 줄(같은 요구값·비교 제품·비교 규칙)이면 새 판정에 이어받는다. 수정은 고친 판정 값까지 옮긴다. 확정한 보증값은 새 판정 줄에 다시 잇는다.
- 위험 조건도 같은 열쇠(종류·표현·항목·요구사항 묶음)면 확인 상태를 이어받고, AI 설명·근거 문장을 다시 쓴다(AI 다시 부르지 않음). 그 위험 조건에서 나온 질의 문장의 확인도 이어진다.
- 이력에 "문서 추가: 파일 이름" 1건을 남긴다. 마이그레이션 0021(이력 동작 값 ADD).
- "문서 n개" 창에 "문서 추가" 칸: 파일 고르기 → 분류 추천 → 묶음·종류 고르기 → "추가하고 다시 분석".
- 덤으로 고침: 다 끝난 검토를 다시 돌리면 위험 조건을 지우다가 목록 출처가 막아 실패하던 문제(다시 시도·문서 추가 모두).

## Non-Goals

- 문서 빼기·바꾸기(정정본이 원본을 대체). 정정본도 새 파일로 더하고, 원본 판정은 사람이 반려한다. 개발 기록에 남긴다.
- 상신 뒤(결재 중·승인 뒤) 문서 추가. 상신을 취소한 뒤 더한다.
- 판정 규칙을 고친 뒤 다시 처리한 문서는 요구사항 번호가 새로 생겨 이어받지 않는다(같은 문서만 다시 씀).
- 처음 문서와 정정본의 값 차이 비교 화면. 값이 다르면 기존 "문서 간 값 불일치" 위험 조건으로 나온다.
