## ADDED Requirements

### Requirement: 검토에 문서 추가
시스템은 담당자 확인 단계(결재 상신 전) 검토에 엔지니어가 docx 문서를 더하면, 처음 올린 파일과 분류에 더한 파일과 그 분류를 합쳐 같은 검토 번호로 다시 분석해야 한다(SHALL). 이미 처리한 문서는 다시 쓰고(NFR-05) AI를 다시 부르지 않는다. 이력에 "문서 추가"와 더한 파일 이름을 남긴다. 담당자 확인 단계가 아니면 409, 엔지니어가 아니면 403, 이미 있는 파일 이름이면 409로 거절하고 검토는 그대로 둔다. [제안]

#### Scenario: 문서를 더해 다시 분석
- **WHEN** 판정 1줄을 확정한 검토에 추가 문서 하나를 더하면
- **THEN** 같은 검토 번호로 담당자 확인 단계까지 다시 가고, 문서가 하나 늘며, 이력에 "문서 추가" 1건과 파일 이름이 남는다

#### Scenario: 상신한 검토에는 못 더함
- **WHEN** 결재 중인 검토에 문서를 더하려 하면
- **THEN** 409 오류와 "결재 상신 전" 안내가 돌아오고 검토는 결재 중 그대로다

#### Scenario: 같은 파일 다시 더하기
- **WHEN** 이미 이 검토에 있는 파일 이름으로 문서를 더하려 하면
- **THEN** 409 오류와 그 파일 이름이 돌아오고 검토는 담당자 확인 단계 그대로다

#### Scenario: 엔지니어만 더함
- **WHEN** 승인자가 문서를 더하려 하면
- **THEN** 403 오류가 돌아온다

### Requirement: 다시 분석할 때 위험 조건 바꾸기
시스템은 같은 검토를 다시 분석할 때(문서 추가·다시 시도) 위험 조건을 새로 만든 뒤 이전 것과 바꿔야 한다(SHALL). 종류·표현·항목·요구사항 묶음이 같은 위험 조건은 AI 설명과 근거 문장을 다시 쓰고 AI를 다시 부르지 않으며, 그 위험 조건에서 나온 목록 항목의 연결을 새 위험 조건으로 옮긴다. 다 끝난 검토를 다시 돌려도 목록 연결 때문에 실패하지 않는다. [제안]

#### Scenario: 같은 위험 조건은 AI 다시 안 부름
- **WHEN** AI 설명이 있는 위험 조건이 나온 검토에 문서를 더해 다시 분석하면
- **THEN** AI 설명 요청은 새로 생긴 위험 조건 수만큼만 가고, 근거 문장은 모두 지금 위험 조건에 붙어 있다
