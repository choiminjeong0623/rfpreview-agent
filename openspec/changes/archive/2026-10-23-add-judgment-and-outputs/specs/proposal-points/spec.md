# Spec Delta

## Purpose

판정 결과를 "지킬 것"에서 멈추지 않고, 엔지니어가 고객에게 내세울 강점 후보를 근거와 함께 받게 한다. 일반 생성형 AI와의 차이다 (FR-14).

## ADDED Requirements

### Requirement: 후보 선정
시스템은 준수이면서 여유 방향이 강점인 판정과 손실 환산 우위를 모두 제안 포인트 후보로 코드가 골라야 한다(SHALL). 근거 칸(요구 원문 위치, 제품 행)이 비어 있으면 후보를 만들지 않아야 한다(MUST NOT, K12 = 0).

#### Scenario: 시간 여유
- **WHEN** 준수이고 여유가 있으면(40 kA 1초 ↔ 3초)
- **THEN** 후보 1건, 근거 위치 2개(요구 원문, 제품 행 GIS-145)이다

#### Scenario: 확인 필요 판정
- **WHEN** 판정이 확인 필요(제품 값 없음)이면
- **THEN** 후보를 만들지 않는다

#### Scenario: 강점이 아닌 여유
- **WHEN** 무게처럼 강점 방향이 "강점 아님"인 항목에 여유가 있으면
- **THEN** 후보를 만들지 않는다

### Requirement: 제안 문장
시스템은 근거 값만으로 AI가 제안 문장을 쓰게 하고(숫자는 자리표시자), 경쟁 제품과 비교하는 문장은 쓰지 않아야 한다(MUST NOT). 손실값이 팀 가정이면 포인트에도 "팀 가정"을 붙인다.

#### Scenario: 근거와 다른 숫자
- **WHEN** 제안 문장 속 숫자가 근거 값과 다르면
- **THEN** 다른 위치를 표시하고 엔지니어에게 넘긴다
