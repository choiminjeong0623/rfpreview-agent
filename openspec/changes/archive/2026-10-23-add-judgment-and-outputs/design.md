# Design

## Context

2단계(add-document-pipeline)가 남긴 요구사항·값(`req_value`)·위험 조건(`risk_flag`)이 입력이다. 파일 1에는 데이터시트 표 49종이 있고 같은 표가 파일 2에도 반복된다(같은 행은 대표 요구사항 하나에 위치가 여럿). 제품표(product_master)는 93행이지만 정격 숫자가 있는 판정용 행은 GIS 11행, 진공차단기 3행, 변압기 설계 카드 3행 정도다.

## Goals / Non-Goals

**Goals:**
- 파일 1(+2)로 판정 → 보증값 → 손실 환산 → 일탈·질의 목록 → 제안 포인트가 끝까지 돌고, 수용 기준이 자동 테스트로 확인된다.
- 숫자·판정·후보 고르기·묶기는 모두 코드(CR-01). AI는 목록·제안 문장만 쓰고, 키가 없으면 코드가 만든 기본 문장을 쓴다.

**Non-Goals:**
- FR-12 공학 규칙 검산(Should). 그래서 "100 kA 질의"처럼 검산에서 나오는 질의는 실제 문서에서 아직 나오지 않는다(묶기 규칙은 합성 테스트로 확인).
- 확인·승인 화면과 이력(4단계 add-review-approval). 이번에는 API로 결과를 보여 주고 비교 제품만 바꿀 수 있다.

## Decisions

- **판정 대상.** 묶음 A·B 문서의 요구사항 중 대표 행(같은 행이 여러 문서에 있으면 하나)만 본다. 데이터시트 칸 값은 모두, 문장 값은 항목키가 있는 것만 판정한다. 하위 항목이 있는 빈 머리 행("Insulation level")은 판정하지 않는다.
- **판정 순서(코드).** 칸 형태 → 비교 제품 → 제품값 → 방향 순서로 본다.
  - 빈칸 → 보증값 작성, 가림 표시·규격 위임·문장·예/아니오·허용 안 되는 계산식·범위 → 확인 필요(사유 코드 REDACTED, DELEGATED, TEXT_VALUE, YESNO_CHECK, FORMULA, RANGE).
  - 한 칸에 숫자가 여럿("3,000/2500") → 질의 후보(MULTI_VALUE, 어느 값인지 묻기).
  - 비교 제품이 없음 → 확인 필요 — 기준값 없음(NO_PRODUCT), 제품을 하나로 못 고름 → 확인 필요(PRODUCT_AMBIGUOUS).
  - 제품값 없음(NO_PRODUCT_VALUE), 단위 다름(UNIT_DIFF, 대소문자·공백만 맞추고 환산 안 함), 단위 없음(UNIT_MISSING) → 확인 필요.
  - 방향: EQ는 같은 값(제품 주파수 "50/60"은 목록에 포함되면 같음), GE·LE는 크기 비교, LT는 요구 "<x"에 제품 "≤x"면 경계값(BOUNDARY) 확인 필요, SOURCE는 요구값 기호를 따르고 기호가 없으면 LE, IN은 규격 번호가 제품 규격 목록에 있는지, FILL은 빈칸이 아니면 확인 필요, TEXT·AI는 확인 필요.
  - 시간 조건: 값이 같거나 크고 제품 시간 ≥ 요구 시간이면 준수, 제품 시간이 짧거나 없으면 확인 필요(CONDITION_DIFF, NO_PRODUCT_TIME).
- **방향 출처.** 비교 방향 사전(compare_rule)에 표 이름+항목 번호가 있으면 그것, 없으면 항목키 기본 방향(item_key.default_direction). 강점 방향도 같은 순서(compare_rule.strength_direction → item_key.strength_direction).
- **여유.** 준수일 때만. GE·LE는 차이(DIFF = 제품 − 요구 또는 요구 − 제품), 같은 값에서 시간이 길면 시간 배수(TIME_RATIO). 여유가 0보다 크고 강점 방향과 맞으면 STRENGTH, 아니면 NOT_STRENGTH. EQ·IN 준수는 NOT_CALC.
- **강점 방향 초안 [제안, 팀 확인 필요].** 전류·내전압·주위 온도·고도·IP 등급은 클수록 좋음(HIGHER), 누설·부분 방전·차단·투입 시간은 작을수록 좋음(LOWER), 정격 전압·주파수·용량·무게·코일 수 등은 강점 아님(NONE). 큰 정격 전압은 다른 등급 제품일 뿐이라 강점으로 보지 않는다.
- **제품값.** item_pm_mapping의 열에서 읽는다. 열 이름이 `description`인 항목(정격 주파수 대신 쓰던 칸, 가스 누설)은 카탈로그 문장에서 정해진 모양("주파수 50/60 Hz", "누설 … 연 1 % 이하")만 읽는다. 정격 주파수는 적재할 때 description에서 `rated_frequency` 칸으로 옮긴다. 단시간 전류의 시간은 description의 "40 kA (3초)", "25kA/3s"에서 읽는다. 열에 값이 없으면 지어내지 않는다(CR-04).
- **비교 제품 선택(설비 묶음 단위).** 설비 묶음 = 데이터시트 표 하나의 로마 숫자 구분(I, II, …) 하나, 문장은 문서 + 설비 종류 + 절 제목의 전압.
  - 설비 종류: 구분 제목·표 이름으로 정한다(GIS 표의 모든 구분 → GIS, 차단기 구분 → 52 kV 미만이면 진공차단기 계열 MV_EQUIP, 이상이면 GCB, 변압기 → TRANSFORMER, 변류기·계기용 변압기·피뢰기 → 판정용 제품 없음).
  - 제품 고르기: 같은 계열에서 설계 사례 카드를 빼고, 전압(요구 Um과 같은 제품 → Um 이상 중 가장 낮은 제품 → 공칭 전압과 같은 제품) → 주파수 포함 → 규격 체계(IEC / IEEE·UL) → 단시간·차단 전류 이상 중 가장 작은 것 → 정격 용량(같은 단위일 때만) 순서로 좁힌다. 앞 조건으로 아무것도 안 남으면 그 조건은 건너뛴다.
  - 그래도 여럿이면 행의 베이 이름(Incoming·Bus section → "인입·모선", Outgoing feeder → "피더")과 제품 설명을 맞춰 행마다 고르고, 못 고르면 PRODUCT_AMBIGUOUS.
- **바꿔 보기.** `run_product_choice(run_id, equipment_group)`에 엔지니어가 고른 제품을 저장하고 판정 이후 단계를 다시 돈다. 이전 판정은 지우지 않고 `is_current = false`로 둔다. 보증값·손실 환산·목록·제안 포인트는 현재 판정으로 다시 만든다(후보 단계라 확정 이력이 없다. 확정 뒤 수정 이력은 4단계).
- **보증값(FR-08).** 판정이 보증값 작성인 행만. 연결표에 항목키가 없으면 비움(NOT_MAPPED). 회사 고정값 → FIXED, 제품 열 → PM(값과 단위). 제품을 못 고르면 비움(PRODUCT_AMBIGUOUS), 열이 비면 비움(NO_PRODUCT_VALUE). "comply" 같은 말은 후보로 쓰지 않는다.
- **손실 환산(FR-13).** 데이터시트에서 단위가 `$/kW`(US$/kW, USD/kW 포함)인 행 셋(무부하·부하·보조)을 찾고, 바로 앞의 비용 영향(COST) 조항을 손실 환산 조항으로 둔다. 비교 제품은 그 표의 변압기 묶음 제품. 손실값이 하나라도 없으면 합계 NULL, 확인 필요. 단가 단위가 $/kW가 아니면 계산하지 않는다. 손실값이 팀 가정이면 is_assumed.
- **변압기 손실값 [팀 가정].** TRF-HV-230-360A(파일 1 TS-AUTO-TR 360/360/75 MVA)에 무부하 60 / 부하 300 / 보조 8 kW를 팀 가정으로 넣는다. 나머지 변압기는 비워 두어 "손실값 없음 → 확인 필요"가 그대로 보이게 한다.
- **목록(FR-09).** 일탈 목록 = 일탈 후보 판정, 질의 목록 = 질의 후보 판정 + 값 불일치 위험 조건. 같은 요구(항목키 + 숫자 + 단위 + 비교 제품, 위험 조건은 값 묶음)는 한 건으로 묶고, 원문 위치는 묶인 요구사항의 위치를 모두 모은다. 같은 요구사항이 일탈 항목과 질의 항목에 함께 있으면 서로 연결한다. 목록 이름은 문서에서 찾은 발주처 양식 이름("Schedule of Deviations" 등)을 쓰고, 없으면 "일탈 목록"·"질의 목록".
- **문장과 숫자(CR-07).** AI에게는 숫자 대신 `{v1}`, `{v2}` 자리표시자와 그 뜻만 준다. 돌아온 문장의 자리표시자를 코드가 근거 값으로 채운 뒤, 문장 속 숫자를 근거 값 목록과 다시 대조해 다르면 MISMATCH와 다른 숫자를 남긴다. AI가 없으면 코드의 기본 문장 틀을 쓴다.
- **누락 점검.** 실행마다 다시 계산: 일탈 후보 판정 수, 일탈 목록 항목에 묶인 수, 빠진 판정 id, 질의 항목 중 확정되지 않은 수. 빠진 것이 있으면 AR-07을 남긴다(승인 흐름은 4단계).
- **제안 포인트(FR-14).** 준수 + STRENGTH 판정마다 하나(MARGIN), 손실 환산 합계가 있는 계산마다 하나(LOSS). 요구 원문 위치와 제품 행이 없으면 만들지 않는다. 경쟁 제품 비교 문장은 프롬프트에서 막고, 숫자 검사는 목록과 같다.
- **LangGraph.** documents → pairs → risks → judge → warranty → loss → outputs → proposals. 판정 이후 단계는 실행 단위 결과라 실행마다(바꿔 보기마다) 다시 만든다.
- **스키마(0004).** judgment에 설비 묶음·사유 문장·팀 가정·제품값 단위, 제품 고르기 표(run_product_choice), product_master에 정격 용량(rated_capacity·unit), 보증값 후보 단위·사유, 손실 환산 단가 단위·상태·계산식, 목록 항목 이름·묶음 키·숫자 검사 내용, 제안 포인트 근거 값·숫자 검사 내용, 누락 점검의 승인 기준 칸을 더한다.
- **2단계 값 정리 보강.** 판정에 필요해서 함께 고쳤다: 하위 항목의 빈 단위 칸은 상위 항목 단위, "25 (2seconds)" 칸의 시간 조건, "- …", "2) …" 목록 표시를 뺀 항목 이름 대조, 소제목 행("1) Continuous current")의 항목키, "kVrms"·"kVp" 단위.

## Risks / Trade-offs

- 제품 고르기 규칙이 틀리면 판정이 통째로 틀린다. 그래서 비교 제품을 판정마다 보여 주고 묶음 단위로 바꿀 수 있게 했다.
- 견적표(가격표) 행의 사양 문장("230kV, 3-pole, 4000A, 50kA …", 파일 1 1784행)은 2단계에서 요구사항으로 뽑지 않아 4,000 A 일탈 묶음에 들어가지 않는다 [확인 필요]. 가격표 사양 추출은 별도 change로 다룬다.
- 판정용 제품값이 있는 항목이 적어(연결표 12항목) 데이터시트 행 다수가 "확인 필요"가 된다. 연결표·description 규칙을 늘리면 줄어든다.
- 강점 방향과 변압기 손실값은 팀 가정·제안이다. 결과에 표시하고 팀 확인 뒤 사전에서 고친다.

## 구현하며 정한 것

- **실행 흐름.** LangGraph 노드는 documents → pairs → risks → judge → warranty → loss → outputs → proposals. 판정 뒤 네 단계는 `rebuild_outputs`로 묶어, 비교 제품을 바꾸면(`switch_product`) 그 묶음만 다시 판정하고 네 단계를 다시 만든다. 제안 포인트가 손실 환산을 가리키므로 손실 환산을 다시 만들 때 제안 포인트를 먼저 지운다.
- **목록 항목 빼기.** 엔지니어가 일탈 목록 항목을 빼면(REMOVED) 바로 누락 점검을 다시 돈다. 확정·승인은 4단계(FR-10). 목록을 다시 만들면 뺀 표시는 없어진다(후보 단계라 이력이 없다).
- **손실 환산 단가 단위.** 종류마다 단위가 다를 때 ", "로 이어 저장한다("$/kW" 안의 "/"와 겹치지 않게).
- **API.** `/api/runs/{id}/judgments·equipment·warranty·losses·outputs·submission-check·proposals` 조회, `PUT equipment/{묶음}/product`(바꿔 보기, product_code 없으면 자동 선택으로 되돌림), `PUT losses/{id}`(손실값 고치기 → 팀 가정), `PUT outputs/{id}/status`(빼기·되돌리기). 결과는 모두 원문 위치가 있는 것만 낸다(CR-02).
- **"20번 외함 온도 상승" 사례.** 파일 1 TS-115-GIS 20-1~3은 요구값(30/40/75)이 있어 보증값 행이 아니다. "제품표에 없는 값" Scenario는 합성 문서(빈 무게 칸, GIS 제품표에 무게 없음)로 확인한다 [확인 필요: 사례 행 번호].
