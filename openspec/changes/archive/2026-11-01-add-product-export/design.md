# Design

## 결정

- 거르기는 목록 API와 같은 `_where`(제품군·검색어·설계 사례 카드)를 쓴다. 쪽 나누기는 하지 않는다: 거른 제품 전부.
- 칸은 화면 상세의 "값" 탭 칸 전체(정격 26칸 + 용량 단위 + 규격)와 끝 칸 5개(팀 가정, 설계 사례 카드, 비교값 출처, 출처 문서, 상태). 머리 이름은 한국어 + 단위. 값은 DB 그대로(CR-10 단위 환산 없음).
- 빈 칸은 빈 셀로 둔다. "비어 있음" 같은 글자를 넣으면 엑셀에서 숫자 칸이 글자로 섞이므로, 안내 줄에 "빈 칸은 값이 없는 칸(확인 필요)"이라고 적는다.
- 팀 가정(CR-06)은 줄마다 "팀 가정" 칸에 무엇이 가정인지(제품 전체·비교값·손실값) 적고 줄을 옅은 파랑으로 칠한다.
- 같은 제품표면 같은 내용(CR-11): 내보낸 시각을 넣지 않는다.
- 파일 만들기는 `pipeline/product_export.py`, API는 `api/reference.py`. TBE·데이터시트 엑셀과 같은 openpyxl.

## 대안

- 화면이 받은 목록으로 브라우저에서 CSV를 만든다: 쪽 나누기 때문에 전체를 다시 받아야 하고, 팀 가정 표시·칸 이름을 화면과 서버 두 곳에서 맞춰야 해서 버림.
- 가져오기까지: 제품표가 바뀌면 이미 끝난 판정과 기준이 달라진다(CR-11). 미리 보기·승인·판 기록이 필요해 동결 전에는 뺌.

## 위험

- 제품표 칸이 늘면 `COLUMNS`도 함께 고쳐야 한다(테스트가 머리 이름을 대조한다).
