# Design

## 결정

### 1. 언제 부르나

머리글 부품이 화면 주소가 바뀔 때마다 `GET /runs`를 한 번 부르고, 처리 중(`PROCESSING`) 검토가 있는 동안만 5초마다 다시 부른다(`useRepeat`, 검토 목록·홈과 같은 주기). 처리 중이 없으면 주소가 바뀔 때만 부른다.
대안: 늘 5초마다 부르기 — 처리 중이 없을 때도 요청이 계속 나가서 버림.

### 2. 진행률은 처리 상태 화면과 같은 계산

`components/progress.ts`의 `progress()`·`stepText()`·`STALL_MS`를 그대로 쓴다. 단추의 p는 처리 중 검토 진행률의 평균(반올림).

### 3. 끝남 안내

앞선 응답에서 처리 중이던 검토가 다음 응답에서 처리 중이 아니면 알린다. 처음 불러온 응답에서 이미 끝난 검토는 알리지 않는다(새로 고침마다 알림이 쏟아지지 않게).
`FAILED`가 아닌 단계는 "분석이 끝났습니다 · 판정 확인", `FAILED`는 "분석이 멈췄습니다 · 실패 보기"(오류 알림이라 닫을 때까지 남음). 사람이 취소한 검토는 알리지 않는다. 취소도 `FAILED`로 남으므로 오류 문장이 "분석을 취소했습니다."로 끝나는지로 가린다(`pipeline/run.py` `cancel_message`, 실행 목록 응답에 취소 칸이 없음). 링크는 검토 상세 `#/reviews/:id`.

### 4. 알림에 링크

`useToast().show(text, kind, link?)`에 `{ href, label }` 하나를 더한다. 링크를 누르면 그 알림을 닫는다.

## 위험

- 사용자가 둘 이상 동시에 분석하면 남의 검토도 보인다 → 화면 명세대로(분석은 공용 자원) 둔다.
