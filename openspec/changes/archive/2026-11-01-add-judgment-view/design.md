# Design

## 결정

### 1. 원문 줄은 분석 때와 같은 방법으로 다시 읽는다

줄 번호는 분석이 정한다: docx 단락 1개·표 행 1개를 줄로 펴고(`docx_reader.read_blocks`), 팀 추출 txt가 있으면 그 줄 번호에 맞춘다(`line_map.map_lines`, `process_document`와 같은 조건). API는 `document.source_path` 파일을 같은 함수로 다시 읽어 `{줄 번호: 글}`을 만들고 범위만 잘라 준다. 그래서 저장한 원문 위치(`line_start`)와 화면 줄 번호가 늘 같다(CR-11).
줄 전체를 DB에 저장하는 방법은 문서마다 수천 줄이 늘고 이미 처리한 문서는 다시 처리해야 해서 쓰지 않는다.

같은 파일을 여러 번 읽지 않게 (경로, 수정 시각)마다 최근 8개를 메모리에 둔다. 판정 상세에서 ↑↓로 넘길 때 같은 문서를 다시 읽지 않는다.

### 2. 파일이 없으면 DB에 남은 줄만, `partial`

업로드 폴더를 지웠거나 다른 컴퓨터에서 만든 DB면 파일이 없다. 그때는 그 문서의 절 제목(`section.line_start`), 요구 문장(`source_location.line_start`의 `requirement.text_raw`), 표 행(`table_row.line_no`, 칸을 " | "로 이음) 중 범위 안의 것만 돌려주고 `partial: true`. 화면은 "저장된 줄만 보입니다"를 보인다. 같은 줄 번호에 여럿이면 절 제목 → 표 행 → 요구 문장 순서로 하나만.

### 3. 줄 범위는 최대 40줄

`from`·`to`는 1 이상, `to ≥ from`, `to − from + 1 ≤ 40`이 아니면 400. 이 검토에 없는 파일 번호는 404. 화면은 `line_start − 2` ~ `(line_end ?? line_start) + 2`를 부르고, 위치 줄이 길면 앞 40줄만.

### 4. 이전·다음은 거른 목록 창(500줄)에서 정한다

판정 상세는 주소의 거르기·쪽으로 `GET /judgments?order=priority`를 `offset = ⌊위치 / 500⌋ × 500`, `limit=500`으로 부른다(서버 상한 500). 창 안에서 지금 판정의 자리로 "판정 n / 전체"와 ↑↓를 정하고, 창 끝에서 넘어가면 다음 창을 부른다. 목록으로 갈 때 쪽 번호는 지금 자리로 다시 계산해 보던 줄이 보이게 한다.
거르기를 주소에 둔 이유: 새로 고침·주소 공유에도 같은 순서가 나오고, 새 전역 상태가 필요 없다(`_프런트원칙.md` 3장).

### 5. 판정 바꾸기는 창, 판정 탭 패널은 그대로

목업은 "판정 바꾸기"를 누르면 판정 탭 패널로 돌아가지만, 화면 명세(SCR-08-12)대로 이 화면에서 공통 `Modal`로 바꾼다(새 판정 5종·사유 필수). 판정 탭의 오른쪽 패널(보증값 넣기·판정 바꾸기)은 그대로 두고, 판정 상세에서 돌아온 줄을 연다. 줄을 누르면 판정 상세 화면으로 간다(목업과 같음).

### 6. 비교 방향은 판정 규칙의 같은 항목에서

`GET /rules/compare`에서 판정의 `item_key`(표 위치면 표 이름까지 같은 줄을 먼저)를 찾아 방향 이름(`DIRECTION_NAMES`)과 부등호를 보인다. 화면은 값을 비교하지 않는다(CR-01). 규칙을 못 찾으면 비교 방향 줄을 뺀다.

### 7. CSS

v4.96 JudgeView에서 새로 쓰인 규칙(`.jv-top` `.jv-back` `.jv-ctx` `.jv .mdo` `.jv .mdw` `.jv .mdh` `.jv .jv-h` `.jv .mdf`)만 `mockup/JudgeView.css`에 원본 그대로 옮기고 `Detail.css`와 함께 쓴다. `.main > :not(.jv)` 규칙은 목업이 같은 쪽에 검토 상세를 함께 그려서 생긴 것이라 옮기지 않는다.

## 위험

- 큰 docx(수백 쪽)를 처음 읽을 때 1~3초 걸린다 → 원문 줄 자리에만 회색 줄을 보이고 나머지는 먼저 보인다. 캐시로 두 번째부터는 바로.
- 팀 추출 txt를 나중에 넣거나 지우면 줄 번호가 분석 때와 달라질 수 있다 → 분석과 같은 조건(지금 txt 폴더에 같은 이름 txt가 있으면 맞춤)을 쓴다. txt는 팀 시험 자료라 분석 뒤에 바뀌는 일은 드물다. [제안]
