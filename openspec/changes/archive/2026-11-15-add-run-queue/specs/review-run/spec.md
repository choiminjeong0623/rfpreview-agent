## ADDED Requirements

### Requirement: 검토 실행 대기열
시스템은 검토 등록·다시 시도·문서 추가·단계부터 다시 처리 요청을 받으면 실행 작업만 대기열에 넣고 응답해야 하며, 처리기가 들어온 순서대로 정해진 동시 실행 수(기본 2)까지만 꺼내 처리해야 한다(SHALL, NFR-11). 꺼내지 못한 검토는 "대기 중 n번째"로 보인다. 같은 입력이면 동시 실행 수와 상관없이 같은 결과다(CR-11). [제안 v3]

#### Scenario: 스캔 PDF 등록은 OCR을 기다리지 않음
- **WHEN** 처리기가 따로 도는 방식에서 스캔 PDF로 검토를 등록하면
- **THEN** 응답은 OCR을 하지 않고 돌아오며 검토는 처리 중·대기 중 1번째다

#### Scenario: 동시 실행 수 2에 등록 3건
- **WHEN** 동시 실행 수 2에서 검토 3건을 등록하고 처리기가 작업을 꺼내면
- **THEN** 2건은 처리 중이고 1건은 "대기 중 1번째"이며, 하나가 끝나면 남은 1건을 꺼낸다

#### Scenario: 동시 실행 수 1과 2의 결과
- **WHEN** 같은 문서를 동시 실행 수 1과 2로 각각 처리하면
- **THEN** 두 검토의 요구사항과 판정이 같다

### Requirement: 실행 소유권
시스템은 작업을 넣을 때마다 새 실행 토큰을 내고, 처리 흐름은 진행을 기록할 때마다 토큰이 아직 자기 것인지 확인해 아니면 결과를 쓰지 않고 멈춰야 한다(SHALL, NFR-12). 한 검토에 도는 실행은 언제나 하나다. [제안 v3]

#### Scenario: 취소 직후 다시 시도
- **WHEN** 처리 중인 검토를 취소하고 바로 다시 시도하면
- **THEN** 옛 실행은 다음 진행 기록 때 멈추고 결과를 쓰지 않으며, 새 실행 하나만 결과를 쓴다

### Requirement: 처리기 살아 있음과 다시 넣기
시스템은 처리기가 정해진 간격(30초)마다 살아 있음을 기록하고, 살아 있음이 소유권 시간(3분) 넘게 끊긴 작업을 새 토큰으로 대기열에 다시 넣어 저장된 흐름 상태로 멈춘 단계부터 이어 처리해야 한다(SHALL, CR-12). 다시 넣기는 2번까지이고, 넘으면 검토를 "처리 실패 — 처리기가 멈춤"으로 둔다. 화면의 멈춤 판단은 살아 있음 기록으로 한다. [제안 v3]

#### Scenario: 처리기를 강제로 끈 뒤 다시 켬
- **WHEN** 처리 중인 작업의 처리기가 꺼져 살아 있음이 3분 넘게 끊긴 뒤 처리기를 다시 켜면
- **THEN** 그 검토는 대기열에 다시 들어가 이어서 처리되고 담당자 확인에서 멈춘다

#### Scenario: 다시 넣기 한도
- **WHEN** 같은 작업이 다시 넣기 2번 뒤에도 살아 있음이 끊기면
- **THEN** 검토는 처리 실패이고 "처리기가 멈춤" 문구가 남는다

#### Scenario: 대기 중 검토 취소
- **WHEN** 대기 중인 검토를 취소하면
- **THEN** 실행 없이 바로 취소되고 그 작업은 꺼내지지 않는다

### Requirement: 중복 등록 방지와 업로드 상한
시스템은 등록 요청에 요청 키가 있고 같은 키가 10분 안에 다시 오면 처음 만든 검토를 돌려주어야 하며, 파일 하나(100 MB)나 요청 하나(300 MB)의 크기 상한을 넘으면 검토를 만들지 않고 400과 상한 안내를 돌려주어야 한다(SHALL). [제안 v3]

#### Scenario: 같은 요청 키로 두 번 등록
- **WHEN** 같은 요청 키로 등록을 두 번 보내면
- **THEN** 검토는 1개이고 두 응답의 검토 번호가 같다

#### Scenario: 파일 크기 상한 초과
- **WHEN** 상한보다 큰 파일로 등록하면
- **THEN** 400과 상한 안내가 돌아오고 검토가 생기지 않는다

### Requirement: 처리기 상태 점검
시스템은 상태 점검에 실행 방식(웹 서버 안 / 처리기), 살아 있는 처리기 수, 대기 작업 수를 보여야 한다(SHALL). 처리기 방식인데 살아 있는 처리기가 없어도 등록은 받아 대기 중으로 둔다. [제안 v3]

#### Scenario: 처리기 0개
- **WHEN** 처리기 방식에서 처리기를 하나도 띄우지 않고 검토를 등록하면
- **THEN** 검토는 대기 중이고 상태 점검에 살아 있는 처리기 0, 대기 작업 1이 보인다
