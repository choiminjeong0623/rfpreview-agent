# Design

## 결정

- **근거 조각 ID = `E-<document_id>-<location_id>`.** 요구사항 원문 위치(`requirement_location`)를 그대로 쓴다. 저장 때 ID에서 `location_id`를 되찾아 `claim_evidence_source`에 넣는다.
- **대조는 형식 검사와 근거 검사로 나눈다.** 형식이 틀리면(빈 문장, 빈 ID 목록, 모르는 관계) 재시도 대상(CR-12). 근거가 틀리면(모르는 ID, 조각에 없는 인용, 없는 숫자) 다시 묻지 않고 설명만 버린다. 숫자 검사(CR-07)와 같은 방식이고, 같은 질문에 같은 답(temperature 0)이라 다시 물어도 소용없다.
- **인용 대조는 공백만 정리한 부분 문자열 비교.** 뜻이 비슷한 문장은 통과시키지 않는다.
- **저장 상태는 `SUPPORTED`만.** 버린 설명은 남기지 않는다. 다른 상태 값(PARTIAL 등)은 사람이 검토하는 나중 화면용으로 표에만 둔다.
- **AI 실패는 숨기지 않는다.** 처음 브랜치는 실패를 잡아 설명을 비웠으나, PR #29(AI 실패 시 실행 멈춤)와 `review-run` 스펙에 맞게 되돌렸다.
- **PROMPT_VERSION은 그대로(p2).** 위험 설명은 실행마다 새로 만들고 문서 처리 결과 재사용 열쇠와 무관하다.
