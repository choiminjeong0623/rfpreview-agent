# Design

## 결정

- **AI 사용량:** `llm/client.py`에 `Usage`(요청·재시도·입력·출력·생각 토큰)를 두고, `call_with_retry`가 요청·재시도를 세고 `GeminiLLM`이 응답의 `usage_metadata`로 토큰을 더한다. `execute_run`은 시작 때 사용량을 복사해 두고 끝(성공·실패)에 차이를 `review_run`에 더한다. 모델 객체는 실행마다 새로 만들지만 차이로 저장해 같은 객체를 여러 실행이 써도(테스트) 섞이지 않는다.
- **단계 시간:** `run_step_time(run_id, attempt, step, started_at, finished_at)`. `_set_step`이 앞 단계를 닫고 새 단계를 연다. attempt는 `retry_count`. 끝·실패 때 열린 단계를 닫는다. `graph_state.updated_at`은 그대로 진행 표시용.
- **다시 쓴 문서 수:** 문서 읽기 단계에서 `DocumentResult.reused`를 세어 `documents_reused`에 적는다(시도마다 덮어씀).
- **비용:** 저장하지 않고 API에서 `(입력 × 입력 단가 + (출력 + 생각) × 출력 단가) × 1,500원`. 단가는 코드 표(`pipeline/run_log.py`)이고 팀 가정이다(CR-06, 화면에 "추정 · 팀 가정"). gemini-3.8-flash는 10-25 파일 1 실측(약 680원)에 맞춘 0.50 / 4.00 $/1M. 표에 없는 모델은 비움, AI 없이 돈 실행은 0원.
- **화면 자리:** 지식 관리 > 정답지·채점 아래 "실행 기록"(`/runlog`). 목업에 없는 화면이라 `SCR-25_공유.md`.

## 대안

- 단가를 설정(환경 변수)으로: 발표 전 값 하나라 코드 표로 충분. 바뀌면 표만 고친다.
- 단계 시간을 graph_state에 배열로: 다시 시도·조회가 번거로워 표로 뺐다.

## 위험

- 단가가 실제와 다를 수 있다 [확인 필요]. 화면에 팀 가정으로 보인다.
- 이 change 전 실행은 호출·토큰이 0, 단계 시간이 없다. 화면에서 "기록 없음"으로 보인다.
