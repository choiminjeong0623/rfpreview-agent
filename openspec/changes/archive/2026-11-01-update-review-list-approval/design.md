# Design

## 1. 결재 정보는 가장 최근 상신 하나

검토 하나에 상신이 여러 번 있을 수 있다(상신 → 취소 → 다시 상신, 반려 → 고침 → 다시 상신).
목록에는 `approval` 표에서 그 실행의 `approval_id`가 가장 큰 줄 하나를 쓴다. 그 줄이 취소(`withdrawn_at` 있음)면 결재 칸은 모두 비운다.
반려 뒤 다시 상신하지 않았으면 반려 줄이 가장 최근이므로 "반려"로 보인다.

응답 칸(`RunListItem`): `approver_id`, `approver`, `requested_by_id`, `requested_by`, `requested_at`, `decision`(`APPROVED`·`REJECTED`·null), `decided_at`.
이름 칸은 결재 대기 상세(`ApprovalOut`)와 같은 이름을 쓴다.

## 2. "내가 올린 결재"는 담당 범위의 세 번째 값

검토 목록에는 이미 담당 범위(내 검토 / 팀 전체)와 단계 거름이 있다. 새 메뉴 대신 담당 범위에 "내가 올린 결재"를 더한다.
- 거름: `requested_by_id` = 머리글에서 고른 사용자. 로그인이 없어 머리글 사용자를 "나"로 본다(다른 화면과 같음).
- 이 보기에서는 단계 칩 셋(결재 대기 · 반려 · 승인)과 개수를 보이고, 표에 "결재" 칸(결재자, 상신 후 n일 또는 결정 시각)을 더한다.
- 다른 담당 범위에서는 표 모양을 바꾸지 않는다.

대안: 새 메뉴 "결재함"(1~2일). 주 사용자 원칙과 목업 메뉴에 맞지 않아 버렸다(2026-10-31 결정).

## 3. 요약 줄 링크

요약 줄 "결재 대기 n"을 누르면 찾기 상자의 단계를 결재 대기로 바꾸고 바로 적용한다(지금은 검색 단추를 눌러야 적용).
홈 "내 업무"의 결재 대기 칸은 지금처럼 카드 강조를 유지하고, 칸 아래에 "목록에서 보기" 링크(`#/reviews?scope=submitted`)만 더한다.

## 위험

- 목록 쿼리에 하위 쿼리가 하나 늘어난다. 실행 수가 수십 개라 문제없다.
- 응답 칸이 늘어 `gen:api`를 다시 돌려야 한다. 다른 사람과 `schemas.py`가 겹치지 않게 `RunListItem`만 고친다.
