## ADDED Requirements

### Requirement: 고장 사전과 해결 사례 적재
시스템은 규칙 사전 적재 때 고장 사전과 해결 사례를 함께 넣어야 하고(SHALL), 해결 사례가 고장 사전과 어긋나면 의심 사례로 이유와 함께 표시해야 한다(SHALL). 의심 기준은 코드로 본다: 고장 사전은 RMA 불필요인데 사례에 RMA 번호가 있음, 처리 시간이 사전 기준의 10배를 넘음. [결정] 2026-10-23 팀

#### Scenario: 의심 사례 표시
- **WHEN** 해결 사례 800건을 적재하면
- **THEN** 108건이 의심 사례로 표시되고 나머지는 정상 사례다

#### Scenario: 의심 이유
- **WHEN** RMA 불필요 고장의 사례에 RMA 번호가 있고 처리 시간이 사전 기준(24h)의 10배를 넘으면(311.7h)
- **THEN** 두 이유를 모두 적는다

### Requirement: 요구–고장 연결표 적재
시스템은 팀이 확정한 요구–고장 연결표(표준 항목키, 고장 사전 제품군, 고장 번호, 적용 설비, 확정자)를 적재해야 한다(SHALL). 고장 사전에 없는 고장 번호, 항목 이름 사전에 없는 항목키, 모르는 적용 설비가 있으면 적재를 멈춘다(MUST). 확정자는 화면에 내지 않는다.

#### Scenario: 연결표 적재
- **WHEN** 팀이 채택한 8줄을 적재하면
- **THEN** 8줄이 확정자 "팀 확정"으로 들어간다

#### Scenario: 고장 사전에 없는 고장 번호
- **WHEN** 연결표에 고장 사전에 없는 고장 번호가 있으면
- **THEN** 그 번호를 알리고 적재를 멈춘다
