## ADDED Requirements

### Requirement: 검토 취소
시스템은 처리 중인 검토에 사람의 취소 요청을 받아 요청 시각과 요청자를 남기고, 처리 흐름이 다음 진행을 기록할 때 멈추게 해야 한다(SHALL). 멈춘 검토는 처리 실패가 되고 멈춘 단계와 "○○이(가) 분석을 취소했습니다" 문장을 남긴다. 멈춘 문서의 반쯤 만든 결과는 저장하지 않는다. 마지막 진행이 10분 넘게 없으면 요청 즉시 처리 실패로 바꾼다. 처리 중이 아닌 검토의 취소 요청은 거절한다. [제안]

#### Scenario: 처리 중 취소
- **WHEN** 문서 읽기 단계를 처리하는 중인 검토에 취소를 요청하면
- **THEN** 처리가 다음 진행 기록에서 멈추고 검토는 처리 실패, 멈춘 단계 문서 읽기, 취소 문장과 취소 표시가 남으며 그 문서는 저장되지 않는다

#### Scenario: 멈춘 검토 취소
- **WHEN** 마지막 진행이 11분 전인 처리 중 검토에 취소를 요청하면
- **THEN** 바로 처리 실패가 되고 "진행이 멈춰" 문장이 남는다

#### Scenario: 끝난 검토는 취소 못 함
- **WHEN** 담당자 확인 단계인 검토에 취소를 요청하면
- **THEN** 409 오류로 거절하고 검토는 그대로다

### Requirement: 검토 다시 시도
시스템은 처리 실패한 검토(취소 포함)에 사람의 다시 시도 요청을 받아, 처음 시작할 때와 같은 파일과 같은 사람 분류로 같은 검토를 다시 처리해야 한다(SHALL). 이미 처리한 문서는 다시 쓰고(NFR-05) 다른 결과는 다시 만든다. 다시 시도하면 처리 중으로 바뀌고 멈춘 단계·오류 문장·취소 표시를 지우며 다시 시도 횟수를 하나 늘린다. 처리 실패가 아니거나 다시 돌릴 파일 정보가 없으면 거절한다. [제안]

#### Scenario: 취소한 검토 다시 시도
- **WHEN** 문서 읽기에서 취소한 검토를 다시 시도하면
- **THEN** 같은 검토 번호로 담당자 확인 단계까지 가고 판정이 나오며 다시 시도 횟수는 1이다

#### Scenario: 처리한 문서는 다시 씀
- **WHEN** 문서 두 개 가운데 첫 문서를 처리한 뒤 실패한 검토를 다시 시도하면
- **THEN** 첫 문서는 같은 문서로 다시 쓰이고 새 문서 줄은 두 번째 문서 하나만 생긴다

#### Scenario: 다시 돌릴 파일 정보 없음
- **WHEN** 파일 정보가 저장되지 않은 처리 실패 검토를 다시 시도하면
- **THEN** 409 오류와 다시 등록하라는 안내가 돌아오고 검토는 그대로다
