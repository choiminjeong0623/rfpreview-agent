# Proposal

## Why

AI를 쓰는 분석은 큰 RFP에서 15분 넘게 걸린다. 잘못 올렸거나 너무 오래 걸려도 멈출 방법이 없었고, 백엔드가 꺼져 멈춘 검토는
"처리 중"으로 영원히 남았다. 분석 실패 화면의 "다시 시도"도 API가 없어 예시였다(SCR-11_공유 3번).
2026-10-31 주말 검토에서 "AI 검토 중에 [취소]할 수 있어야 하지 않나"는 요청이 나왔고, 통합 개발 목록 2장 2번에서
취소와 다시 시도를 한 change로 묶기로 했다(둘 다 실행을 멈추고 다시 이어 가는 같은 코드).

관련: CR-12, NFR-05, `review-run` "AI 오류 처리"·"처리 세부 진행 기록", `review-workspace` "처리 상태 화면"·"분석 실패 화면".

## What Changes

- 처리 중인 검토를 사람이 취소한다. 처리는 다음 진행 기록(파일 안 세부 진행이나 단계 바뀜) 때 멈추고, 검토는 처리 실패(FAILED)가 되며 멈춘 단계와 취소한 사람이 남는다. 마지막 진행이 10분 넘게 없으면 바로 멈춘 것으로 표시한다.
- 실패·취소한 검토를 사람이 다시 시도한다. 같은 파일·같은 분류로 다시 돌리고, 이미 처리한 문서는 다시 쓴다(NFR-05). 다시 시도한 횟수를 남긴다.
- 처리 상태 화면에 "분석 취소", 분석 실패 화면의 "다시 시도"를 실제로 만든다.
- 마이그레이션 0018: 취소 요청 시각·요청자, 다시 시도 횟수.

## Non-Goals

- 실패 화면의 나머지 계속하는 방법(코드 규칙만으로 계속, 직접 확인, 시스템 담당자에게 알리기). 예시로 둔다.
- 홈 실패 알림 띠의 "재시도" 단추(홈은 다른 담당). 개발 기록에 남긴다.
- 새 단계 값(CANCELLED). 취소도 처리 실패로 보여 목록·홈 라벨을 바꾸지 않는다.
