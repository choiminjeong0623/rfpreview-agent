# Design

## 1. 보내는 시점: 판정 확정 [제안]

| 시점 | 문제 |
|---|---|
| 분석이 끝나자마자 | 사람이 보기 전 후보가 다른 부서로 나감(CR-08 위반) |
| **판정 확정 때 (고름)** | 확정을 늦게 하면 늦게 나감 |
| 결재 승인 뒤 | 협조 회신은 결재 전에 필요해 순서가 거꾸로 됨 |

판정 확정(한 줄·여러 줄 확정, 확정 뒤 수정 포함)이 끝난 뒤, 그 실행에서 **아직 보내지 않았고 연결된 요구사항의 판정이 모두 확정된** 협조 요청을 부서별로 모아 한 통씩 보낸다.
판정이 없는 요구사항(비용·시험·자격 문장은 대부분 판정 대상이 아님)은 엔지니어가 협조 요청 화면에서 [보내기]를 누를 때 보낸다. 채택한 제안 포인트는 채택할 때 보낸다.

## 2. 발송 모듈

`rfp_agent/notify/mail.py` 한 곳에서만 SMTP를 부른다(LLM 모듈과 같은 원칙). 테스트는 가짜 발송기로 바꿔 보낸 메일을 목록으로 확인한다.
설정은 환경 변수만: `RFP_SMTP_HOST`, `RFP_SMTP_PORT`, `RFP_SMTP_USER`, `RFP_SMTP_PASSWORD`, `RFP_MAIL_FROM`, `RFP_MAIL_COST`, `RFP_MAIL_QUALITY`, `RFP_MAIL_SALES`.
`docker-compose.yml`에 Mailpit(:8025 웹, :1025 SMTP)을 붙이고 `.env.example` 기본값을 Mailpit로 둔다. 실제 사내 서버는 값만 바꾼다.
주소가 비어 있는 부서는 보내지 않고 "주소 없음"으로 남긴다(지어내지 않음).

## 3. 한 번만 보내기

`assignment.sent_at`은 할 일을 만든 시각("만듦")으로 이미 쓰고 있어, 메일 보낸 시각은 새 칸 `mail_sent_at`에 둔다(구현 때 바꿈). `mail_sent_at`이 있으면 다시 보내지 않는다. 목록을 다시 만들 때 `task_key`로 상태를 이어 쓰므로(지금 규칙), 이미 보낸 요청은 보낸 기록이 남고 새 요청만 보낼 대상이 된다(CR-11).
실패는 3번까지 다시 시도(CR-12)하고 `mail_error`에 마지막 오류를 남긴다. 판정 확정 때 자동 발송은 `mail_error`가 없는 요청만 대상으로 한다(메일 서버가 죽었을 때 확정마다 기다리지 않게). 실패·주소 없음 요청은 엔지니어가 [다시 보내기]로 보낸다.

## 4. 상태 뜻 (DB 값은 그대로)

| 값 | 바뀐 뒤 | 바꾸는 사람 |
|---|---|---|
| TODO | 안 보냄 (발송 실패 포함, `mail_error`로 구분) | 시스템 |
| DOING | 메일 보냄, 회신 대기 | 발송 성공 때 시스템 |
| DONE | 회신 받음 | 엔지니어 |

견적·품질·영업 담당은 상태를 바꾸지 않는다. 엔지니어는 DOING ↔ DONE만 바꾼다.

## 5. 협조 대기 기준

TODO 또는 DOING이 남으면 협조 대기(회신 받지 못한 요청). 홈·사업 현황·협조 요청 요약 줄이 같은 함수를 쓴다.

## 6. 화면 (SCR-13)

협조 요청 화면은 "보낸 기록과 회신" 화면이 된다. 요약 줄: 안 보냄 · 회신 대기 · 24시간 넘게 회신 없음 · 회신 받음.
줄: 상태, 보낸 주소, 보낸 시각, 발송 실패면 빨간 꼬리표와 [다시 보내기]. 상세 창: 진행(만듦 → 메일 보냄 → 회신 받음), [회신 받음 표시](요지 한 줄).
"확인함"·"처리 끝"·재요청(잠김)은 지운다.

## 7. 이력

발송과 회신 기록은 `review_log`에 `SEND`(대상 assignment, 받는 주소·요청 수), `REPLY`(회신 요지) 동작으로 남겨 이력 탭에 보인다. 마이그레이션 0017에서 동작 값을 더한다.

## 8. 홈 화면

홈 문구("협조 미확인" 등)는 목업을 고친 뒤 바꾼다(10-31 사용자 결정). 이 change는 홈 카드 열 기준만 "회신 받음이 아닌 요청"으로 맞춰 사업 현황과 같게 한다.

## 위험

- 고객 RFP 문장이 메일 서버로 나간다. 사내 서버만 쓰고, 시연은 Mailpit(밖으로 안 나감)만 쓴다. 보안 점검 문서에 "메일 발송 내용"을 더한다.
- 상태 뜻이 바뀌어 기존 DOING 줄은 "메일 보냄"으로 보인다. 시연 DB는 새로 만든다.
