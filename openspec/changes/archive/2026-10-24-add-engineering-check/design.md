# Design

## Context

스키마 v1에 engineering_check(규칙 B1, 단시간·최대 순간·주파수 값, 기대값, 결과)와 output_item_source.check_id가 있다.
명세서 FR-12: 규칙 하나만 [결정], 같은 장비 부위의 값끼리만, 주파수를 같은 표에서 못 찾으면 확인 필요, 위반이면 질의 후보.

## Decisions

### 1. "같은 부위"는 판정의 설비 묶음
- 판정(FR-07)이 쓰는 설비 묶음(표 하나의 로마 숫자 구분, 구분이 없으면 표 하나)을 그대로 쓴다. 문장 값은 같은 부위인지
  알 수 없어 보지 않는다.
- 값은 판정과 같이 묶음 A·B 문서의 대표 요구만 본다 (같은 행이 파일 1·2에 있으면 위치는 대표에 모두 있다). [제안]
- 단시간 전류: 같은 부위의 단시간 전류, 없으면 차단 전류 (명세서 예: 230 kV 차단기 "차단 50 kA"). 같은 부위에 값이 여럿이면
  확인 필요(MULTI_IK).
- 최대 순간 전류: peak_current와 making_current(투입 전류는 같은 배수). 단위가 kA가 아니면 확인 필요(CR-10).

### 2. 주파수는 같은 표에서
- 같은 부위 → 같은 표 순서로 찾는다. 쪽 넘김으로 나뉜 같은 이름 표(파일 1 TS-230-DS)는 한 표로 본다.
- 50 Hz → 2.5, 60 Hz → 2.6. 없거나, 여럿이거나, 다른 값이면 확인 필요.

### 3. 같다고 보는 범위 [제안]
- 계산값 그대로, 정수로 올린 값(60 Hz 31.5 kA × 2.6 = 81.9 → 82), 50 Hz는 규격 표준값(R10 수열: 25 × 2.5 = 62.5 → 63,
  31.5 × 2.5 = 78.75 → 80)까지 통과. 그대로 비교하면 파일 1 TS-SG의 25 kA ↔ 63 kA가 거짓 위반이 된다.
- 60 Hz에 50 Hz 표준값(40 kA → 100 kA)을 적은 것은 위반으로 남긴다.
- 대안: 1 % 허용 → 78.75 ↔ 80(1.6 %)을 놓치고, 104 ↔ 100(3.8 %)은 잡지만 기준이 규격과 이어지지 않는다.

### 4. 질의 후보
- 위반마다 질의 초안: 요구값, 단시간 전류, 주파수, 배수, 계산한 값을 자리표시자로 두고 코드가 채운다 (CR-07).
- 같은 숫자(항목, 요구값, 단시간 전류, 배수)의 위반은 한 건. 근거 위치는 최대 순간 전류 행과 단시간 전류 행.
- 확인 필요는 질의로 만들지 않고 검산 탭에만 보인다.

### 5. 실행 단계
- 판정 다음, 보증값 앞에 "check" 단계. 판정 뒤 단계 다시 만들기(제품 바꾸기 등)에도 같이 돈다(같은 입력이면 같은 결과).
- 다시 만들 때 검산을 가리키는 목록 출처를 먼저 지운다. 엔지니어가 확인한 질의는 묶음 키로 이어 쓴다(기존 규칙).

## Risks / Trade-offs

- 설비 묶음이 잘못 나뉘면(로마 숫자 구분을 못 찾음) 다른 부위 값끼리 맞춰 볼 수 있다 → 단시간 전류 값이 여럿이면 확인 필요로 막는다.
- 표준값 범위는 규격 확인이 필요하다 [제안].
