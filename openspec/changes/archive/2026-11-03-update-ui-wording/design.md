# Design

## 결정

- **지우는 것.** 사용자가 할 일이 없는 구현 설명(DB 표 이름, 적재 판, 응답 모양, change 이름, 규칙 번호 괄호, 명령·옵션, 환경 변수 이름). 운영자에게 필요한 정보는 "시스템 담당자에게 문의하세요"로 바꾼다.
- **남기는 것.** 사용자 판단에 필요한 표시: "팀 가정"(CR-06), "AI 작성"·"기본 문장", 외부 전송 안내("문장을 외부 AI로 보냅니다"), "(단위 환산 안 함)", "후보", 지표 이름(K1 등).
- **용어표.** proposal의 통일 목록을 기준으로 바꾸고, 같은 말이 화면마다 다르게 쓰이지 않게 한다. 업무 용어(유사도, 동의어, 규칙 기반, 검수, 협조 요청)를 쓴다.
- **스펙.** 화면 문구를 따옴표로 적은 시나리오만 MODIFIED로 고친다. 시나리오 이름(예: "Claude 초안 표시")은 테스트·추적표 연결 때문에 그대로 둔다.

## 대안

- 줄 → 건, 상태 이름까지 한 번에: 수십 개 테스트·스펙 시나리오 문구가 바뀌어 위험이 커서 다음 단계로 나눔.
