# Proposal

## Why

여러 화면에 개발자를 위한 문구가 그대로 보인다. DB 표 이름(`review_run · run_step_time`, `product_master`), change 이름(`add-type-examples`), 규칙 번호(`CR-09`, `CR-06`), 명령(`rfp-db load-answer-key …`), 환경 변수(`RFP_MAIL_SALES`), "적재 판", "요약 응답 모양" 같은 것들이다. 영어를 옮긴 듯한 말("뜻 비슷", "같은 뜻 표현", "코드 규칙", "코드가 씀", "언어 모델")도 섞여 있어 업무 화면답지 않다. 또 검토 등록·문서 추가 안내는 "스캔한 문서의 글자는 읽지 않음", "docx 올리기"로, PDF·OCR을 받는 지금 동작(add-pdf-input, add-ocr)과 맞지 않는다.

관련: 모든 화면, CLAUDE.md "글쓰기", `docs/screens/_프런트원칙.md`.

## What Changes

- 개발자용 문구는 지우거나 사용자 말로 바꾼다(표 이름·change 이름·규칙 번호·명령·환경 변수·적재·판).
- 용어를 통일한다: 뜻 비슷 → 유사도, 뜻 찾기 → 유사 문장 검색, 가까운 → 유사, 같은 뜻 표현 → 동의어, 코드 규칙 → 규칙 기반, 코드가 씀 → 자동 요약, 언어 모델 → AI, 사람 확인 전 → 검수 전, Claude 초안 → AI 초안, 코드 자동 → 자동 생성, 팀 합성 → 팀 가정, 담당 전달 → 협조 요청, 문장 벡터 → 유사도 분석.
- 사실과 다른 안내를 고친다: 검토 등록 "docx·PDF, 스캔 문서는 글자 인식(OCR)으로 읽음", 파일 칸 이름 "파일 올리기"·"추가할 파일 (docx·PDF)".
- 스펙 시나리오가 화면 문구를 적은 곳(정답지 꼬리표, 동의어로 추가, AI 추출, 자동 요약, 근거 위치 불일치)을 같은 말로 고친다.

## Non-Goals

- 동작·API·백엔드 변경 없음. 백엔드가 만드는 문장(오류 메시지 등)은 그대로.
- 개수 단위(줄 → 건), 상태 이름(안 보냄 등), 동사(고치기 → 수정 등)는 이번에 바꾸지 않는다(테스트·스펙이 넓게 쓰고 있어 따로 정한다).
- 예시 화면(views/examples)과 부품 견본은 그대로.
