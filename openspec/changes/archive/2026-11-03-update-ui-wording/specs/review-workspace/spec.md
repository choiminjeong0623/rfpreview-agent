## MODIFIED Requirements

### Requirement: 정답지·채점 화면
화면은 정답지·채점(SCR-19)에서 채점 결과(지표, 무엇을 재나, 지난, 이번, 변화, 목표), 정답지(사람이 판정을 확정한 검토와 넣기 체크, 유형 정답지와 "Claude 초안·사람 확인 전" 표시), 개선 기록(채점 기록)을 실제 데이터로 보이고, "지금 채점하기"로 넣은 검토·고른 정답지·메모로 채점해야 한다(SHALL). 예시 띠를 붙이지 않는다. [제안]

#### Scenario: 지금 채점하기
- **WHEN** 사람이 판정을 확정한 검토가 있는 상태에서 정답지·채점 화면의 "지금 채점하기"를 누르면
- **THEN** 채점 결과 탭에 K5와 처리 시간 값이 보이고 개선 기록에 새 줄이 생긴다

#### Scenario: Claude 초안 표시
- **WHEN** Claude 초안 유형 정답지가 들어 있는 상태에서 정답지 탭을 열면
- **THEN** 그 정답지에 "AI 초안 · 검수 전"과 사람 확인 줄 수가 보인다

### Requirement: 버린 AI 설명 표시
화면은 실행 기록 화면 검토 줄에 버린 AI 설명 수를 보이고(0이면 보이지 않음), 위험 조건 탭에서 설명을 버린 줄의 설명 칸에 "AI 설명 버림"과 이유(근거 위치 불일치, 근거에 없는 인용, 근거에 없는 숫자, 형식 오류)를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 버린 설명 보기
- **WHEN** 설명 하나가 근거에 없는 숫자로 버려진 검토의 위험 조건 탭과 실행 기록 화면을 열면
- **THEN** 그 위험 조건 줄에 "AI 설명 버림 · 근거에 없는 숫자"가, 실행 기록 줄에 "AI 설명 버림 1"이 보인다

### Requirement: 요구사항 정답지 고르기 화면
화면은 정답지·채점 화면 정답지 탭에서 유형 정답지와 따로 요구사항 정답지 목록(이름, 대상 문서, 줄 수, 만든 이)을 보이고 하나를 골라 채점하게 해야 한다(SHALL). 코드가 만든 정답지에는 "자동 생성 · 검수 전"을 붙이고, 판정 줄이 없는 검토는 "판정 0줄"로 보이되 처음에는 넣지 않는다. 요구사항 정답지로 채점하면 채점 결과에 K1·K2·K3·K10이 보인다. [제안 11-01]

#### Scenario: 요구사항 정답지로 채점
- **WHEN** 코드 자동 요구사항 정답지가 있는 상태에서 정답지 탭을 열어 그 정답지를 고르고 "지금 채점하기"를 누르면
- **THEN** 정답지에 "자동 생성 · 검수 전"과 대상 문서가 보이고, 채점 결과 탭에 K1 값이 보인다

### Requirement: 뜻 찾기 표시
화면은 위험 조건 탭에 "사전 추가 후보"(문장, 유사 문장·표현, 유사도, 원문 위치, [사전 추가 제안])와 유사 문장 검색 상태(안 함·건너뜀)를 보이고, 판정 탭 지난 확정 꼬리표에 뜻으로 찾은 것이면 "유사도 0.93"처럼 점수를 붙이며, 판정 규칙 화면 "항목 이름" 탭에 연결 후보와 엔지니어·승인자용 [동의어로 추가]·[숨기기]를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 사전 추가 후보 보기
- **WHEN** 사전 추가 후보가 있는 검토의 위험 조건 탭을 열면
- **THEN** 후보 문장과 유사도, 유사 문장이 보이고 [사전 추가 제안]을 누르면 아래 제안 칸에 그 문장(100자까지)과 메모가 채워진다

#### Scenario: 항목 연결 후보 받아들이기
- **WHEN** 엔지니어가 판정 규칙 화면 항목 이름 탭의 연결 후보에서 [동의어로 추가]를 누르면
- **THEN** 후보가 목록에서 빠지고 알림이 보인다

### Requirement: 판정 상세 근거와 출처
화면은 판정 상세에 비교(요구값·부등호·제품값), 판정 근거(비교 방향과 판정 규칙 보기, 적용 규칙, 같은 요구가 나온 위치 수, 제품값 출처, 팀 가정이면 "팀 가정"), 판정 출처(시스템 제안, 요구사항을 찾은 방법과 신뢰도, 담당자 확정, 지난 확정)를 보여야 한다(SHALL). 질의 후보는 "질의 초안" 꼬리표, 목록 문장이 있으면 그 문장, 보증값 작성 줄은 후보 값과 데이터시트로 가는 링크를 보인다(SHALL). 화면은 값을 계산하지 않는다(CR-01).

#### Scenario: 팀 가정 표시
- **WHEN** 팀 가정 비교값으로 한 판정의 판정 상세를 열면
- **THEN** 제품값 출처 옆에 "팀 가정"이 보인다

#### Scenario: 찾은 방법과 신뢰도
- **WHEN** AI가 찾은 요구사항의 판정 상세를 열면
- **THEN** 판정 출처에 "AI 추출"과 신뢰도가 보인다

### Requirement: 요약 상자
화면은 검토 상세 제목 줄 아래와 홈 나의 업무 아래에 요약 상자를 보여야 한다(SHALL). 상자에는 "요약"과 "자동 요약" 꼬리표, 요약 시각, [다시 요약], 문장(링크는 그 화면으로 이동)이 있다. 요약을 부르지 못하면 상자를 숨기지 않고 "요약을 만들지 못했습니다"와 [다시 요약]을 보인다. 검토가 처리 중이면 검토 상세에는 상자를 두지 않는다. [결정 Q1]

#### Scenario: 검토 상세 요약 상자
- **WHEN** 담당자 확인 단계 검토 상세를 열면
- **THEN** 제목 줄 아래에 "요약" · "자동 요약" 상자와 꼭 볼 것 문장이 보이고, 일탈 후보 링크를 누르면 그 판정 상세로 간다

#### Scenario: 홈 요약 상자
- **WHEN** 엔지니어가 홈을 열면
- **THEN** 나의 업무 아래 요약 상자 첫 문장의 수가 "내가 처리할 건" 칸의 수와 같다

#### Scenario: 요약 실패
- **WHEN** 요약 API가 실패하면
- **THEN** 상자에 "요약을 만들지 못했습니다"가 보이고 [다시 요약]을 누르면 다시 부른다
