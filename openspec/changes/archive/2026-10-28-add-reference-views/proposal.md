# Proposal

## Why

화면 목업 v4.57의 "제품표"(SCR-16)와 "판정 규칙"(SCR-17) 화면은 판정이 **무엇을 기준으로** 나왔는지 보여 주는 화면이다.
값은 이미 DB에 있다(`product_master`, `compare_rule`, `item_key`, `item_alias`, `risk_expression`, `fault_link`). 하지만 이것을 읽는 API가 없어서
엔지니어는 판정 근거가 된 제품값이 어디서 왔는지, 어떤 비교 방향이 적용됐는지 화면에서 확인할 수 없다.
2026-10-28 minjeong 결정: 두 화면은 예시 화면이 아니라 **읽기 API를 만들어 실제 화면**으로 한다.

관련: FR-05(항목 이름 사전), FR-06(위험 표현 사전), FR-07(비교 방향, 제품표), FR-13(손실값 팀 가정), FR-14(강점 방향), FR-15(현장 이력 연결표),
CR-02(근거 위치), CR-04(빈 값은 비워 둠), CR-06(팀 가정 표시), CR-11(사전·제품표 판).

## What Changes

- 제품표 읽기 API: 제품 목록(제품군 거르기, 코드·이름 검색), 제품 하나의 전체 칸, 판정에 쓰는 칸 중 빈 칸 수와 팀 가정 칸 수, 설계 사례 카드 표시, 값의 출처(`source_doc`).
- 제품 하나가 어디에 쓰였는지: 현재 판정에 비교 제품으로 쓰인 수와 실행별 목록, 제안 포인트, 연결된 현장 이력(고장 사례).
- 규칙 사전 읽기 API: 비교 방향 사전, 표준 항목과 같은 뜻 표현(항목 이름 사전), 위험 표현 사전. 각 줄이 현재 판정·위험 조건에 몇 번 쓰였는지.
- 화면: SCR-16 제품표(목록, 거르기, 오른쪽 제품 상세, 두 제품 나란히 비교), SCR-17 판정 규칙(사전 탭 3개, 검색, 쓴 횟수).

## Non-Goals

- 제품표·사전 **고치기**(엑셀 가져오기, 규칙 추가, 수정 요청). 바꾸는 방법은 지금처럼 `data/seed/`를 고쳐 다시 적재하는 것이다.
- 목업의 "단위" 사전 탭(단위 사전이 없음, 단위 환산은 하지 않음 CR-10), 규칙별 마지막 수정자·수정일(기록이 없음).
- "요구 조건으로 제품 찾기", "사람이 제안한 위험 표현" 목록.
- 표준 문구(SCR-18), 정답지·채점(SCR-19)은 예시 화면으로 남긴다.

## Capabilities

### New Capabilities
없음.

### Modified Capabilities
- `reference-data`: 제품표와 규칙 사전을 읽는 요구사항, 쓰인 곳 집계를 더한다.
- `review-workspace`: 제품표 화면과 판정 규칙 화면을 더한다.

## Impact

- API: `GET /api/products`, `GET /api/products/{code}`, `GET /api/rules/compare`, `GET /api/rules/items`, `GET /api/rules/risk-expressions` 추가. 모두 읽기 전용.
- DB 변경 없음(마이그레이션 없음). 판정·후보 계산은 바뀌지 않는다.
- 화면: 메뉴 "지식 관리"에 두 화면 추가.
