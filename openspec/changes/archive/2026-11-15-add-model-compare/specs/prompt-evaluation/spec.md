## MODIFIED Requirements

### Requirement: 모델 비교
시스템은 같은 평가셋을 AI 사용 방식 `gemini`와 `local`(사내 OpenAI 호환 주소) 모델로 각각 평가할 수 있어야 하며, 평가셋별 보기에서 모델마다 최근 평가를 나란히 보여야 한다(SHALL, NFR-07). 여러 회사 모델을 한 번에 비교하는 실행은 "여러 회사 모델 비교 실행" 요구사항을 따른다. [제안]

#### Scenario: 오픈 모델과 나란히
- **WHEN** 같은 유형 평가셋을 `gemini`와 `local`(오픈 모델 1종)로 한 번씩 평가하면
- **THEN** 평가셋 보기에 두 모델의 지표·시간·비용이 나란히 보인다

## ADDED Requirements

### Requirement: 여러 회사 모델 비교 실행
시스템은 `공급자:모델` 목록(공급자 `gemini`·`anthropic`·`openai`·`local`)을 받아 같은 평가셋과 같은 프롬프트 판을 모델마다 평가하고, 모델마다 평가 기록 하나를 같은 비교 묶음 번호로 남기며, 모델이 줄인 비교표(역할별 주 지표 최솟값, 형식 오류율, 주입 영향, 호출·토큰, 추정 비용, 응답 시간 p50·p95)를 내야 한다(SHALL). 키가 없는 모델은 "건너뜀(키 없음)"으로 남기고 나머지는 평가한다. 분석 운영 모델은 바꾸지 않는다. [제안 v4 FR-23]

#### Scenario: 키가 없는 모델이 섞인 비교
- **WHEN** 모델 3개를 비교하는데 그중 하나의 키가 없으면
- **THEN** 두 모델은 지표·비용·p50·p95가 표에 남고, 키 없는 모델은 "건너뜀(키 없음)"이며 그 모델로는 요청이 0건이다

#### Scenario: 한 모델의 설정 오류
- **WHEN** 비교 중 한 모델이 키·모델 설정 오류로 답하지 못하면
- **THEN** 그 모델의 문항은 답 없음으로 세고, 다른 모델의 결과는 그대로 남는다

#### Scenario: 비교 기록 묶음
- **WHEN** 모델 2개 비교를 끝내면
- **THEN** 평가 기록 2개가 같은 비교 묶음 번호와 각자의 공급자로 저장되고, 평가 조회 API에 보인다

### Requirement: 문항 응답 시간
시스템은 평가 문항마다 묻는 데 걸린 시간(재시도·도구 반복 포함)을 재고, 평가 기록에 모든 반복·문항의 응답 시간 p50·p95(밀리초)를 남겨야 한다(SHALL). [제안 v4 FR-23]

#### Scenario: 응답 시간 기록
- **WHEN** 문항 4개를 평가하고 각 문항이 100·200·300·900밀리초 걸리면
- **THEN** 기록의 p50은 200, p95는 900이다

### Requirement: 같은 품질에 가장 싼 모델
시스템은 비교 결과에서, 역할마다 주 지표 최솟값이 그 역할의 최고 모델보다 평가셋 문턱(%p) 넘게 낮지 않고 주입 영향이 0이며 추정 비용을 아는 모델 가운데 추정 비용이 가장 적은 모델을 코드로 골라 비교표 아래 한 줄로 보여야 한다(SHALL, CR-01). 고를 모델이 없으면 이유를 보인다. [제안 v4 FR-23]

#### Scenario: 싸고 품질이 같은 모델
- **WHEN** 유형 정확도가 A 90 %(비용 300원), B 89 %(비용 50원), C 70 %(비용 10원)이고 문턱이 2 %p이면
- **THEN** 가장 싼 모델은 B다

#### Scenario: 단가를 모르는 모델
- **WHEN** 품질이 가장 좋은 모델의 단가를 모르고 다른 모델은 문턱 안에 들지 않으면
- **THEN** "고를 수 없음"과 이유를 보인다

### Requirement: 허용되지 않은 외부 전송 막기
시스템은 고객 원문이 든 평가셋(`data/private/` 아래)을 운영진이 허용한 Gemini와 사내 `local`로만 보내야 하며, `anthropic`·`openai` 모델은 요청 없이 "건너뜀(외부 전송 허용 안 됨)"으로 남겨야 한다(SHALL, NFR-07). [제안 v4 FR-23]

#### Scenario: 비공개 평가셋과 외부 모델
- **WHEN** `data/private/eval/` 평가셋을 `anthropic` 모델과 `local` 모델로 비교하면
- **THEN** `anthropic` 모델은 요청 0건으로 "건너뜀(외부 전송 허용 안 됨)", `local` 모델은 평가된다

### Requirement: 비교 비용 상한
시스템은 비교를 시작하기 전에 보낼 수 있는 모델들의 어림 비용 합을 상한과 비교하고, 넘으면 확인 옵션 없이는 어떤 모델도 부르지 않아야 한다(SHALL). 단가를 모르는 모델은 합에서 빼고 보고서에 알린다. [제안 v4 FR-23]

#### Scenario: 합계가 상한을 넘는 비교
- **WHEN** 모델 하나하나는 상한 아래지만 합이 상한을 넘는 비교를 확인 옵션 없이 시작하면
- **THEN** AI를 부르지 않고 합계 어림 비용과 상한을 알린다
