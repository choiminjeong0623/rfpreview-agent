# Proposal

## Why

시스템은 후보까지만 낸다(CR-08). 사람이 확인·승인하기 전에는 아무것도 확정되지 않아야 하고, 엔지니어가 결과를 보고 판단할 화면이 있어야 RFP 1건을 처음부터 끝까지 시연할 수 있다. 업무 흐름 ⑩, FR-10, 승인 기준 AR-01·02·03·06·07·08, 기획서 6-3, 화면 시안 1·3.

## What Changes

- 멈춤 지점 2곳(담당자 확인, 승인)과 승인 기준 판단.
- 확정 / 수정 / 반려 / 채택 / 버림 동작과 수정 이력. 확정 뒤 수정하면 관련 목록을 다시 점검.
- 기술 제안 포인트는 채택한 것만 전달 대상(AR-08).
- 화면: 문서 올리기와 실행 상태, 요구사항 표(유형 칸), 위험 조건, 적합성 표(비교 제품·여유), 보증값, 일탈·질의 목록과 누락 점검, 제안 포인트 채택, 승인.

## Capabilities

### New Capabilities
- `review-approval`: FR-10 담당자 확인, 승인, 수정 이력.
- `review-workspace`: 엔지니어·승인자가 결과를 보고 판단하는 화면.

### Modified Capabilities

## Impact

- 앞의 두 change(add-document-pipeline, add-judgment-and-outputs)의 결과 표를 읽고 쓴다.
- 사용자 구분은 MVP에서 app_user의 역할로만 한다. 로그인은 범위 밖.
- 범위 밖: FR-11 "내 할 일" 화면(Should), 입찰 검토 요약 화면(제외).
