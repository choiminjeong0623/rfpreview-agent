# Proposal

## Why

검토 목록·홈 일정·상신 권장일·사업 마감은 모두 검토의 제출 마감일로 움직인다. 그런데 마감일은 화면 등록에서만 꼭 넣게 되어 있고, API(`POST /api/runs`, `/api/runs/library`)와 `rfp-review run`은 마감일 없이도 검토를 만든다. 확정 스펙도 "모든 칸은 비어 있어도 된다"(review-run "검토 정보")라서, e2e·pytest·스크립트로 만든 검토는 대부분 마감이 비어 있다(로컬 `rfp` 513건 중 29건만 마감 있음). 마감이 빈 검토는 목록 D-day, 홈 달력, 상신 권장일에 나타나지 않는다.

## What Changes

- 제출 마감일은 검토를 시작할 때 꼭 받는다. API가 마감일 없이 시작하면 400 "제출 마감일을 입력해 주세요."로 실행을 만들지 않는다. 다른 검토 정보 칸은 그대로 비어 있어도 된다.
- 머리글 고치기에서 마감일을 비울 수 없다(400).
- `rfp-review run`은 `--due-in`(기본 14일)으로 사람이 정한 마감을 넣는다(`rfp-db demo-businesses`와 같음).
- 이미 마감이 빈 검토: `rfp-db fill-due --due-in N`을 사람이 돌리면 시작일 + N일로 채우고 이력에 "시연 데이터 마감 채움"을 남긴다. 시스템이 저절로 채우지 않는다(CR-04).
- e2e·pytest가 검토를 만들 때 마감일을 보낸다.

## Non-Goals

- 마이그레이션으로 기존 줄을 채우지 않는다(실데이터에 지어낸 날짜가 들어감).
- 사업 마감(business.due_date)은 그대로 비어 있어도 된다.
