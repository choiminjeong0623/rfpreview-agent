# Design

## 결정

- **마감일만 필수.** 목록·홈·요약·사업 현황이 모두 마감으로 줄을 세우고 D-day를 보이므로, 등록 화면과 같이 API도 마감을 받는다. 사업명·고객사 등은 등록 뒤에 채워도 되는 정보라 그대로 둔다.
- **검사 자리.** `review_info.require_due`를 `_start`에서 실행을 만들기 전에 부른다(판정 대상 검사 다음). 고치기에서는 `due_date`를 보냈는데 비었으면 거절한다.
- **기존 빈 마감은 사람이 돌리는 명령으로만.** 마이그레이션은 실데이터에도 돌아 시스템이 날짜를 지어내게 되므로(CR-04) 쓰지 않는다. `rfp-db fill-due`는 개발·시연 DB에서 사람이 일부러 돌리고, 시작일 + N일(기본 14, 데모 사업과 같음)로 줄마다 다른 날을 넣고 이력(EDIT, 사유 "시연 데이터 마감 채움 (rfp-db fill-due)")을 남긴다.
- **CLI 기본값.** `rfp-review run --due-in 14`. 명령을 돌리는 사람이 고르는 값이다.

## 대안

- 마감이 비면 화면에서 "마감 없음" 칩으로 강조: 홈 달력·상신 권장일이 여전히 빠져 버림.
- API에서 마감이 비면 오늘 + 14일로 채우기: 사람이 넣지 않은 값을 시스템이 지어내므로(CR-04) 버림.
