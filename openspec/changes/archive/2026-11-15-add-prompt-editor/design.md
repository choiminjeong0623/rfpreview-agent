# Design

## 결정

1. **iframe 대신 우리 화면 + Langfuse 공개 API.** Langfuse 화면을 끼우면 Langfuse 로그인이 따로 필요하고, 저장 전에 자리표시자·데이터 규칙(CR-14) 검사를 걸 수 없다. 이미 쓰는 `prompt_source.Client`(get_prompt·create_prompt·set_labels)를 그대로 쓴다.
2. **저장은 언제나 staging.** 화면에서 저장한 글은 운영에 바로 가지 않는다. 운영 반영은 평가를 거친 판만(ADR-011의 `--promote`와 같은 규칙: 3번 반복·기준선 있음·회귀 없음).
3. **권한.** 역할 표에 관리자가 없다. 고치기·평가는 엔지니어·승인자, 운영으로 올리기는 승인자만. 협조 부서는 보기만.
4. **평가 범위.** 화면 평가는 그 역할 문항만(공개 평가셋, 반복 3). 다른 역할은 지금 운영 판. 주입 시험·도우미 픽스처는 평가셋 규칙 그대로 따른다. 결과는 평가 기록(`prompt_eval_run`)에 메모 "화면 staging 평가"와 함께 남아 프롬프트 관리 점수에도 보인다.
5. **평가 작업은 웹 서버 스레드.** 수 분 걸리므로 요청은 작업 번호만 돌려주고 화면이 3초마다 묻는다. 동시에 하나만 돈다. 실행 대기열은 검토 실행용이라 쓰지 않는다(Non-Goals).
6. **올리기 직전 다시 확인.** 평가한 뒤 누가 staging에 새 판을 저장했으면 올리지 않고 "다시 평가"를 요구한다.

## 버린 대안

- Langfuse 화면 iframe: 로그인 따로, 검사 못 걸고, 같은 출처 정책 문제.
- 화면에서 바로 운영 저장: 평가 없는 판이 검토에 쓰임.
- 관리자 역할 추가: 역할 표·화면 사용자 바꾸기·스펙 여러 곳이 바뀜. 지금은 승인자로 충분.

## 위험

- 웹 서버가 여러 개면 작업 상태가 서버마다 다르다. 지금 배포는 웹 서버 하나라 받아들임.
- 실제 Langfuse 서버로 끝까지 돌려 보지 못했다(이 환경에서 Langfuse 스택을 띄우지 못함). 가짜 서버(같은 공개 API)로 시험했다. [확인 필요]
