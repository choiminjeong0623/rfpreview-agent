# 위험 설명 검증 에이전트 (B조 B2)

## 왜

- AI 기술 활용성 추가 개발 항목 B2. 근거 대조(add-claim-evidence, update-ai-answer-checks)는 근거 ID·인용 글자·숫자만 본다. 인용이 원문에 그대로 있어도, 그 인용이 설명 문장의 주장을 받쳐 주는지는 보지 못한다. 예: 인용 "0.5 % or less"에 "누설 기준이 더 엄격하다"는 해석을 붙여도 통과한다.
- 평가 항목 "에이전트 역할 분담"과 "환각 대응"에 함께 닿는다: 쓰는 AI와 검사하는 AI의 역할을 나눈다.

## 무엇

- 코드 대조를 통과한 위험 조건 설명마다, 다른 질문(검증 프롬프트)으로 문장별 "인용과 근거 조각이 이 문장을 받쳐 주나"를 예(YES)/아니오(NO)/모름(UNSURE)으로 받는다.
- 모든 문장이 예면 설명에 "AI 검증 통과"(VERIFIED). 하나라도 아니오·모름이거나 검증 답 형식이 틀리면 "AI 검증: 확인 필요"(NEEDS_REVIEW). 문장별 상태도 claim_evidence에 남긴다(SUPPORTED / NEEDS_REVIEW).
- 설명은 지우지 않는다. 후보·판정도 바꾸지 않는다(CR-01·08). 사람이 볼 곳만 표시한다.
- 위험 조건 탭 설명 옆 "AI 검증: 확인 필요" 꼬리표, 실행 기록 "검증 확인 필요 n". 마이그레이션 0026.

## 하지 않음

- 문장 초안(일탈·질의·제안)의 검증: 사실 문장을 코드가 쓰고 숫자는 자리표시자라 지어낼 여지가 적다. 다음 단계.
- 검증 결과로 설명을 자동으로 버리기: 검증 AI도 틀릴 수 있어 표시만.

관련: 명세서 FR-06 ④ "설명 검증 [제안 11-01]", add-claim-evidence.
