## Purpose

사람이 확정한 결과와 정답지로 시스템의 정확도를 코드로 재고, 사전·규칙을 고칠 때마다 점수를 다시 재 개선 전→후를 기록한다(기획서 2-2 K지표, 8장).

## ADDED Requirements

### Requirement: 유형 정답지 넣기
시스템은 유형 정답지 CSV(원문, 절 제목, 정답 유형, 애매함, 사람 확인)를 이름과 함께 넣어야 하며, 정답은 사람 확인 칸이 있으면 그 값, 없으면 초안 값으로 하고, 만든 이(Claude 초안 또는 사람)와 사람이 확인한 줄을 저장해야 한다(SHALL). 같은 이름으로 다시 넣으면 줄을 바꾼다. 정답 유형이 유형 코드가 아닌 줄은 넣지 않고 알린다. [제안]

#### Scenario: Claude 초안 정답지 넣기
- **WHEN** 4줄 가운데 1줄에 사람 확인 값이 있는 Claude 초안 CSV를 넣으면
- **THEN** 정답지 목록에 4줄, 사람 확인 1줄, 만든 이 Claude 초안으로 보이고, 사람 확인한 줄의 정답은 사람 값이다

#### Scenario: 잘못된 유형 코드
- **WHEN** 정답 유형이 유형 코드가 아닌 줄이 든 CSV를 넣으면
- **THEN** 그 줄은 빠지고 빠진 줄 번호가 알려진다

### Requirement: 채점
시스템은 고른 검토들과 고른 유형 정답지로 K4·K5·K6·K11·K12·K13과 처리 시간을 코드로만 재고(CR-01), 지표마다 값·분자·분모·목표·달성 여부를 내야 한다(SHALL). K5·K6는 사람이 확정·수정한 판정을 정답으로 보고, 수정한 판정의 시스템 판정은 첫 수정 이력의 이전 값으로 한다. 요구사항 정답지가 필요한 지표(K1·K2·K3·K8·K9·K10)는 재지 않았다고 보인다. 같은 입력이면 같은 점수여야 한다(SHALL, CR-11). [제안]

#### Scenario: 사람 확정 기준 판정 정확도
- **WHEN** 판정 4줄 중 3줄을 그대로 확정하고 1줄을 준수에서 일탈 후보로 고친 검토를 채점하면
- **THEN** K5는 3/4(75 %)이고, K6는 0/1이다

#### Scenario: 유형 분류 정확도
- **WHEN** 검토의 요구사항 원문과 글자가 같은 줄 3개(정답 2개 일치)와 없는 줄 1개가 든 정답지로 채점하면
- **THEN** K13은 2/3이고 못 찾은 줄 1개가 따로 보인다

#### Scenario: 결과만으로 재는 지표
- **WHEN** 원문 위치가 모두 있는 검토를 채점하면
- **THEN** K4는 100 %, K11·K12는 0건이고 처리 시간이 분으로 보인다

#### Scenario: 같은 입력 같은 점수
- **WHEN** 같은 검토와 같은 정답지로 두 번 채점하면
- **THEN** 두 기록의 지표 값이 같다

### Requirement: 채점 기록
시스템은 채점마다 검토 목록, 정답지, 지표, 메모(무엇을 고쳤나), 한 사람, 시각, 코드 판을 저장하고, 최근 것부터 보여야 한다(SHALL). [제안]

#### Scenario: 개선 전후
- **WHEN** 같은 검토를 채점하고 판정 하나를 고친 뒤 메모와 함께 다시 채점하면
- **THEN** 채점 기록 두 줄이 최근 것부터 보이고 두 번째 줄에 메모와 바뀐 K5가 있다
