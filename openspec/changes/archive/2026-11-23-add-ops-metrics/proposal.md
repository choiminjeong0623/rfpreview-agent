# Proposal: AI 호출 운영 지표·평가 중 비용 상한·사람 수정 비율 (add-ops-metrics)

## Why

2026-11-22 포트폴리오 점검 P1-1·P1-5·P1-8.

- P1-1: AI 호출 기록(`ai_call`)은 호출마다 남지만, 응답 시간 p50·p95·실패율은 모델 비교 평가에만 있다. 실제 분석에서 역할별로 얼마나 느리고 얼마나 실패하는지 한눈에 볼 수 없다.
- P1-5: 평가는 시작 전에 어림 비용만 본다. 어림이 틀리면(도우미 반복 질문, 긴 답) 상한을 넘겨도 끝까지 돈다(PR #25에서 상한 1,000원을 넘김).
- P1-8: 사람이 판정을 고치거나 반려한 이력은 있지만 비율로 모으지 않는다. "AI·규칙이 낸 판정을 사람이 얼마나 고쳤나"는 운영 품질의 기본 지표다.

## What Changes

1. 실행 기록 상세 "AI 호출"에 역할별 표: 요청 수, 시도 수(재시도 포함), 응답 시간 p50·p95, 실패율(성공 아닌 시도), 코드 검사로 버린 비율, 재시도 뒤 성공(첫 시도가 실패한 요청 중 나중에 성공한 수). `GET /api/runs/{id}/ai-calls` 응답에 `roles`.
2. 평가 실행 중 실제 사용량으로 비용을 재어 상한을 넘으면 아직 묻지 않은 문항은 묻지 않고 멈춘다. 결과는 실패(이유: 비용 상한)로 남기고 기준선 비교·운영 올리기에 쓰지 않는다. 확인 옵션으로 시작한 평가는 상한과 어림 비용 두 배 가운데 큰 값에서 멈춘다.
3. 채점에 "사람 수정 비율": 사람이 직접 본 판정(한꺼번에 확정만 받은 줄 제외) 중 수정·반려한 비율. 한꺼번에 확정 이력에 표시를 남긴다.

## Non-Goals

- 분석(검토 실행)의 비용 상한. 분석은 이미 실행 기록에 비용을 남기고, 멈추면 검토가 반쯤 끝난 상태가 된다.
- 새 화면. 실행 기록 상세와 채점 결과에 칸만 더한다.
- 마이그레이션. 이력 표시는 이유 칸 글로 남긴다.

## Capabilities

### Modified Capabilities

- `review-run`: AI 호출 기록 요약에 역할별 운영 지표.
- `prompt-evaluation`: 비용 상한을 실행 중에도.
- `evaluation`: 채점에 사람 수정 비율.
