# Proposal: AI 호출 기록 (add-ai-call-trace)

## Why

- 운영 중 "AI 답이 이상하다"는 신고가 오면 어느 단계의 어느 호출이 원인인지 찾아야 한다. 지금 실행 기록(NFR-09)은 검토 단위 합계(호출 수·토큰·비용·단계별 시간)뿐이고 호출 하나하나의 기록이 없다.
- 보안 때문에 프롬프트·답 원문을 저장하지 않아(NFR-06·07) 다시 볼 방법도 없다. 원문을 남기지 않으면서 추적할 수 있어야 한다.

관련: 명세서 v3 **FR-21**(Should), **NFR-14**, NFR-06·07·09, CR-11, FR-18(평가 실행), FR-20(실행 토큰). 기존 capability `review-run`(실행 기록), `service-health`. 팀 프로젝트 뒤 개인 개선.

## What Changes

1. **호출 기록** — AI 요청 한 번(재시도 포함)마다 검토·실행 토큰·처리 단계·AI 역할·모델·프롬프트 판·시작/끝·걸린 시간·토큰·결과(성공 / 형식 오류 / 설정 오류 / 시간 초과 / 연결 오류)·코드 검사에서 버린 이유·입력 해시·출력 해시·묶음 줄 수를 남긴다(마이그레이션 0043). 분석·검토 도우미·협조 요청 질문·프롬프트 평가 모두.
2. **원문은 기본으로 저장하지 않음** — 해시만. `RFP_TRACE_RAW=on`일 때만 원문을 따로 저장하고 7일 지나면 원문만 지운다. 켜져 있으면 상태 점검에 경고.
3. **같은 입력, 다른 답** — 입력 해시가 같은 다른 호출과 출력 해시가 다른 호출 수(재현성 점검, CR-11).
4. **화면** — 실행 기록 펼친 줄에 "AI 호출" 목록(단계·역할 거르기, 느린 순)과 단계별 시간 막대.
5. **OpenTelemetry 형식 내보내기** — 호출마다 span 하나(OTLP JSON, 생성형 AI 이름 규칙). 새 의존성·외부 전송 없음.

## Non-Goals

- 외부 추적 서비스(LangSmith 등)로 직접 보내기. 내보낸 JSON을 사람이 넣는다.
- 원문 기본 저장, 호출 다시 돌리기(replay).
- 문장 벡터 요청 기록: 명세서 ② 입력에는 있지만 토큰을 주지 않아 지금도 호출 수에 넣지 않으므로 이번에는 뺀다 [확인 필요].
