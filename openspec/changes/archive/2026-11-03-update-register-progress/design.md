# Design

## 결정

- **실제 업로드 진행.** `fetch`는 보내는 진행을 알려 주지 않아, 파일을 올릴 때만 `XMLHttpRequest`의 `upload.onprogress`로 보낸 바이트를 받는다(`api.upload(..., onProgress)`). 오류 처리는 `send`와 같게(`detail` 문장, 없으면 `API 상태 코드`).
- **두 번째 단계는 어림하지 않는다.** 서버가 파일을 저장하고 판정 대상을 확인해 검토를 만드는 시간은 알 수 없어 퍼센트를 지어내지 않고 끝을 모르는 막대(`.anbar.ind`)로 보인다.
- **자리.** 아래 단추 줄(`.foot2`) 바로 위. 막대는 공통 `.anbar`.

## 대안

- 0→90 % 어림 막대: 업로드는 실제 값을 받을 수 있어 굳이 어림하지 않음.
