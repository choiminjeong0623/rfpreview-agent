# Spec Delta

## Purpose

누가 시스템을 쓰는지 서버가 확인하고, 권한 검사와 이력의 "누가"를 요청이 보낸 값이 아니라 로그인한 세션 사용자로 정하기 위한 능력이다.

## ADDED Requirements

### Requirement: 비밀번호 로그인
시스템은 로그인 아이디와 비밀번호가 맞고 활성인 사용자에게 세션을 만들어 브라우저 스크립트가 읽을 수 없는 쿠키로 줘야 한다(SHALL). 아이디가 없거나 비밀번호가 틀리거나 비활성 사용자면 세션을 만들지 않고, 셋을 구분할 수 없는 같은 오류를 내야 한다(MUST). 비밀번호는 되돌릴 수 없는 형태로만 저장해야 한다(MUST).

#### Scenario: 맞는 비밀번호로 로그인
- **WHEN** 활성 사용자 "기본 엔지니어"가 맞는 아이디와 비밀번호로 로그인하면
- **THEN** 세션 쿠키를 받고, 내 정보 요청에 기본 엔지니어와 엔지니어 역할이 돌아온다

#### Scenario: 틀린 비밀번호와 없는 아이디
- **WHEN** 있는 아이디에 틀린 비밀번호로, 또 없는 아이디로 로그인하면
- **THEN** 두 경우 모두 401과 같은 오류 문구가 나고 세션 쿠키는 없다

#### Scenario: 비활성 사용자
- **WHEN** 비활성으로 바뀐 사용자가 맞는 비밀번호로 로그인하면
- **THEN** 401이 나고 세션은 만들어지지 않는다

### Requirement: API는 로그인을 요구
시스템은 상태 점검과 로그인 요청을 뺀 모든 API에서 유효한 세션이 없으면 요청을 처리하지 않고 401을 내야 한다(MUST). 로그아웃했거나 만료된 세션, 비활성이 된 사용자의 세션은 유효하지 않다.

#### Scenario: 쿠키 없이 부르기
- **WHEN** 쿠키 없이 공개 목록(상태 점검·로그인) 밖의 아무 API를 부르면
- **THEN** 401이 나고 아무것도 바뀌지 않는다

#### Scenario: 로그아웃한 세션
- **WHEN** 로그아웃한 뒤 같은 쿠키로 검토 목록을 부르면
- **THEN** 401이 난다

#### Scenario: 만료된 세션
- **WHEN** 세션 유지 시간이 지난 쿠키로 검토 목록을 부르면
- **THEN** 401이 난다

### Requirement: 세션 사용자로 권한과 이력
시스템은 역할 검사와 수정 이력·상신·결정·확정 기록의 "누가"를 세션 사용자로만 정해야 하고(MUST), 요청 본문이나 주소에 담긴 사용자 번호로 정하지 않아야 한다(MUST NOT). 결재자처럼 동작의 대상을 고르는 값은 요청으로 받는다. 역할이 허용하지 않는 동작은 403으로 거절한다.

#### Scenario: 엔지니어가 승인 시도
- **WHEN** 엔지니어로 로그인한 사용자가 승인 대기 검토를 승인하려 하면
- **THEN** 403이 나고 검토는 승인 대기로 남는다

#### Scenario: 본문에 다른 사용자 번호
- **WHEN** 엔지니어로 로그인한 사용자가 판정을 확정하면서 요청 본문에 승인자 사용자 번호를 함께 보내면
- **THEN** 확정 이력의 "누가"는 로그인한 엔지니어이다

#### Scenario: 지정 결재자 승인
- **WHEN** 상신 때 지정된 결재자로 로그인한 사용자가 승인하면
- **THEN** 검토는 승인됨이 되고 결정한 사람은 그 결재자이다
