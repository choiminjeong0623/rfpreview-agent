# Proposal: 읽지 못한 쪽 알림 (add-unread-pages)

## Why

- 11-14 실험: 글자 쪽(1·3쪽) 사이에 OCR 신뢰도가 낮은 스캔 쪽(2쪽)을 끼운 PDF를 넣자 결과에 1·3쪽만 남고, 2쪽은 문서 읽기 점검에도 보이지 않았다. 그 쪽의 요구사항을 놓쳐도 엔지니어는 알 수 없다. "빠짐없이 찾는다"(기획서 G1)와 어긋난다.
- OCR 엔진이 없거나 꺼져 있을 때(`RFP_OCR=off`)도 스캔 쪽이 같은 방식으로 빠진다. docx 그림도 OCR이 글자를 찾지 못한 이유가 남지 않는다.

관련: 명세서 v3 **FR-19**(Must), **CR-13**(못 읽은 곳을 숨기지 않음), **AR-09**. 기존 capability `document-intake`(OCR로 글자 읽기, 판정 대상 없는 등록 거절), `review-workspace`(문서 읽기 점검 탭, 검토 상세 문서 표, 검토 등록 문서 분류 확인), `review-approval`(결재 상신). 팀 프로젝트 뒤 개인 개선.

## What Changes

1. **쪽마다 읽은 결과 기록** — PDF를 읽는 그 자리에서 쪽마다 읽음 / 빈 쪽 / 읽지 못함과 이유(`OCR_OFF`, `OCR_MISSING`, `OCR_LOW_CONF`, `OCR_EMPTY`, `BLANK`), OCR이 버린 줄 수와 평균 신뢰도를 문서에 저장한다(마이그레이션 0041). 쪽 번호 빈틈으로 추측하지 않는다.
2. **docx·PDF 그림의 OCR 이유** — 그림을 OCR로 읽지 못하면 그림 위치에 같은 이유 코드를 남긴다.
3. **문서 읽기 점검 "쪽" 줄** — 읽지 못한 쪽마다 점검 줄 하나(빈 쪽은 줄 없이 수만), 이유별 문장. "그림" 줄에 OCR 이유 문장.
4. **문서 확인 필요** — 쪽 절반 이상을 읽지 못한 문서는 확인 필요.
5. **AR-09** — 확인하지 않은 "쪽" 점검 줄이 있으면 결재 확인 사유(상신은 막지 않음).
6. **화면** — 문서 표 "읽은 쪽 n / m", 등록 화면 미리 보기에 문서마다 읽지 못한 쪽 수와 OCR 꺼짐 안내, 판정할 문서를 모두 읽지 못해 거절할 때 이유가 든 다른 문구.

## Non-Goals

- 못 읽은 쪽을 AI 이미지 읽기나 다른 방법으로 채우기(CR-04, NFR-07).
- OCR 엔진·신뢰도 기준 바꾸기, 쪽 이미지 미리 보기.
- 다시 스캔한 파일 넣기: 지금의 "문서 추가"를 그대로 쓴다.
