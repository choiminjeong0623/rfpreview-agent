# Proposal

## Why

화면 목업 v4.57(24개 화면)과 지금 API를 대조한 갭 목록(2026-10-28)에서 가장 큰 갭은 **검토 한 건을 사람이 알아보는 정보가 없다**는 점이다.
검토 목록, 홈(내 업무), 검토 상세, 결재 화면이 모두 머리글에 검토명·고객사·국가·제출 마감·담당 엔지니어를 보여 주는데,
지금 `review_run`과 `/api/runs` 응답에는 실행 번호, 단계, 시작 시각, 파일 이름만 있다. 그래서 화면은 "실행 3"처럼만 부를 수 있고,
마감이 가까운 검토를 먼저 고를 수도 없다. 목록 응답에는 요구사항·위험·일탈·제안 개수도 없어 줄마다 요약 API를 따로 불러야 한다.

관련: FR-10(담당자 확인 — 누가 담당인지), FR-11(내 할 일), 명세서 1장 주 사용자(입찰 기술 검토 엔지니어),
기획서 7-1 일정(10-29 핵심 흐름 시연, 11-04 기능 동결). CR-02·04(시스템이 만든 값에만 원문 위치, 없는 값은 지어내지 않음).

## What Changes

- 실행에 **검토 정보** 칸을 더한다: 사업명, 검토명(설비 범위), 고객사, 국가, 제출 마감일, 담당 엔지니어. 모두 사람이 입력하는 값이고 비어 있어도 된다.
- 검토를 시작할 때(파일 올리기, 서버에 둔 문서로 시작) 검토 정보를 함께 받고, 시작한 뒤에도 고칠 수 있게 한다. 고치면 수정 이력이 남는다.
- 담당 엔지니어를 비워 두면 검토를 시작한 사람이 엔지니어일 때 그 사람으로 둔다.
- 실행 요약과 실행 목록 응답에 검토 정보, 검토 번호(`RV-<시작 연도>-<실행 번호 세 자리>`), 그리고 목록에는 요구사항·위험·일탈 후보·제안 포인트 개수를 넣는다.
- 요구사항·판정·보증값 목록 API는 걸러진 전체 개수를 함께 알려 준다(화면의 "전체 69건"과 페이지 번호).
- 화면: 검토 시작 칸에 검토 정보 입력, 검토 목록과 검토 머리글에 검토 정보·D-day 표시, 머리글에서 고치기.

## Non-Goals

- RFP 문서에서 검토명·고객사·마감일을 **자동으로 뽑는 것**(목업 등록 2단계 "자동 추출 확인"). 뽑으면 원문 위치가 필요하고(CR-02) 언어 모델이 빈칸을 채우면 안 되므로(CR-04) 별도 change로 한다.
- 사업(project) 단위 화면, Lot 나누기, 같은 입찰 묶기, 고객 입찰 번호(목업의 "사업 현황·사업 상세").
- 결재자 지정·상신 의견은 `update-approval-flow`에서 다룬다.
- 로그인·직급·팀 현황(명세서 범위 밖).

## Capabilities

### New Capabilities
없음.

### Modified Capabilities
- `review-run`: 검토 정보를 기록하고 고치는 요구사항, 실행 목록에 검토 정보·개수, 목록 API 전체 개수를 더한다.
- `review-workspace`: 검토 시작 때 검토 정보 입력, 목록·머리글 표시와 고치기를 더한다.

## Impact

- DB: 마이그레이션 다음 번호 1개(`review_run`에 칸 6개). 기존 실행은 칸이 비어 있고 화면은 파일 이름으로 대신 보여 준다.
- API: `POST /api/runs`(폼 칸 추가), `POST /api/runs/library`(본문 칸 추가), `GET /api/runs`, `GET /api/runs/{id}` 응답 칸 추가, `PUT /api/runs/{id}/info` 새로 추가, 목록 API에 `X-Total-Count` 머리글.
- 판정·후보 계산은 바뀌지 않는다(CR-11 영향 없음). 검토 정보는 판정에 쓰지 않는다.
- 화면: `App.tsx`의 시작 칸과 실행 고르기, 머리글 컴포넌트.
