# Proposal

## Why

RFP 1건을 끝까지 돌리려면 먼저 docx를 "한 줄" 단위의 요구사항과 비교할 수 있는 값으로 바꾸고, 놓치면 계약 조건이 되는 위험 조항을 찾아야 한다. 판정(FR-07)과 결과물(FR-09·13·14)은 모두 이 결과 위에서 동작한다. 업무 흐름 ①~⑥, 명세서 FR-01~06, 추적표 v3 사례 1, 4, 6~11, 13.

## What Changes

- 검토 실행(review run): 문서를 올리면 실행 하나가 생기고, 모든 결과가 그 실행과 사전 판에 묶인다. AI 오류는 정해진 횟수만 재시도한다(CR-11, CR-12).
- 근거 묶음 규칙: 모든 결과 값에 원문 위치·신뢰도·가정 여부. 위치가 없으면 내보내지 않는다(CR-02~05).
- FR-01 문서 분류(묶음, 종류, 규격 체계, 판정 대상, 판독 불가, 원본·정정본 쌍 후보).
- FR-02 구조 나누기(절 복원, 쪽 넘김 표 잇기, 반복 머리글 제거, 하위 항목, 칸 역할, 목차 구분).
- FR-03 요구사항 추출, FR-04 유형 표시.
- FR-05 값 정리(칸 형태 6종, 기호·단위·조건 분리, 계산식, 규격 위임, 단위 환산 안 함).
- FR-06 위험 조건 찾기(포괄 조항, 값 불일치, 범위 모호).
- Gemini 호출부: 절 단위 입력, 응답 형식 검증, 재시도. 키가 없으면 AI 보조 단계를 건너뛰고 코드 규칙 결과만 낸다. 키가 있는데 재시도 뒤에도 실패하면 "처리 실패 — 다시 시도"로 멈춘다.

## Capabilities

### New Capabilities
- `review-run`: 검토 실행의 생성, 단계, 실패 처리, 재현성.
- `evidence-integrity`: 모든 결과 값의 근거 묶음과 지어내지 않음 규칙.
- `document-intake`: FR-01 문서 분류와 FR-02 구조 나누기.
- `requirement-extraction`: FR-03 요구사항 추출과 FR-04 유형 표시.
- `value-normalization`: FR-05 값 정리.
- `risk-detection`: FR-06 위험 조건 후보.

### Modified Capabilities
- `service-health`: 스키마 판 Scenario를 "마지막 마이그레이션"으로 바꾼다(0003 추가).

## Impact

- 새 의존성: python-docx(design.md), LangGraph, Google Gen AI SDK, python-multipart.
- 새 API: 문서 올리기, 실행 시작·상태, 문서·쌍 후보·요구사항·값·위험 조건 조회. 새 명령 `rfp-review run`.
- DB: 마이그레이션 0003(처리 판, 실행 실패 정보, 표 행 칸, 사전 표 2개, 기본 사용자).
- 사전 작업 필요: 칸 이름 사전, 유형 규칙표, 사업 묶음 표(Q5 답 전까지 파일 3~8은 "확인 필요"), 위험 표현 사전의 빈 조건 4줄.
- 범위 밖: FR-11 유형별 전달, FR-12 공학 규칙 검산, OCR(파일 8), 단위 환산.
