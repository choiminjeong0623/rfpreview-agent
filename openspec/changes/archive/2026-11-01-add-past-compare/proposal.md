# Proposal

## Why

입찰 엔지니어는 같은 고객의 반복 입찰에서 "지난번과 무엇이 달라졌나"부터 본다. 바뀐 요구가 일탈·질의의 시작점이고, 같은 요구는 지난번 판단을 그대로 쓸 수 있기 때문이다.
검토 상세 "지난 RFP 비교" 탭은 목업대로 만들었지만 API가 없어 예시 화면이었다(SCR-08-7_공유 1번). 검토 상세 탭 9개 가운데 마지막 남은 예시 탭이다.
통합 개발 목록 3장 '다음 단계'에서 "지난 RFP 비교 실제화"를 골랐다(2026-11-01, minjeong "멈추지 말고 진행").

관련: 명세서 8장 "지난 RFP 비교"(11-01 추가), CR-01·10·11, `review-workspace` "지난 RFP 비교 예시 탭"·"검토 상세 요약 칸과 탭".

## What Changes

- 비교 대상: 고객사 글자가 같은(앞뒤 공백·여러 칸 공백·대소문자 무시) 처리를 마친 다른 검토, 최근 것부터 20개.
- 비교: 두 검토의 지금 판정 줄을 같은 설비(제품군 + 설비 최고 전압)·같은 항목(표준 항목 + 표의 항목 이름)으로 짝지어 값 바뀜·새로 생김·사라짐과 판정 변화를 낸다. 값과 판정이 같은 줄은 숨기고 수만 보인다. 반려한 판정은 뺀다.
- 참고 문장은 코드가 쓴다: 같은 단위일 때만 "요구 값이 올라감/내려감"(단위 환산 없음), "판정 같음/바뀜", "지난번에 없던 요구", "이번에는 요구 없음 · 지난번 ○○".
- API `GET /api/runs/{id}/compare`, `GET /api/runs/{id}/compare/{other_id}`.
- 지난 RFP 비교 탭을 실제 데이터로: 예시 띠를 없애고, 고객사가 없거나 대상이 없으면 안내를 보인다. 지난 검토 번호는 그 검토 상세로 간다.

## Non-Goals

- 지난 입찰 결과(수주·실주), 입찰 번호. 입찰 이력 데이터가 없다(입찰 이력 화면은 예시).
- 줄을 눌러 판정 상세 창 열기(목업). 다음에 판정 탭과 잇는다.
- 고객사 이름이 조금 다른 경우(약칭 등) 같은 고객으로 묶기. 글자가 같아야 한다.
- AI로 비슷한 항목 짝짓기. 짝짓기는 코드 규칙만(CR-01).
