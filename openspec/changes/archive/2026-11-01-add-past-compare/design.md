# Design

## 결정

1. **짝짓는 열쇠 = (설비, 표준 항목, 항목 이름).** 설비는 판정 묶음의 제품군 + 설비 최고 전압(`GroupContext.family`, `um`)이다. 묶음 키(`T63|`처럼 표 번호가 든 내부 값)는 검토마다 달라 쓰지 않는다. 최고 전압이 없으면 묶음 이름을 쓴다. 항목 이름은 표의 항목 이름(`table_row.item_name_raw`)을 소문자·기호 없음·앞 번호 없음으로 고친 것이고, 표 밖 문장은 표준 항목 이름, 그것도 없으면 원문 앞 80자다. 같은 고객의 데이터시트는 항목 이름이 거의 같아 이 규칙으로 충분하다고 봤다. 대안(AI 짝짓기)은 CR-01 때문에 버렸다.
2. **한 열쇠에 값이 여럿이면 값 묶음으로 비교.** 같은 표에 같은 항목 이름이 여러 번 나오면(예: 정격 전류 4,000 A 세 곳) 값 글자 묶음을 비교하고, 판정 칸에는 가장 무거운 판정(일탈 → 질의 → 확인 필요 → 작성 필요 → 준수)을 보인다.
3. **값 글자 비교, 단위 환산 없음.** 값은 원문 값 + 단위 글자로 비교한다. 올라감·내려감은 양쪽 값이 하나씩이고 단위 글자가 같을 때만 숫자로 비교한다(CR-10).
4. **사람 확인 반영.** 수정한 판정은 판정 칸의 값을 쓰고(수정 결과), 반려한 판정은 양쪽에서 뺀다.
5. **고객사 비교는 글자.** 앞뒤 공백, 여러 칸 공백, 대소문자만 무시한다. 고객사가 비면 대상이 없다.
6. **정렬.** 값 바뀜 → 새로 생김 → 사라짐, 그 안에서 판정 무게 → 설비 → 항목 → 값 글자 순서. 같은 두 검토면 같은 결과(CR-11).

## 위험

- 다른 고객사가 같은 이름을 쓰면 섞인다. 고객사 칸은 사람이 넣는 값이라 받아들인다.
- 항목 이름이 바뀐 개정 데이터시트는 "사라짐 + 새로 생김" 두 줄로 보인다. 참고 문장으로 구분하지 않는다.
- 판정 묶음 계산(`group_contexts`)을 두 검토에 대해 하므로 큰 RFP는 몇 초 걸릴 수 있다. 저장하지 않고 열 때마다 계산한다.
