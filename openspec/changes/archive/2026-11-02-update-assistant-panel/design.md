# Design

## 결정

- **원인은 백엔드, "0건"은 화면.** `note`는 대체 검색일 때 원인 한 마디만 담는다(`NO_AI`·`AI_CONFIG`·`AI_FAILED`). 맞는 줄이 없는지는 화면이 `evidence`·`sentences` 길이로 안다. 그래서 API 응답 칸을 바꾸지 않고(`gen:api` 불필요) 안내 두 개가 겹치지 않는다.
- **설정 오류만 따로.** `LLMConfigError`(400·401·403·404)는 다시 물어도 같으므로 "AI 키·모델 설정 오류 — 설정 확인". `LLMFormatError`와 재시도 끝 실패는 사용자가 할 일이 같아(잠시 뒤 다시) "AI가 답하지 못함" 하나로 묶는다.
- **상태 줄은 중립색.** 대체 검색은 사용자 잘못이 아니므로 주황·빨강을 쓰지 않는다. 설정 오류도 문구에 "설정 확인"이 있어 색으로 따로 나누지 않는다.
- **근거 번호.** AI 답에서 근거는 처음 인용한 순서로 오므로 `evidence` 순번(1부터)을 각주 번호로 쓴다. 클릭하면 그 카드로 스크롤(지금과 같음). 카드 `id`는 계속 내부 번호(`as-R12`)로 둔다.
- **영어 낱말 안내.** 질문에 한글이 있고 0건일 때만 보인다. 문서 언어를 판정하지 않는다(CR-01과 무관한 화면 안내).
- **예시 칩.** 세 낱말은 합성 154 kV GIS 문서와 실제 입찰 문서에 흔한 표현이고, 대체 검색에서도 `ILIKE`로 걸린다.

## 대안

- 응답에 `reason` 칸을 더해 원인 코드를 따로 준다: 화면 색을 원인별로 나눌 수 있지만 스키마·생성 타입·계약 검사를 함께 바꿔야 해서 이번에는 문구로만.
- 예시 칩을 AI 상태에 따라 바꾼다: 상태를 묻는 호출이 하나 더 필요해서 버림.

## 위험

- e2e는 AI 키 없이 돌아 "검색어로 찾은 결과"만 확인한다. AI 답 화면은 가짜 AI 백엔드 테스트와 사람 확인으로 본다.
