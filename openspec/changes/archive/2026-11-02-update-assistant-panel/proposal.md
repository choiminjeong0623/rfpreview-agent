# Proposal

## Why

11-02 검토 도우미 화면을 확인하다가 두 가지 문제가 나왔다.

1. **안내가 원인을 가린다.** AI 키가 있는데도 "AI 응답을 받지 못해 질문 글자로만 찾았습니다."만 보였다. 코드(`pipeline/assistant.py`)가 키·모델 설정 오류(`LLMConfigError`)와 형식 오류, 연결 실패를 모두 같은 문장으로 덮어, 화면만 보고는 설정을 고쳐야 하는지 다시 물으면 되는지 알 수 없다. CR-12는 키·모델 설정 오류를 따로 알리라고 정한다.
2. **창이 만든 티가 난다.** 같은 상태를 노란 표시와 주황 문장으로 두 번 말하고, 부제가 설계 원칙("읽기만 합니다 · 답마다 원문 위치")을 그대로 옮기고, 입력창에 있는 질문을 따옴표 제목으로 한 번 더 보이고, 근거 카드 맨 앞에 내부 번호(R87158)를 파란 글씨로 두고, 찾은 경로를 디버그 기록처럼 번호·화살표로 보인다. "글자로 찾음", "글자가 맞는 줄이 없습니다"처럼 서비스에서 쓰지 않는 말도 있다. 예시 칩 셋 중 둘은 AI가 없을 때 반드시 0건이 되는 한국어 문장이고, 0건이면 다음에 무엇을 할지 안내가 없다.

관련: FR-17, CR-12, `review-assistant` "AI 없이 글자로 찾기", `review-workspace` "검토 도우미 창".

## What Changes

- 백엔드: AI 답이 없을 때 안내를 원인별로 나눈다. AI를 쓰지 않는 설정(키 없음·`off`) / AI 키·모델 설정 오류 — 설정 확인 / AI가 답하지 못함(연결·시간 초과·형식 오류). 안내는 맞는 줄이 있든 없든 원인만 담고, "맞는 줄 없음"은 화면이 정한다. API 모양은 그대로.
- 화면(검토 도우미 창):
  - 부제를 없애고, 빈 화면 안내를 사용자 말로 바꾼다.
  - 질문 반복 제목을 없앤다.
  - 상태는 한 줄, 중립색: "AI 답변 (근거와 대조함)" 또는 "검색어로 찾은 결과 (원인)". 뺀 문장 수는 같은 줄에.
  - 맞는 조항이 없으면 "일치하는 조항이 없습니다."를 보이고, 한국어로 물었으면 영어 낱말로 찾아 보라고 덧붙인다.
  - 근거 카드: 머리에 번호와 원문 위치, 그 아래 유형·판정 꼬리표와 원문. 내부 번호는 번호에 마우스를 올리면 보인다. 답 문장의 근거 표시는 [1] [2] 번호.
  - "근거 n줄" → "근거 조항 n건".
  - 찾은 경로는 접어 두는 "찾은 방법 보기"로, 줄마다 "요구사항에서 'ambient temperature' 찾기 — 2건" 문장.
  - 예시 칩은 AI가 있든 없든 결과가 나오는 영어 낱말(ambient temperature, type test, witness)로 바꾸고 한 줄로 둔다. 한국어 예시는 입력창 안내 글에 둔다.

## Non-Goals

- 의미(벡터) 검색 도구 추가. 도우미 도구는 지금처럼 글자 찾기 세 가지.
- 원문 위치 표기(`locName`)를 바꾸는 일. 다른 화면과 함께 쓰는 부품이다.
- docker compose 환경변수 전달(`RFP_AI_MODE`·`GEMINI_MODEL` 등) 정리. 따로 다룬다.
