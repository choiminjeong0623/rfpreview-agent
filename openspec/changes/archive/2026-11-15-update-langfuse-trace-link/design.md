## Context

add-langfuse-trace-push를 실제 Langfuse(v3 self-host, docker 백엔드)로 돌려 본 결과에서 나온 수정이다. 데이터셋 업로드·키·연결은 정상이었다.

## Decisions

- **링크는 가장 최근에 AI를 부른 실행의 trace.** trace id는 `run-<run_id>-<run_token>`이고 호출은 그 호출을 낸 작업의 토큰에 붙는다. 링크는 지금 작업 토큰을 먼저, 없으면 토큰이 있는 호출 가운데 가장 늦게 시작한 것의 토큰으로 만든다. 토큰 있는 호출이 없으면(분석 밖 호출만) 빈 토큰 trace. 보내는 내용(검토의 모든 호출)은 그대로라 Langfuse에는 실행마다 trace가 하나씩 있다.
  - 버린 대안: 다시 처리한 작업은 링크를 비움 — 사용자가 링크를 잃는다. 검토 하나 = trace 하나로 합침 — 이미 보낸 trace id가 바뀌어 중복된다.
- **화면 주소는 따로(`RFP_LANGFUSE_UI_URL`).** 서버가 닿는 주소(docker 안 `host.docker.internal`)와 사람이 여는 주소(`localhost`)가 다르다. 비면 `LANGFUSE_HOST`라 지금 설정은 그대로 동작한다. 이미 저장된 링크는 바꾸지 않는다(다음 보내기 때 새 주소).
- **보내기 시간 제한 분리(`RFP_LANGFUSE_SEND_TIMEOUT_S`, 30초).** 프롬프트 가져오기는 분석 시작을 막으니 짧게(5초) 두고, 보내기는 작업이 끝난 뒤·명령 끝이라 사람이 기다리지 않아 길게 둔다. 실제 확인에서 느린 Langfuse가 13건을 받는 데 45초 걸렸다.

## Risks

- 30초 동안 Langfuse가 답하지 않으면 처리기 하나가 작업 끝에서 그만큼 붙잡힌다. 살아 있음 판단(30초 간격, 3분)보다 짧아 작업을 다시 넣지는 않는다.
- 점수를 목록 한 번으로 보내는 요청이 실제 Langfuse에서 받아지는지는 서버가 느려 확인하지 못했다. [확인 필요]
