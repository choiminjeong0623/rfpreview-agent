# Design

## 1. 저장

`judgment`에 `query_sent_at`, `query_sent_by`(0031). 되돌리면 둘 다 NULL. 판정 결과(`result`)·확인 상태(`review_status`)는 바꾸지 않는다. 그래서 보증값·목록·제안 포인트·협조 요청을 다시 만들지 않는다(`review.act`가 이 동작만 일찍 끝낸다).

## 2. 검사

- 질의 후보(`QUERY_CANDIDATE`)가 아니면 409, 반려한 판정 409, 이미 보냄인데 다시 보냄 409, 보내지 않았는데 되돌리기 409.
- 엔지니어가 아니면 403(다른 동작은 역할을 보지 않지만 이 표시는 엔지니어가 고객과 주고받은 일을 적는 것이라 막는다).
- 단계: `act`와 같이 담당자 확인만.

## 3. 이어받기

`doc_add.carry_judgments`가 같은 줄 짝마다 상태를 옮긴 뒤, 이전 줄에 표시가 있고 옮긴 뒤 새 줄이 질의 후보이면 표시를 옮긴다. 수정으로 옮긴 판정 값이 먼저 들어간 뒤 보므로, 사람이 질의 후보로 고친 줄도 이어진다.

## 4. 화면

날짜는 `MM-DD`(올해가 아니면 연도 포함, `dueText`). 잠김 이유는 판정 상세의 다른 단추와 같은 문장("승인 대기 중에는 고칠 수 없습니다", "기술 검토 엔지니어만 고칠 수 있습니다").
