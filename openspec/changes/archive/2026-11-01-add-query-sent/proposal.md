# Proposal

## Why

질의 후보 판정은 엔지니어가 고객에게 질의서(Clarification)로 묻는다. 지금은 보냈는지 화면에 남지 않아, 판정 수백 줄 가운데 어떤 질의를 이미 보냈는지 엑셀이나 기억으로 따로 챙겨야 한다.
결정 Q4(`docs/screens/_v4.96_결정.md`): "질의 보냄" 상태를 저장한다. 엔지니어가 표시하면 날짜가 남고, 되돌릴 수 있다. 고객 회신 내용은 저장하지 않는다.
프런트 4단계 8번. minjeong 11-01 16:13 "승인받지 않고 클로드의 제안대로 앞으로 진행합니다".

## What Changes

- `POST /runs/{id}/actions` 판정 동작 `QUERY_SENT`·`QUERY_UNSENT`: 질의 후보이고 반려하지 않은 현재 판정에만, 검토 엔지니어만, 담당자 확인 단계에서. 이력에 남는다.
- 판정 응답 `query_sent_at`·`query_sent_by_name`. 문서를 더해 다시 분석해도 같은 줄(이어받기 열쇠)이 질의 후보면 표시가 옮겨진다.
- 화면: 판정 상세 질의 칸("질의 초안"/"질의 보냄 · MM-DD", [질의 보냄 표시]/[되돌리기]), 판정 표 질의 꼬리표.
- 마이그레이션 0031 (`judgment.query_sent_at`·`query_sent_by`, 이력 동작 이름).

## Non-Goals

- 고객 회신 내용·회신 반영 띠(Q4).
- 질의서 줄(목록 항목) 단위 표시: 질의서 줄은 판정에서 다시 만들어지므로 판정에 둔다.
- 승인 뒤 표시: 다른 판정 고치기처럼 담당자 확인 단계에서만 한다.
