## Purpose

명세서 요구사항(FR)부터 OpenSpec 시나리오, 화면 수용 기준, 구현 컴포넌트, 자동 테스트까지를 한 표로 잇고, 그 표가 늘 지금 스펙·테스트와 같게 검사해 "스펙이 곧 검증 기준"이 되게 한다.

## ADDED Requirements

### Requirement: 추적표 생성
시스템은 명세서 FR 표, 연결 설정, OpenSpec 시나리오, 화면 명세 수용 기준, 백엔드·e2e 테스트에서 추적표를 코드로 만들어야 한다(SHALL). 표는 FR마다 capability·시나리오 수·테스트 있는 시나리오 수·화면·컴포넌트·테스트 파일을, 화면마다 수용 기준과 이어진 테스트를 보이고, 테스트 없는 시나리오·수용 기준을 따로 모은다. 같은 입력이면 같은 표다.

#### Scenario: 이름으로 테스트 잇기
- **WHEN** 시나리오 이름이 백엔드 테스트 docstring `Scenario:` 뒤 이름이나 e2e `test()` 이름과 같으면
- **THEN** 추적표에서 그 시나리오 옆에 테스트 파일과 줄이 보인다

#### Scenario: 테스트 없는 시나리오
- **WHEN** 어떤 테스트와도 이름이 같지 않은 시나리오가 있으면
- **THEN** 추적표 "검증 안 된 것"에 capability와 시나리오 이름이 나온다

#### Scenario: 같은 입력 같은 표
- **WHEN** 스펙·테스트를 바꾸지 않고 두 번 만들면
- **THEN** 두 표가 글자 하나까지 같다

### Requirement: 추적표 CI 대조
CI는 추적표가 지금 스펙·테스트로 다시 만든 것과 같은지 검사해야 한다(SHALL). 다르거나, 연결 설정의 컴포넌트 파일이 없거나, 설정에 없는 capability·화면 이름을 쓰거나, 이어진 시나리오·수용 기준이 하나도 없는 FR이 있으면 실패하고 이유를 보인다.

#### Scenario: 낡은 추적표
- **WHEN** 테스트 이름을 바꾸고 추적표를 다시 만들지 않으면
- **THEN** 검사가 실패하고 `npm run trace`로 다시 만들라고 안내한다

#### Scenario: 없는 컴포넌트 파일
- **WHEN** 연결 설정이 없는 파일을 컴포넌트로 적으면
- **THEN** 검사가 그 파일 이름과 함께 실패한다

### Requirement: 핵심 흐름 e2e
e2e는 RFP 한 건을 화면으로 처음부터 끝까지 도는 테스트를 가져야 한다(SHALL): 검토 등록 화면에서 올리기, 분석 끝남, 판정 확정, 결재 상신, 승인, 인계 패키지 내려받기. 각 단계 끝 화면 상태를 확인한다.

#### Scenario: RFP 한 건 처음부터 끝까지
- **WHEN** 엔지니어가 등록 화면에서 합성 데이터시트를 올리고 판정을 확정해 상신한 뒤 승인자가 승인하면
- **THEN** 제출본 탭에서 인계 패키지(zip)를 내려받을 수 있다

### Requirement: 목업 배치 점검
목업 대조 도구는 기준 목업의 화면마다 앱 화면을 같은 너비로 나란히 찍고, 정해 둔 영역 이름의 있음과 위→아래 순서를 목업과 비교한 결과를 남겨야 한다(SHALL). 값·글자는 비교하지 않는다.

#### Scenario: 배치 같음
- **WHEN** 앱 화면에 목업의 영역이 모두 있고 순서가 같으면
- **THEN** 결과에 그 화면이 "배치 같음"으로 나온다

#### Scenario: 영역이 빠짐
- **WHEN** 목업에 있는 영역이 앱에 없으면
- **THEN** 결과에 빠진 영역 이름이 나온다
