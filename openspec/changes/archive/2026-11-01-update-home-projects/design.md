# Design

## 1. 내 차례인 검토 (홈)

| 사용자 | 내 차례 |
|---|---|
| 엔지니어 | 내가 담당인 검토 중 담당자 확인·반려·처리 실패 + 내가 결재자인 결재 대기 |
| 승인자 | 내가 결재자인 결재 대기 (결재자가 비어 있으면 모든 결재 대기) |
| 견적·품질·영업 | 없음. 대신 "내 부서 협조 요청 n건"(회신 받지 않은 요청) 한 줄 |

"내가 처리할 건" 칸 수와 오늘 할 일 전체 수는 같은 목록에서 센다(9번 요약 상자의 수와도 같아야 한다).

## 2. 오늘 할 일 순서와 이유

- 순서: 상신 권장일(제출 마감 2일 전, `submitBy`) → 없으면 제출 마감 → 둘 다 없으면 뒤. 같으면 검토 번호.
- 이유: 담당자 확인·반려 = "상신 권장 MM-DD (D-n) · 확인 필요 n줄 · 일탈 후보 n"(반려는 앞에 "반려됨"). 확인 필요 줄 수는 보이는 3건만 `judgment-counts`로 부른다. 처리 실패 = "<단계>에서 멈춤 · 마감 D-n"(빨강). 결재 대기 = "결재 대기 n일째 · 마감 D-n".
- 단추: 판정 확인(검토 상세), 다시 시도(엔지니어만, `POST /runs/{id}/retry`), 결재 보기(검토 상세).

## 3. 일정 달력

- 7일 칸(오늘부터, 이전·다음은 7일씩, "오늘"은 처음으로). 목업처럼 08~17시 눈금을 두지만 마감에 시각이 없으므로 칸 안 항목은 "상신 권장"(09시) → "제출 마감"(17시) 순서로 놓고, 같은 자리에 둘 이상이면 한 시간씩 아래로 민다. 놓을 자리가 없으면 마지막 칸에 "+n".
- 상신 권장은 담당자 확인·반려 검토에만 놓는다(목업과 같음). 승인된 검토는 놓지 않는다.
- 항목 색: 내 차례(`me`), 다른 사람 차례(`ot`), 시스템 처리 중(`sy`), 분석 실패(`fl`). 목업 `tc-e` 클래스 그대로.

## 4. 어제 이후 바뀐 것

- 기준 시각 = 어제 0시(브라우저 시각). `finished_at`이 그 뒤인 내 검토(보드에 보이는 검토). 실패는 "분석 실패", 그 밖은 "분석 끝남".
- 줄: 아이콘·"<번호> <이름> · 분석이 끝났습니다"·"요구사항 n줄 · 일탈 후보 n · 시각"·[가기](실패면 분석 실패 상세, 아니면 검토 상세).
- 0건이면 접힌 채 "어제 이후 바뀐 것 없음". 문서 추가는 7번 `add-revision-notice`에서 더한다.

## 5. 사업 현황 요약 칸

- 진행 중 사업 설명: "설비 범위 n개 · 내 담당 m개"(진행 중 사업의 범위 수, 그중 담당 엔지니어가 고른 사용자인 범위).
- 3일 내: 마감 가까운 두 사업 "<이름> D-n", 더 있으면 " 외 k". 마감 지남: "없음" 또는 첫 사업 이름(+ 외 k).
- 누르면 서버 요약과 같은 조건(제출 안 한 사업, 0 ≤ 남은 날 ≤ 3 / 남은 날 < 0 / 제출 안 함)으로 표를 거른다. 다른 찾기 조건과 함께 적용한다. 다시 누르거나 "모두 보기"면 풀린다.

## 6. 인계 패키지 창 (사업 상세)

제출본 탭의 내려받기·영업에 넘기기·마지막 넘긴 기록을 `components/PackageActions.tsx`로 떼어 두 곳이 같이 쓴다. 창은 공통 `Modal`. 승인된 검토(`ranges[].stage = APPROVED`)가 없으면 단추를 잠그고 이유 "결재가 승인된 검토가 없습니다".

## 위험

- 홈 화면이 길어진다: 일정 보기를 처음 보기로 두고 단계별·사업별은 고를 때만 그린다.
- 브라우저 시각 기준 "어제 0시": 시간대가 다르면 경계가 어긋날 수 있다. 화면 표시용이라 받아들인다.
