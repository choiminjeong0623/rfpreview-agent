# Proposal

## Why

검토가 끝나면 엔지니어는 결과를 영업에 넘겨야 한다. 영업은 데이터시트를 고객 양식에 넣고, 일탈 목록·질의서·TBE 준수표로 입찰서를 낸다.
지금은 파일을 하나씩 내려받아 손으로 메일에 붙인다. 데이터시트 화면의 "영업에 넘기기"(목업 v4.57)는 잠겨 있다(SCR-10_공유 3번).
협조 요청 메일(`update-role-handoff-mail`)이 들어와 부서 주소로 메일을 보낼 수 있게 되었다.
그래서 계획 문서(10-31) 3장의 "인계 패키지"를 할 수 있다. minjeong은 10-31 15:53에 "네 진행합니다"로 승인했다.

관련: FR-11(영업 인계 확장, 명세서 10-31 추가), `role-assignment`, `review-workspace`, CR-02, CR-04, CR-08, CR-12.

## What Changes

- **데이터시트 영업에 넘기기**: 엔지니어가 데이터시트 화면에서 누르면 그 표의 엑셀을 영업 주소로 한 통 보낸다. 본문에는 칸 수와 확인 필요 칸 수를 적는다.
  - 후보 칸이 남아 있으면 넘기지 않는다(CR-08). 사람이 보지 않은 값이 다른 부서로 나가지 않게 하기 위해서다.
  - 확인 필요 칸은 비운 채로 넘긴다(CR-04).
- **인계 패키지**: 결재가 승인된 검토의 제출본 탭에서 zip 한 개를 내려받거나 영업 주소로 보낸다.
  - 담는 것: 일탈 목록 초안, 질의서 초안(Word), TBE 준수표(제출본 v1 기준), 데이터시트 전부(엑셀).
  - 없는 목록은 빼고, 무엇을 뺐는지 본문과 목록 파일에 적는다.
- **넘긴 기록**: 영업에 넘긴 기록(종류, 표, 받는 주소, 파일 이름, 시각, 보낸 사람, 오류)을 남긴다.
  - 이력 탭에도 남긴다(SEND).
  - 다시 넘기면 새 기록을 남긴다.
  - 주소가 없으면 보내지 않고 "주소 없음"을 남긴다. 발송 실패는 정해진 횟수만 다시 시도한다(CR-12).
- **화면**:
  - 데이터시트 화면의 "영업에 넘기기" 잠금을 푼다. 넘긴 뒤에는 단추가 "다시 넘기기"로 바뀌고 넘긴 시각을 보인다.
  - 제출본 탭에 "인계 패키지 내려받기"와 "영업에 넘기기"를 둔다. 첨부 칸에 실제 파일 수를 보인다.
- 마이그레이션 0020: `sales_handoff` 표.

## Non-Goals

- 영업이 받은 뒤의 화면이나 회신 기록. 회신은 협조 요청과 달리 받지 않는다.
- 고객에게 직접 보내기, 오퍼시트·가격 정보.
- 비용 조건 요약 내보내기. 비용 조건은 견적 협조 요청으로 이미 간다.
