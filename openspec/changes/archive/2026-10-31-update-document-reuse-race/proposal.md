# Proposal

## Why

같은 docx를 두 검토가 거의 동시에 올리면 둘 다 "아직 처리한 문서 없음"을 보고 처리를 시작하고, 늦게 저장하는 쪽이
문서 중복 키(`ux_document_version`) 오류로 "문서 읽기"에서 멈춘다. 자동 재시도도 같은 오류로 실패하고, 홈 알림에 DB 오류 원문이 보인다.
2026-10-31 나송주 구역 주말 검토 중 로컬 e2e(작업자 2개)에서 RV-2026-054로 재현됐다. 실제로는 같은 RFP를 두 사람이 거의 동시에 올릴 때 생긴다.

관련: NFR-05, CR-11, `review-run` "긴 문서는 절 단위로 처리", change `update-document-reuse`(내용이 같은 파일만 재사용).

## What Changes

- 문서 저장이 중복 키로 겹치면 늦은 쪽은 자기 처리를 되돌리고, 먼저 저장된 같은 처리 판·같은 내용의 문서를 다시 쓴다.
- 분석은 멈추지 않고 이어서 판정까지 간다.

## Non-Goals

- 처리 시작 전 잠금으로 두 번째 처리를 아예 막기(AI 호출이 두 번 나갈 수 있지만 드문 경우).
- 홈 실패 알림 문구 바꾸기(박경빈 구역, 개발 기록에 남김).
