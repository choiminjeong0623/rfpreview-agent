# 흐름 안의 멈춤 지점과 이어서 다시 시도 (C조 C2)

## 왜

- 기획서는 "LangGraph, 멈춤 지점 2곳(담당자 확인, 승인)"이라고 적었지만, 지금 흐름은 문서 읽기부터 뜻 찾기까지 일직선으로 돌고 끝난다. 두 멈춤 지점은 `review_run.stage` 칸 값일 뿐이고 흐름(그래프)과 이어져 있지 않다(AI 기술 활용성 자체 평가 "흐름 = 보통").
- 처리 중 실패하거나 취소한 검토를 "다시 시도"하면 처음부터 다시 돈다. 문서는 다시 쓰지만(NFR-05) 위험 조건 설명·검증 같은 AI 호출은 다시 한다. 실제 RFP("Bidding Forms")는 한 번에 약 15분이 걸려, 끝 단계에서 멈추면 그만큼 다시 기다린다.

## 무엇

- 흐름 상태를 단계마다 PostgreSQL에 저장한다(LangGraph checkpoint, 검토 하나 = 흐름 하나).
- 흐름 끝에 사람 단계 노드 세 개를 더한다. 노드는 흐름 안에서 실제로 멈추고(interrupt), 사람이 동작하면 그 자리에서 이어 간다.
  - **담당자 확인**: 결재 상신 → 승인 대기로, 문서 추가 → 문서 처리부터 다시.
  - **승인 대기**: 승인 → 끝, 반려 → 반려됨, 상신 취소 → 담당자 확인.
  - **반려됨**: 다시 확인 → 담당자 확인.
- 다음 갈 곳은 사람 동작 이름으로 코드가 고른다(CR-01). 권한·단계 검사·기록은 지금 함수 그대로 쓴다.
- **이어서 다시 시도**: 실패·취소한 검토를 다시 시도하면 저장된 흐름에서 멈춘 단계부터 이어 간다. 끝난 단계는 건너뛰고, 실행 기록에 "이어서 시작한 단계"를 남긴다.
- 흐름 기록이 없는 예전 검토(이 change 전에 만든 검토)는 지금처럼 단계 칸만 바꾸고, 다시 시도는 처음부터 한다.

## 하지 않음

- 화면 바꾸기. API 경로·응답은 그대로다. 실행 기록 응답에 칸 하나(`resumed_from`)만 더하고, 화면 표시는 목업 v4.96 적용 뒤에 한다.
- 다른 판정 다시 하기(비교 제품 바꾸기)를 흐름 안으로 옮기기. 지금처럼 흐름 밖에서 그 묶음만 다시 판정한다.
- 작업 대기열(Redis 등)이나 여러 서버에서 이어 돌리기.
- C1 문서 종류별 처리기(다음 change).
