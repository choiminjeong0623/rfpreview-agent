## MODIFIED Requirements

### Requirement: 검토 다시 시도
시스템은 처리 실패한 검토(취소 포함)에 사람의 다시 시도 요청을 받아, 처음 시작할 때와 같은 파일과 같은 사람 분류로 같은 검토를 다시 처리해야 한다(SHALL). 저장된 흐름이 있으면 끝난 단계는 건너뛰고 멈춘 단계부터 이어서 처리하고, 없으면 처음부터 처리하되 이미 처리한 문서는 다시 쓴다(NFR-05). 다시 시도하면 처리 중으로 바뀌고 멈춘 단계·오류 문장·취소 표시를 지우며 다시 시도 횟수를 하나 늘린다. 처리 실패가 아니거나 다시 돌릴 파일 정보가 없으면 거절한다. [제안] [이어서 처리: 제안 11-01, C2]

#### Scenario: 취소한 검토 다시 시도
- **WHEN** 문서 읽기에서 취소한 검토를 다시 시도하면
- **THEN** 같은 검토 번호로 담당자 확인 단계까지 가고 판정이 나오며 다시 시도 횟수는 1이다

#### Scenario: 처리한 문서는 다시 씀
- **WHEN** 문서 두 개 가운데 첫 문서를 처리한 뒤 실패한 검토를 다시 시도하면
- **THEN** 첫 문서는 같은 문서로 다시 쓰이고 새 문서 줄은 두 번째 문서 하나만 생긴다

#### Scenario: 다시 돌릴 파일 정보 없음
- **WHEN** 파일 정보가 저장되지 않은 처리 실패 검토를 다시 시도하면
- **THEN** 409 오류와 다시 등록하라는 안내가 돌아오고 검토는 그대로다

#### Scenario: 멈춘 단계부터 이어서
- **WHEN** 위험 조건 단계까지 끝내고 판정 단계에서 실패한 검토를 다시 시도하면
- **THEN** 문서·짝·위험 조건 단계는 다시 돌지 않고(위험 설명 AI 호출 없음) 판정 단계부터 이어서 담당자 확인까지 가며, 실행 기록에 이어서 시작한 단계가 판정으로 남는다

#### Scenario: 이어서 해도 결과가 같음
- **WHEN** 같은 파일을 처음부터 끝까지 돌린 검토와 중간에 실패한 뒤 이어서 다시 시도한 검토를 비교하면
- **THEN** 판정·위험 조건·일탈 후보 수가 같다

## ADDED Requirements

### Requirement: 실행 기록의 이어서 시작한 단계
시스템은 실행 기록 응답에 이어서 다시 시도한 검토의 이어서 시작한 단계 이름을 돌려주고, 처음부터 돌린 검토는 비워 두어야 한다(SHALL). [제안 11-01, C2]

#### Scenario: 처음부터 돈 검토
- **WHEN** 한 번에 끝난 검토의 실행 기록을 부르면
- **THEN** 이어서 시작한 단계가 비어 있다
