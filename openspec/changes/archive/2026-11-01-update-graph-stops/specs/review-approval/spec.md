## ADDED Requirements

### Requirement: 흐름 안의 멈춤 지점
시스템은 처리를 마친 검토의 흐름을 담당자 확인 자리에서 실제로 멈추고 그 자리를 DB에 저장해야 한다(SHALL). 결재 상신·승인·반려·상신 취소·다시 확인은 저장된 자리에서 흐름을 이어 가고, 다음 자리(승인 대기, 담당자 확인, 반려됨, 끝)는 사람 동작에 따라 코드가 고른다(CR-01). 서버를 다시 켜도 멈춘 자리는 남는다. [제안 11-01, C2]

#### Scenario: 처리를 마치면 담당자 확인에서 멈춤
- **WHEN** 검토 처리가 끝나면
- **THEN** 단계는 담당자 확인이고 저장된 흐름도 담당자 확인 자리에서 멈춰 있다

#### Scenario: 상신하면 승인 대기 자리로
- **WHEN** 담당자 확인에서 멈춘 검토를 결재 상신하면
- **THEN** 단계는 승인 대기이고 흐름은 승인 대기 자리에서 멈춘다

#### Scenario: 반려 뒤 다시 확인
- **WHEN** 승인 대기 검토를 반려하고 엔지니어가 다시 확인을 누르면
- **THEN** 흐름은 반려됨 자리를 거쳐 담당자 확인 자리로 돌아오고 단계도 담당자 확인이다

#### Scenario: 상신 취소
- **WHEN** 승인 대기 검토의 상신을 취소하면
- **THEN** 흐름은 담당자 확인 자리로 돌아온다

#### Scenario: 승인하면 흐름이 끝남
- **WHEN** 승인 대기 검토를 지정 결재자가 승인하면
- **THEN** 단계는 승인됨이고 흐름은 끝나 더 이어 갈 자리가 없다

#### Scenario: 서버를 다시 켜도 이어 감
- **WHEN** 담당자 확인에서 멈춘 검토가 있는 채로 흐름 실행기를 새로 만들고 결재 상신하면
- **THEN** 같은 흐름이 승인 대기 자리로 이어진다

#### Scenario: 거절된 동작은 자리를 바꾸지 않음
- **WHEN** 상신 의견 없이 결재 상신하면
- **THEN** 400 오류가 나고 흐름은 담당자 확인 자리에 그대로 있다

#### Scenario: 흐름 기록이 없는 예전 검토
- **WHEN** 저장된 흐름이 없는 담당자 확인 검토를 결재 상신하면
- **THEN** 지금처럼 승인 대기가 되고 오류가 나지 않는다

#### Scenario: 자리와 단계가 다름
- **WHEN** 흐름은 담당자 확인 자리인데 단계 칸이 승인 대기로 바뀐 검토에 승인을 요청하면
- **THEN** 409 오류로 거절하고 아무것도 바꾸지 않는다

### Requirement: 문서 추가는 흐름을 처음 단계로 되돌림
시스템은 담당자 확인 자리에서 엔지니어가 문서를 더하면 저장된 흐름을 문서 처리 단계부터 다시 돌려 담당자 확인 자리에서 다시 멈춰야 한다(SHALL). 같은 줄의 확정·수정·반려 이어받기는 지금과 같다. [제안 11-01, C2]

#### Scenario: 문서 추가 뒤 다시 멈춤
- **WHEN** 담당자 확인에서 멈춘 검토에 docx 하나를 더하면
- **THEN** 흐름이 문서 처리부터 다시 돌아 담당자 확인 자리에서 멈추고 확정한 판정은 이어받는다
