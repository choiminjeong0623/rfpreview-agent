# Design

## 결정

- **틀은 코드에 둔다.** `tasks.TEMPLATES[역할]`은 지금 프롬프트 글에서 코드가 채우는 부분(문서 본문, 문서 종류 설명, 도우미 도구 목록 등)을 `{{이름}}`으로 바꾼 것이다. 채우기는 한 번에(채운 글 안의 `{{…}}`는 다시 채우지 않음). 리팩터링 전후 프롬프트 해시가 같아 판을 올리지 않았다.
- **Langfuse 판은 검사를 통과해야 쓴다.** 판 설정 `config.code_version`이 지금 코드 판과 같고, 자리표시자 묶음이 코드 틀과 같고, `DATA_RULE`이 들어 있어야 한다. 하나라도 어긋나면 그 역할만 코드 판(이유를 남김). 코드가 채우는 자리가 바뀌면 코드 판을 올리므로 예전 Langfuse 판은 저절로 쓰이지 않는다.
- **판 이름은 `코드판+lf버전`.** 재사용 열쇠(문서 분류·구분·유형)에 그대로 들어가 Langfuse 판이 바뀌면 같은 파일도 새로 처리한다(CR-11). 해시 테스트(판 올리기 확인)는 코드 틀에 그대로 적용된다.
- **한 실행 = 판 묶음 하나.** `execute_run`이 시작할 때 `prompt_source.resolve()`로 고른 묶음을 contextvar로 두고(`use`), 동시 호출 스레드는 이미 문맥을 이어받는다(`parallel.run_ordered`). 평가 명령도 같은 방식. 검토 도우미·협조 질문처럼 실행 밖 호출은 60초 캐시(`RFP_LANGFUSE_CACHE_S`)를 쓴다.
- **닿지 못하면 한 번만 묻는다.** 연결 오류가 나면 나머지 역할은 묻지 않고 모두 코드 판(요청 시간 제한 `RFP_LANGFUSE_TIMEOUT_S` 5초). 실패 결과도 캐시해 매 요청마다 기다리지 않는다.
- **운영 승격은 평가 명령에서 코드가 정한다(CR-01).** `--promote`는 표시가 production이 아니고, 끝난 평가이고, 반복 3번 이상, 같은 평가셋 판의 기준선이 있고, 회귀가 없을 때만 Langfuse 판에 production을 붙인다. 되돌리기는 Langfuse 화면에서 표시를 예전 버전으로 옮긴다.
- **호출 기록은 이미 있는 OTLP JSON을 그대로 보낸다.** 원문은 없고 해시만(NFR-06·07). Langfuse 판으로 부른 호출에는 `langfuse.observation.prompt.name`·`.version` 속성을 붙여 프롬프트와 잇는다. 보내기는 사람이 명령으로 한다.
- **SDK 없이 공개 API를 httpx로.** 쓰는 것은 프롬프트 v2 가져오기·만들기·표시 바꾸기와 OTLP 받기 4개뿐이라 의존성을 더하지 않았다(이미 있는 httpx). 테스트는 같은 API를 흉내 낸 가짜 서버(MockTransport).

## 버린 대안

- **Langfuse SDK(`langfuse`)**: 프롬프트 캐시·폴백을 주지만 OpenTelemetry 계측까지 끌어와 기존 호출 기록과 겹친다.
- **Langfuse 판을 쓸 때 판 이름을 Langfuse 버전만으로**: 코드 판과 짝이 끊겨 예전 실행을 해석하기 어렵다.
- **분석이 끝날 때마다 자동으로 호출 기록 보내기**: 운영자가 모르게 외부로 나가는 길이 생긴다. 명령으로만.

## 위험

- Langfuse 쪽에서 프롬프트 글을 크게 바꾸면 코드 검사(근거 대조·자리표시자·숫자)는 그대로지만 품질은 평가로만 막힌다. 그래서 운영 표시는 평가를 통과해야 옮기게 했다(Langfuse 화면에서 직접 옮기는 것은 막지 못한다 — 운영 규칙으로 둔다).
- 이 환경에서는 실제 Langfuse를 띄우지 못해 가짜 서버로만 시험했다. OTLP 속성 이름(`langfuse.observation.prompt.*`)은 연동할 때 Langfuse 화면에서 프롬프트와 이어지는지 확인한다. [확인 필요]
