# Proposal

## Why

목업 v4.57 검토 상세의 판정 탭에는 "n줄 선택 · 제안대로 확정"과 "준수 45줄 모두 확정"이 있다. 지금 API는 후보를 한 줄씩만 확정할 수 있고,
한 줄 확정할 때마다 일탈 목록·제안 포인트를 다시 만든다(언어 모델 호출 포함). 화면이 45번 부르면 느리고 비용이 든다.
로드맵 7번(작은 수정), 갭 목록 "준수 45줄 모두 확정".

관련: FR-10(확인·승인·이력), CR-08(확정은 사람).

## What Changes

- 여러 판정을 한 번에 "제안대로 확정"하는 동작. 줄마다 이력을 남기고, 목록·보증값·제안 포인트는 한 번만 다시 만든다. 하나라도 확정할 수 없으면 아무것도 바꾸지 않는다.
- 판정 탭: 줄 고르기 칸, "n줄 선택 · 제안대로 확정", "아직 확정하지 않은 판정 n줄 · 준수 n줄 모두 확정" 띠.

## Non-Goals

- 판정을 바꾸는(수정·반려) 한꺼번에 동작. 사유가 줄마다 달라야 하므로 한 줄씩 한다.
- 위험 조건·목록·보증값의 한꺼번에 확정.
- 보증값 후보 응답에 고객 요구값 더하기(로드맵 7번의 다른 절반). 보증값 후보는 요구값 칸이 빈 행에서만 나온다(개발 DB 662줄 모두 빈칸).
  목업 데이터시트의 "고객 요구" 칸은 판정 줄의 요구값이므로, 데이터시트 화면(로드맵 5번 `add-datasheet-export`)에서 판정과 합쳐 보인다.

## Capabilities

### New Capabilities
없음.

### Modified Capabilities
- `review-approval`: 여러 판정 한꺼번에 확정.
- `review-workspace`: 판정 탭의 한꺼번에 확정 띠.

## Impact

- `backend/src/rfp_agent/pipeline/review.py`(한꺼번에 확정), `api/runs.py`(`POST /runs/{id}/actions/bulk`).
- `frontend/src/api.ts`, `views/detail/JudgeTab.tsx`.
- DB 스키마 바뀜 없음.
