# Proposal

## Why

검토 상세와 홈에는 숫자가 칸마다 흩어져 있어, 처음 연 사람이 "지금 무엇부터 해야 하는지"를 칸을 하나씩 읽고 스스로 모아야 한다. 목업 v4.96은 화면 맨 위에 2~4문장 "AI 요약" 상자를 둔다.
결정 Q1(`docs/screens/_v4.96_결정.md`): 검토 상세(SCR-08)와 홈(SCR-03) 두 곳만 먼저 만든다. 문장은 코드가 정해진 틀에 숫자·이름·날짜를 채워 쓴다(AI 없음, CR-01·07·11). 상자 이름은 "요약", 꼬리표 "코드가 씀".
프런트 4단계 9번(마지막). minjeong 11-01 16:13 "승인받지 않고 클로드의 제안대로 앞으로 진행합니다".

## What Changes

- `GET /runs/{id}/summary`: 검토 요약 문장. 단계(반려·승인), 꼭 볼 판정 수(일탈·질의·확인 필요)와 상신 권장일, 먼저 볼 일탈 후보 두 줄(판정 상세 링크), 마지막 개정, 데이터시트 빈 작성 칸에서 최대 4문장. 머리 한 줄(문서·요구사항·판정 수, 분석 시간).
- `GET /home/summary?user_id=`: 홈 요약 문장. 내 차례인 검토 수와 먼저 할 검토(홈 "내가 처리할 건"과 같은 규칙·같은 수), 분석이 멈춘 내 검토, 결재 중·협조 회신 대기인 내 검토. 견적·품질·영업은 회신하지 않은 자기 부서 협조 요청 수.
- 문장은 조각(글자·링크·강조) 목록으로 돌려주고, 같은 데이터면 같은 문장이다. 응답에 만든 시각과 `written_by: CODE`.
- 화면: 공통 요약 상자(`.ais`, "요약" + "코드가 씀", 요약 시각, [다시 요약], 실패하면 "요약을 만들지 못했습니다 · 다시 요약"). 검토 상세 제목 줄 아래(처리 중이면 숨김), 홈 나의 업무 아래.

## Non-Goals

- AI가 문장을 다듬는 것(다음 단계, Q1). 나머지 10개 화면의 요약 상자(Q1).
- 요약을 DB에 저장하거나 미리 만들어 두기: 부를 때마다 지금 데이터로 만든다.
- 마이그레이션 없음.
