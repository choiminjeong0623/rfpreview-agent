# Design

## 1. 문장은 코드 틀 (Q1, CR-01·07·11)

`pipeline/screen_summary.py`가 문장마다 틀을 고르고 숫자·이름·날짜를 채운다. 언어 모델은 부르지 않는다. 같은 데이터면 같은 문장이고, 응답의 `made_at`만 달라진다.
문장은 조각 목록 `[{t, kind: text|link|strong, href}]`이다. `href`는 화면 주소(`/reviews/12/judgments/34`)이고 화면이 `#`를 붙인다. 강조(`strong`)는 상신 권장일처럼 날짜를 빨갛게 보이는 곳에 쓴다(목업 `.rd`).
조사는 `numbers.josa`로 앞 글자 받침에 맞춘다(이름 뒤 은/는, 이/가).

## 2. 검토 요약 (SCR-08)

순서대로 최대 4문장:
1. 반려됨이면 "결재자가 반려했습니다…", 승인이면 "결재가 승인되었습니다…"(제출본 탭 링크).
2. 꼭 볼 것 = 일탈 + 질의 + 확인 필요(탭 수와 같은 `judgment_counts`, 반려한 판정 제외). 0이면 "꼭 볼 판정이 없습니다". 마감이 있으면 상신 권장일(마감 2일 전, 화면과 같음).
3. 먼저 볼 일탈 후보: 반려하지 않은 현재 일탈 후보를 판정 번호 순으로 두 줄, 항목 이름(요구값) 링크, 더 있으면 "외 n건".
4. 개정이 있으면 바뀐·추가·사라진 줄 수와 "바뀐 줄 보기" 링크(`?rev=1`).
5. 데이터시트 빈 작성 칸이 있으면 수와 "데이터시트 채우기" 링크.
처리 중이면 "분석 중이라 아직 요약할 판정이 없습니다" 한 문장. 머리 한 줄은 "문서 n개에서 요구사항 m줄을 찾아 k줄 비교 · 분석 x분 y초".

## 3. 홈 요약 (SCR-03)

"내 차례" 규칙은 홈 화면(`components/myWork.ts` `myTurn`)과 같게 옮긴다: 엔지니어 = 내 검토 중 판정 확인·반려·실패 + 내가 결재자인 결재 대기, 승인자 = 내가 결재자인(결재자 없으면 모든) 결재 대기, 그 밖 = 없음. 사용자를 모르면 판정 확인·반려·실패. 대상 목록도 홈과 같은 최근 200건이다. 먼저 할 검토는 마감 빠른 순(없으면 뒤), 같으면 검토 번호 순.
견적·품질·영업은 내 차례 검토가 없으므로 회신하지 않은 자기 부서 협조 요청 수와 협조 요청 화면 링크를 쓴다.
대안: 화면이 이미 가진 목록으로 문장을 만들기 — 문장 틀이 백엔드 한곳에 모이지 않고, 다음 단계(AI 다듬기)에서 숫자 대조를 할 곳이 없어 택하지 않았다.

## 4. 화면

공통 부품 `components/SummaryBox.tsx`가 목업 `.ais` 모양(`mockup/SummaryV496.css`, 원본 규칙 그대로)을 쓴다. 아이콘은 AI 느낌의 `auto_awesome` 대신 `summarize`. [다시 요약]은 API를 다시 부르고, 부르는 동안 회색 줄 두 개(목업 `.ais-sk`)를 보인다. 실패하면 상자를 숨기지 않는다.
검토 상세는 판정을 고치면(tick) 다시 부른다.

## 5. 위험

- 홈 수와 요약 수가 어긋날 수 있다: 규칙을 두 곳(TS·Python)에 둔다. e2e에서 "내가 처리할 건" 칸 수와 요약 첫 문장의 수를 같이 본다.
