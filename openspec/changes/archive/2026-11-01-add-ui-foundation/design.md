# Design

## 결정

### 1. 토큰은 목업 CSS 값을 이름만 붙여 모은다

목업 v4.96 26개 화면 CSS에서 색 95가지 중 많이 쓰는 31가지, 둥글기 5가지, 간격 8단계, 글자 크기 7단계, 그림자 4가지를 `tokens.css`의 `:root` 변수로 둔다(값은 목업 그대로).
목업 CSS는 토큰으로 바꾸지 않는다. 목업이 새 판으로 오면 파일을 통째로 바꾸는 지금 방식(`_디자인.md` 1장)을 지키기 위해서다.
우리가 쓴 CSS(`shell/`, `views/`, `ui/`)는 토큰만 쓴다. `scripts/check-tokens.mjs`가 이 파일들의 `#RRGGBB`·`rgb(`를 찾으면 실패한다(토큰 파일과 목업 폴더는 뺀다).

대안: 목업 CSS까지 토큰으로 바꾸기 — 11,000줄을 고쳐야 하고 새 판이 오면 다시 해야 해서 버림.

### 2. 서버 데이터는 `useLoad`를 그대로 쓴다

TanStack Query를 들이면 캐시·다시 부르기·중복 요청 막기를 얻지만, 30개 화면이 이미 `useLoad`(늦게 온 응답 버리기, `reload`)와 `useRepeat`(처리 중 5초마다)를 쓰고, 화면끼리 캐시를 나눌 일이 적다.
의존성을 늘리지 않고 원칙 문서에 규칙만 적는다. 다시 볼 기준: 같은 데이터를 3개 이상 화면이 동시에 부르거나, 낙관적 갱신이 필요해질 때.

### 3. 부품은 목업 클래스를 그대로 쓰는 얇은 React 부품

부품은 새 모양을 만들지 않고 목업 클래스(`.st.c-red`, `.bp`, `.bo`, `.mdo`, `.ttl`, `.tw > .tbl`, `.pager`)를 붙인다. 목업에 없는 모양(순번 칸, 알림 쌓기)만 `ui/ui.css`에 토큰으로 더한다.

- 순번: 목업 v4.77은 CSS `tr::before`로 넣지만, 앱은 표 부품이 첫 칸(`th`/`td.sq`)을 그린다. 화면 읽기 도구가 칸으로 읽게 하기 위해서다.
- 알림 쌓기: 목업 v4.96 `.antstw`(오른쪽 위, 세로로 쌓음) 모양. 성공·안내는 4초 뒤 사라지고 오류는 닫기 전까지 남는다. 같은 문장이 이미 떠 있으면 하나만.
- 단추 잠김 이유: `disabledReason`을 주면 `disabled` + `title` + 화면 읽기용 `aria-describedby`.

### 4. 부품 견본 화면

`#/dev/ui`에 토큰 견본과 부품을 예시 데이터로 놓는다. 메뉴에는 넣지 않고 주소로만 연다. e2e가 이 화면으로 부품 동작을 확인한다.

## 위험

- 화면마다 부품으로 바꾸는 동안 옛 방식과 새 방식이 섞인다 → 원칙 문서에 "고치는 화면은 새 부품으로" 규칙을 둔다.
