# Proposal

## Why

목업 v4.96 화면을 하나씩 만들기 전에(프런트 4단계), 모든 화면이 함께 쓰는 바탕을 먼저 만든다(3단계, minjeong 11-01 13:21 "3단계를 진행합니다").
지금 화면 코드는 목업 CSS를 화면마다 그대로 쓰고, 같은 모양을 화면마다 따로 만든다. 알림(`.toast`)은 15개 파일에서 43번, Esc로 창 닫기는 9번, 상태 배지는 48번 따로 쓴다.
그래서 같은 동작이 화면마다 조금씩 다르고(알림이 겹쳐 하나만 보임, 잠긴 단추에 이유가 없는 곳), v4.96이 요구하는 표 순번·알림 쌓기를 화면마다 다시 만들어야 한다.

관련: 화면 명세 `docs/screens/SCR-00-앱틀.md` "v4.96 바뀐 점" 6·7장, `docs/screens/_공통규칙.md` 1장(화면 상태 4종), `docs/screens/_v4.96_결정.md` 4장 1번.

## What Changes

- 디자인 토큰: 목업 v4.96 CSS에서 자주 쓰는 색·둥글기·간격·글자 크기·그림자를 CSS 변수(`frontend/src/styles/tokens.css`)로 모은다. 우리가 쓴 CSS(목업 CSS 밖)는 색을 직접 쓰지 않고 토큰만 쓴다. 검사 스크립트가 `npm run lint`에서 막는다.
- 공통 부품(`frontend/src/ui/`): 상태 배지, 단추(잠김 이유), 창(Esc·바깥 누르기·처음 칸 초점), 화면 제목, 목록 표(순번·로딩·빈 목록·오류), 화면 상태(로딩·빈·오류), 알림 쌓기.
- 부품 견본 화면 `#/dev/ui`: 토큰과 부품을 예시 데이터로 보여 준다(메뉴에 없음). e2e와 목업 대조에 쓴다.
- 프런트 원칙 문서 `docs/screens/_프런트원칙.md`: 폴더 구조, 상태 관리, 이름 규칙, 오류 처리, 토큰·부품 규칙, 시험.

## Non-Goals

- 있는 화면을 새 부품으로 바꾸기. 4단계에서 화면마다(수직 슬라이스) 바꾼다.
- 목업 CSS(`frontend/src/mockup/*.css`) 고치기. 목업 새 판을 그대로 덮어쓸 수 있게 둔다.
- TanStack Query 같은 새 라이브러리. 서버 데이터는 지금처럼 `useLoad`로 다룬다(design.md).
- 머리글 분석 진행 표시(SCR-00 4장). 앱 틀 기능이라 4단계 첫 화면에서 만든다.
