# Design

## 결정

- **한 곳의 코드(CR-01).** 화면이 배수·R10·허용 오차를 따로 계산하면 분석 검산과 어긋날 수 있어, `pipeline/engineering.py`에 순수 함수 `peak_check(ik_ka, frequency_hz, peak_ka)`를 두고 분석(`check_group`)과 API가 같은 `FACTORS`·`matches`를 쓴다.
- **읽기 전용 API.** DB를 읽지도 쓰지도 않는 GET. 입력이 0 이하이거나 숫자가 아니면 422(Pydantic).
- **주파수.** 50·60만 배수가 있다. 그 밖이면 확인 필요(`NO_FACTOR`).
- **화면.** 판정 상세 "공학 검산" 줄 아래 상자. 원문 검산 값(`ik_ka`, `frequency_hz`, `peak_ka`)으로 채우고, 입력이 바뀌면 0.3초 뒤 묻는다. 결과 배지·계산식("50 kA × 2.5 = 125 kA")·같다고 보는 값 목록. [원문 값으로] 단추로 되돌림.
- **기록 없음.** 참고 계산이라 이력에 남기지 않는다(판정을 바꾸려면 판정 변경).

## 대안

- 화면에서 계산: 규칙 중복이라 버림.
- 브라우저 계산기 단추: 규칙(R10·허용)을 모르고 기록도 없어 버림.
