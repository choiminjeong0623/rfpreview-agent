# 유형 정답지 작성 기준 (Jev·Gemini 비교용, 파일 1)

## 순서

1. **작성자**가 `정답지_작성용.csv`를 구글 시트로 열고, 줄마다 `정답(작성자)` 칸에 유형 코드 하나를 적는다.
   모델 답은 일부러 뺐다. 모델 답을 보면 그쪽으로 기울기 때문이다.
2. 고르기 어려우면 가장 가까운 코드를 적고 `애매함` 칸에 Y, `메모`에 이유를 적는다.
3. **검토자**(작성자와 다른 사람)가 `정답(검토자)` 칸을 따로 채운다. 작성자 답은 가리고 한다.
4. 두 사람 답이 다른 줄만 모여서 정하고, 정한 답을 `정답(작성자)` 칸에 덮어쓴다.
5. 다 끝나면 `정답지_열쇠_모델답.csv`와 번호로 합쳐 채점한다.

## 유형 코드 (하나만)

| 코드 | 뜻 | 이런 줄 |
|---|---|---|
| TECH_PERF | 기술 성능 | 정격 전압·전류, 절연 내전압, 구조·형식, 재질, 보호 등급 |
| RISK | 위험 조건 | 지체상금, 무제한 책임, 일방적 해지처럼 손해가 될 수 있는 조건 |
| STANDARD_CERT | 적용 규격·인증 | IEC 62271, KS 같은 규격 지정, 인증서 요구 |
| COST | 비용 영향 | 가격 구성, 보증금, 지급 조건처럼 돈과 직접 관련된 조건 |
| TEST | 시험 | 시험 방법·항목, 시험 성적서 제출 |
| MAKER_QUAL | 제조사 자격 | 제조사명, 원산지, 납품 실적, 제조사 자격 기준 |
| SITE_ENV | 설치 환경 | 고도, 기온, 습도, 오염, 내진, 풍속 같은 현장 조건 |
| NONE | 어느 것도 아님 | 서식 작성 안내, 항목 제목만 있는 줄, 잘린 조각("m/s", "mil") |

## 정할 때 원칙

- **줄 자체**를 보고 정한다. `context`(절·표 제목)는 뜻을 알 때만 참고한다.
  예: "0.2G" 줄은 context가 "Seismic"이면 SITE_ENV.
- 값 칸이 비어 있는 항목 제목(예: "4 / Insulation Levels")은 아래 항목들의 유형을 따른다.
- 제조사명·원산지 칸은 MAKER_QUAL로 통일한다.
- 형식명·모델 번호 칸("Type designation", "Model No.")은 TECH_PERF. [제안]
- 제출 서류 요구(일정표, 예비품 목록, 도면 번호)는 NONE. 단 가격 내역 요구는 COST, 운전 실적 증빙은 MAKER_QUAL. [제안]
- 발주처가 주는 보조 전원, 설치 장소(옥내·옥외)는 SITE_ENV. [제안]
- 이 기준에 없는 경우가 나오면 메모에 적고, 끝난 뒤 이 문서에 규칙을 더한다.

## 채점에서 볼 것

- 정답과 같은 비율: Gemini, Jev 각각
- Jev 확률 0.9 이상 줄과 미만 줄로 나눠 Jev 정확도
- 두 사람 답이 처음에 같았던 비율 (낮으면 기준을 더 다듬어야 함)
- 애매함 Y 줄은 따로 센다 (모델이 틀렸다고 보기 어려움)
