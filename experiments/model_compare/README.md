# 유형 붙이기 모델 비교 (정답지 100줄)

파일 1의 유형 정답지 100줄로 Gemini 설정들과 Jev를 비교합니다. Jev는 10-25 실험에 남은 답·확률을 쓰므로 **다시 부르지 않고 비용도 들지 않습니다.** Gemini만 새로 묻습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `type_compare.py` | 비교 스크립트 (본 코드는 읽기만 함) |
| `정답지_Claude초안.csv` | 정답 100줄 (Claude 초안, 사람 확인 칸 있음) |
| `정답지_열쇠_모델답.csv` | 10-25 실험의 줄마다 Gemini 답, Jev 답, Jev 확률 |
| `정답지_작성기준.md` | 정답 고르는 기준 |
| `results/` | 실행하면 생김 |

## 실행

저장소 맨 위 폴더에서 실행합니다. 파이썬 3.12 이상이면 되고, 따로 설치할 패키지는 없습니다. Docker는 켜지 않아도 됩니다.

```powershell
cd C:\RFP\RFP-agent-service-1
python experiments\model_compare\type_compare.py
```

- Gemini 키는 `.env`의 `GEMINI_API_KEY`를 읽습니다.
- 기본으로 두 설정을 돌립니다.
    - `현재_3.8flash`: `gemini-3.8-flash`, 생각 설정 없음 (지금 시스템과 같음)
    - `목표_2.5lite`: `gemini-2.5-flash-lite`, 생각 끔
- 1~2분이면 끝나고, 비용은 몇십 원 안쪽입니다.

### 다른 설정을 더 보고 싶을 때

```powershell
python experiments\model_compare\type_compare.py `
  --config "현재_3.8flash=gemini-3.8-flash" `
  --config "목표_2.5lite=gemini-2.5-flash-lite,budget=0" `
  --config "3.8생각낮게=gemini-3.8-flash,level=low"
```

- `budget=N`: 생각 토큰 예산 (2.5 계열, 0이면 끔)
- `level=low` 등: 생각 수준 (3 계열). 모델이 받지 않으면 그 설정만 "실패"로 나오고 나머지는 계속 돕니다.
- `--mix 0.95`: 섞어 쓰기 Jev 확률 문턱 바꾸기 (기본 0.9)

## 결과

`results\type_summary.md`에 표가 저장됩니다.

| 줄 | 뜻 |
|---|---|
| Gemini 3.8 Flash / Jev / 섞기 (10-25 기록) | 그날 답을 오늘 다시 채점한 것. 57 / 64 / 66이 나오면 정상 |
| 현재_3.8flash (지금 프롬프트) | 지금 시스템의 유형 질문(절·표 제목 문맥, 문서 종류 설명 포함)으로 새로 잰 것. **10-25의 57과 비교하면 프롬프트 개선 효과** |
| 목표_2.5lite (지금 프롬프트) | 목표 설정. **현재_3.8flash와 비교하면 모델을 내려도 되는지** |
| 섞기 Jev≥0.9 + 각 설정 | Jev 확률 0.9 이상은 Jev 답, 나머지는 그 설정의 답 |

열 설명:
- 맞힌 줄: 100줄 중 정답과 같은 줄
- 애매함 뺀 줄: 정답지에서 애매함(Y)이 아닌 68줄만 셈
- 두 모델 답이 달랐던 줄 / 같았던 줄: 10-25에 Gemini와 Jev 답이 달랐던 70줄(어려운 줄)과 같았던 30줄
- 줄마다 답은 `results\type_details.csv`에 있습니다.

## 조심할 점

- 정답은 Claude 초안이고 사람 확인이 없습니다. 발표에서 "Claude 초안 정답 기준"이라고 밝혀야 합니다.
- 100줄 중 70줄은 일부러 어려운 줄에서 뽑아서, 문서 전체 정확도가 아닙니다.
- Jev 답은 10-25 버전입니다.
- 지금 프롬프트에서 사람 확정 예시(DB에서 가져오는 것)는 넣지 않았습니다. 시스템에서는 사람이 유형을 고친 기록이 있을 때만 들어갑니다.
