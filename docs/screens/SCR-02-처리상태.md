# 화면 명세: SCR-02 처리 상태

- 연결 요구사항: FR-01~06·07~15 처리 흐름, `review-workspace` 처리 상태 화면
- 기준 목업: `Spec2Win_목업_v4.57.html#Loading` (`.ldo` 로고 + 진행 막대 + 문장)
- 구현 방식: 실제 (`update-review-screens` 묶음 11, 세부 진행은 `update-processing-progress`)
- 사용 API: `GET /runs/{id}` (`stage`, `step`, `step_detail`, `step_updated_at`, `started_at`, `llm_model`, `documents`, `requirements`). 처리 중이면 2초마다 다시 묻는다
- 예정 API: 없음

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 머리글 | 검토 번호, "처리 중", 제목, 문서 수·담당 | 검토 정보 | SCR-08 머리글 그대로 |
| 로고 | Spec2Win 색 로고 | — | |
| 진행 막대(`role=progressbar`, 이름 "RFP 분석") | 막대 + 백분율 | `step`, `step_detail` | 문서 읽기 단계가 2~85%(파일 순번과 세부 일·줄 수로 움직임), 나머지 9단계가 85~99%. 99에서 멈춤 [제안] |
| 문장(`.ldtx`, `aria-live`) | 단계 문장 · 문서 n개 · 요구사항 n개 | `step`, `step_detail`, `documents`, `requirements` | 문서 읽기 단계 세부: 문서 종류 확인하는 중, 절·표 나누는 중, 요구사항 뽑는 중, AI로 문장 구분하는 중 n / 전체줄, 요구사항 저장하는 중, AI로 유형 붙이는 중 n / 전체줄 (파일이 여럿이면 · 파일 i / n). 그 밖의 단계: 처리를 시작하는 중, 문서 읽는 중, 원본·정정본 찾는 중, 위험 조건 찾는 중, 제품과 비교해 판정하는 중, 공학 규칙 검산 중, 보증값 후보 만드는 중, 손실 환산 중, 일탈·질의 목록 만드는 중, 제안 포인트 만드는 중, 담당자에게 나누는 중 |
| 지난 시간(`.ldtime`) | "지난 시간 n분 m초" | `started_at` | 1초마다 다시 센다 |
| 안내 | AI 사용: "AI를 쓰는 분석은 문서가 크면 15분 넘게 걸릴 수 있어요. 이 창을 닫아도 분석은 계속됩니다." / AI 없음: "AI 없이 규칙으로만 분석해 보통 1분 안에 끝나요." | `llm_model` | 15분은 2026-10-25 실측(약 14분 40초) |
| 멈춤 안내(`role=alert`) | "10분 넘게 진행이 없습니다. …검토를 다시 등록해 주세요." | `step_updated_at` | 마지막 진행에서 10분이 넘으면 [제안] |

처리가 끝나면(담당자 확인 단계) 같은 주소에서 탭과 요약 칸이 있는 검토 상세로 바뀐다. 처리 실패는 SCR-11.

## 수용 기준 (Given / When / Then)

- **Given** 위험 조건 찾기 단계인 검토, **When** 검토 상세를 열면, **Then** 진행 막대 값이 0과 100 사이, "위험 조건 찾는 중", 끝나면 판정 탭. (처리 중인 검토)
- **Given** 문서 읽기 단계에서 AI 유형 붙이기 480 / 3,397줄, **When** 검토 상세를 열면, **Then** "AI로 유형 붙이는 중 480 / 3,397줄", 지난 시간, 막대 값은 0줄일 때보다 큼. (유형 붙이기 진행)
- **Given** 마지막 진행이 11분 전, **When** 검토 상세를 열면, **Then** "10분 넘게 진행이 없습니다" 안내. (오래 진행이 없음)
