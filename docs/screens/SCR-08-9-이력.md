# 화면 명세: SCR-08-9 이력 탭

- 연결 요구사항: FR-10(확인·수정 이력), AR-07, `review-workspace` 이력 탭, `review-run` 이력 대상 이름
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 이력 탭 (`#log`)
- 구현 방식: 실제 (`update-review-screens` 묶음 5)
- 사용 API: `GET /runs/{id}/history`(`target_label`), `GET /runs/{id}`(`finished_at`, `judgments`)
- 예정 API: 없음

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 표 (`table.mini`) | 시각(MM-DD HH:mm), 사람, 한 줄 문장, "사유: …"(결재·상신은 "의견: …") | `acted_at`, `actor`, `target_table`·`action`·`before_value`·`after_value`·`target_label`, `reason` | 새것부터 |
| 맨 아래 줄 | "시스템 · 판정 n줄 생성" | `finished_at`, `judgments` | 실행이 끝난 시각 |

문장 (`components/history.ts`, 기록 값 그대로):

| 대상 | 문장 |
|---|---|
| 판정 바꾸기 / 확정 | 판정 "항목" 이전 → 새 판정 / 판정 "항목" 제안대로 확정 |
| 보증값 | 보증값 "항목"에 값 입력 / 확정 |
| 위험 조건 | 위험 조건 "표현" 위험으로 확정 / 문제 없음으로 닫음 |
| 일탈·질의 목록 | 목록 문장 "앞부분" 확정 / 고침 / 목록에서 뺌 |
| 제안 포인트 | 제안 포인트 "근거" 채택 / 버림 / 문장 고침 |
| 손실 환산 | 손실값 고침 (무부하 · 부하 · 보조 kW) |
| 비교 제품 | 비교 제품 바꿈: 이전 → 새 (자동은 "자동") |
| 검토 실행 | 결재 상신 · 승인 · 반려 · 결재 상신 취소 · 반려 뒤 다시 확인 시작 · 검토 정보 고침(칸 이전 → 새) |

시스템이 넣은 고정 사유(검토 정보 고치기, 손실값 고치기, 비교 제품 바꿔 보기, 상신 취소, 반려 뒤 다시 확인)는 문장과 겹쳐 사유 줄에 보이지 않는다.

## 화면 상태

- 데이터 없음: 시스템 줄만 보인다.
- 오류: 오류 문장 + "다시 불러오기"

## 수용 기준 (Given / When / Then)

- **Given** 판정을 일탈 후보로 바꾼 실행, **When** 이력 탭을 열면, **Then** 맨 위에 판정 문장과 사유, 맨 아래에 시스템 판정 생성 줄. (판정 바꾼 이력)
- **Given** 위험 조건을 닫은 실행, **When** 이력 탭을 열면, **Then** "위험 조건 "표현" 문제 없음으로 닫음"과 사유. (위험 조건 닫은 이력)

## 단계부터 다시 처리 (add-step-rewind, C2)

이력 표 위 한 줄: 처리 단계 고르기(문서 읽기~담당자 전달), 사유 칸, [다시 처리]. 엔지니어이고 담당자 확인 단계일 때만 보인다. 사유가 비면 못 누른다. 누르면 처리 중 화면이 되고, 끝나면 이력에 "{단계}부터 다시 처리"와 사유가 남는다. 사람이 확정·수정한 판정은 같은 줄이면 이어받는다는 안내를 함께 보인다. 목업에 없는 칸이다.
