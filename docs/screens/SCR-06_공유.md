# SCR-06 검토 목록: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 단계 "분석 중·검토 중·결재 대기·결재 완료·반려·분석 실패" | "처리 중·담당자 확인·승인 대기·승인됨·반려됨·처리 실패" | 값 종류와 라벨은 API를 따른다(2026-10-28 결정). 색은 목업과 같다 |
| 2 | 사업명이 사업 상세로 가는 링크 | 글자만 | 사업 화면(SCR-04·05)은 예시 화면이라 실제 검토와 잇지 않는다 |
| 3 | 같은 입찰(Lot) 묶음 줄 "같은 입찰: … 같이 보기" | 없음 | Lot 나누기는 `add-review-info` Non-Goal |
| 4 | 분석 실패 줄 → 분석 실패 상세, 결재 대기 줄 → 결재 대기 상세 | 둘 다 검토 상세 | SCR-11·SCR-12를 만들면 바꾼다 |
| 5 | 다른 사람 검토를 볼 때 "판정 변경과 결재 상신은 담당자와 위임받은 대리인만…" | 첫 문장 "…의 검토를 보고 있습니다."만 | 지금 권한은 담당자가 아니라 역할로 정한다(`_공통규칙.md` 5장). 없는 규칙을 안내하지 않는다 |
| 6 | 줄 끝 "⋯" 메뉴 | 검토 상세로 가는 링크 | 목업에도 메뉴 내용이 없다 |
| 7 | 검색 자리 안내 "검토명, 번호, 고객사, 파일명" | "사업명, 검토명, 번호, 고객사, 파일명" | 사업명을 따로 저장해서 함께 찾는다 |
| 8 | 담당 범위 "내 검토·팀 전체" | "내 검토·팀 전체·내가 올린 결재", 결정 칩과 "결재" 칸 | 엔지니어가 올린 결재의 대기·반려·승인을 볼 곳이 없었다. 결재함 메뉴 대신 목록 안 보기로(2026-10-31 결정, 11-01 승인, `update-review-list-approval`) |
| 9 | 요약 줄은 숫자만 | "결재 대기 n"을 누르면 결재 대기로 거름 | 위와 같음 |
