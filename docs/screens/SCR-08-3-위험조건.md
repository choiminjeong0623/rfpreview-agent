# 화면 명세: SCR-08-3 위험 조건 탭

- 연결 요구사항: FR-06·10, `review-workspace` 위험 조건 탭·사전 추가 제안 화면, `risk-detection` 위험 표현 사전에 추가 제안, `review-run` 위험 조건 항목 이름
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 위험 조건 탭 (`#risk`)
- 구현 방식: 실제 (`update-review-screens` 묶음 2). "사람이 찾은 특이 요구"는 `add-rule-suggestion`으로 실제
- 사용 API: `GET /runs/{id}/risks`(값 불일치 줄에 `item_name`), `GET /runs/{id}/history`, `GET /runs/{id}/documents`, `POST /runs/{id}/actions` risk_flag CONFIRM·REJECT,
  `GET·POST /runs/{id}/rule-suggestions` (`add-rule-suggestion`)
- 예정 API: 없음

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 머리 (`.sech`) | "위험 조건" + "포괄 조항 n · 값 불일치 n · 범위 모호 n" | 닫지 않은(`CLOSED_OK` 아닌) `risk_kind`별 수 | |
| 사람이 찾은 특이 요구 (`.rk`) | 설명, 이 검토의 제안 줄(“표현”, 찾은 곳 · 메모 · 제안한 사람, 상태 칩: 제안함 · 규칙 담당 확인 대기 / 반영 / 반려(사유)), 놓친 표현 칸 + 메모 칸 + "위험 표현 사전에 추가 제안" | `expression`, `locations`, `note`, `suggested_by_name`, `status`, `decision_reason` | 찾은 곳은 표현이 처음 나온 문장의 원문 위치(CR-02). 반영·반려는 판정 규칙 화면(SCR-17) |
| 위험 조건 표 (`table.mini`) | 상태 배지(후보·확정·문제 없음), 제목, 종류 · 설명, 원문 위치(외 n곳), 처리 | `status`, `expression` / `item_name` + `members[].value_raw`, `explanation_ai`, `members[].locations` | 닫지 않은 줄 먼저, 문제 없음은 흐리게(`tr.dis`) 맨 아래 |
| 처리 칸 | 후보: "위험으로 확정", "문제 없음". 확정·문제 없음: 처리한 사람 · 시각 | `history`의 risk_flag 마지막 CONFIRM·REJECT | |
| 원문 펼치기 | 원문 위치를 누르면 아래 줄에 원문 문장(표현 또는 값 강조)과 모든 위치 | `members[].text_raw` | |

제목: 포괄 조항·범위 모호는 “표현”, 값 불일치는 "항목 이름 값1 / 값2". 설명: 문제 없음은 닫은 사유, 아니면 AI 설명, 없으면 종류별 한 줄.

## 화면 상태

- 데이터 없음: "위험 조건 후보가 없습니다."
- 오류: 오류 문장 + "다시 불러오기"
- 권한 없음: 확정·문제 없음 단추 비활성화 + 툴팁("담당자 확인 단계에서만 고칠 수 있습니다" / "엔지니어만 고칠 수 있습니다")

## 목업에 있지만 만들지 않는 요소

- 규칙 담당 이름(김민수 수석): 직급·담당 지정이 없다. "규칙 담당"으로 쓴다.

## 수용 기준 (Given / When / Then)

- **Given** 포괄 조항·값 불일치·범위 모호 후보가 하나씩, **When** 위험 조건 탭을 열면, **Then** 머리에 "포괄 조항 1 · 값 불일치 1 · 범위 모호 1", 줄 3개에 "후보"와 원문 위치. (위험 조건 건수)
- **Given** 값 불일치 후보, **When** 엔지니어가 사유를 적어 문제 없음으로 닫으면, **Then** 흐린 "문제 없음" 줄로 맨 아래, 사유·처리자, 값 불일치 0. (문제 없음으로 닫기)
- **Given** 사유 칸이 빔, **When** 닫으려 하면, **Then** 닫기 단추가 눌리지 않는다. (사유 없이 닫기)
- **Given** 포괄 조항 후보, **When** 위험으로 확정하면, **Then** 배지 "확정"과 처리자. (위험으로 확정)
- **Given** 문서에 있고 사전에 없는 표현, **When** 엔지니어가 위험 조건 탭에서 제안하고 판정 규칙 화면에서 반영하면, **Then** 위험 조건 탭의 "확인 대기" 줄이 "반영"이 되고 위험 표현 탭에 그 표현이 보인다. (제안하고 반영하기)
