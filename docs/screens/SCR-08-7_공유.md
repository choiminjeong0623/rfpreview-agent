# SCR-08-7 지난 RFP 비교 탭: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 실제 기능 | 실제 데이터 (`add-past-compare`, 11-01). 같은 고객사(검토 정보의 고객사 글자가 같음)의 처리를 마친 검토와 비교 | 고객사 칸은 사람이 넣는 값이다. 비어 있으면 넣으라고 안내한다 |
| 2 | "지난 입찰" BD-번호, 제출일, 결과(수주) | "지난 검토" 검토 번호(그 검토 상세로), 시작일, 판정 줄 수, 비교 제품, 단계 | 입찰 번호·제출일·수주 결과 데이터가 없다(입찰 이력 화면은 예시) |
| 3 | 줄을 누르면 이번 판정의 원문(판정 상세 창)을 엶 | 누를 수 없음 | 다음에 판정 탭과 잇는다. 응답에 이번 요구사항 번호는 있다 |
| 4 | 참고 칸 "히터 옵션 검토 필요" 같은 엔지니어 판단 문장 | 코드가 쓴 짧은 문장("요구 값이 올라감/내려감", "판정 같음/바뀜", "지난번에 없던 요구", "이번에는 요구 없음 · 지난번 ○○") | 판단 문장은 AI나 사람 몫인데, 비교는 코드만 한다(CR-01). 올라감·내려감은 단위 글자가 같을 때만(CR-10) |
| 5 | 항목 이름 한 줄 | 표준 항목 이름 + 아래 줄에 설비(예: 245 kV GIS)와 표의 영문 항목 이름 | 같은 "정격 전류"가 여러 줄(주모선·피더 등)이라 구분이 필요하다 |
