# SCR-12 결재 대기 상세: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 결재자는 사내 전자결재에서 결정하고, 이 화면은 기안자 쪽만 있음 | 지정 결재자가 열면 띠 오른쪽에 반려·승인, 그 위에 "결재 의견" 칸 | 전자결재 연계가 범위 밖이라 앱 안에서 결정한다 (스펙 "승인 결정", design 5) |
| 2 | "결재 요청 다시 알림" 단추 | 없음 | Non-Goal (다시 알림) |
| 3 | "열람함 · 결재 대기", 띠의 "10-24 09:12 열람함" | "결재 대기", 띠에는 상신 후 날 수만 | Non-Goal (열람 시각) |
| 4 | 기본 정보의 전자결재 번호·참조, 첨부 카드 | 없음. 기본 정보에 국가를 더함 | Non-Goal (전자결재 번호·참조·첨부) |
| 5 | 상신 취소는 기안자만 | 엔지니어 역할이면 누구나 | 스펙 "상신 취소" (엔지니어가 취소). 로그인이 없어 기안자 구분을 강제하지 않는다 |
| 6 | 상신 전 확인 결과 5줄 | 승인 기준 6줄 + 문서 읽기 점검 줄 + AR-01 줄에 "일탈 목록에 n건" | 값 종류는 API (공통 규칙 2장). 스펙 Scenario "승인 화면"의 "목록에 들어간 수" |
| 7 | "우리 제안 · 판단" 칸이 우리 제안 문장 | 제품값(없으면 판정 이름), 위험 조건은 사실 문장 | 제안 문장은 목록 항목에 있고 판정 행과 1:1이 아니다. `update-review-screens`에서 다시 본다 |
