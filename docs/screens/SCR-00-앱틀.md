메뉴에 없는 화면 주소. 새 라우터 의존성 없이 `#` 뒤 주소를 쓴다(목업도 `#화면 키`로 화면을 연다).

|---|---|---|
| `#/reviews/:id` | 검토 상세 (탭은 화면 안에서 고름) | SCR-08 |
| `#/reviews/:id/tbe` | TBE 준수표 | SCR-09 |

## 화면 상태

- 로딩 중: 사용자 목록이 오기 전에는 "사용자 없음"으로 보인다.
- 오류: 사용자 목록을 못 받아도 틀은 그대로 보인다. 각 화면이 자기 오류를 보인다.

## 수용 기준 (Given / When / Then)

- **Given** RFP 검토 화면, **When** 지식 관리 > 제품 관리를 누르면, **Then** 주소가 `#/products`가 되고 제품 관리 메뉴가 강조되며 위치에 "홈 > 제품 관리"가 보인다. (메뉴로 화면 이동)
- **Given** 아무 화면, **When** 주소 `#/todo`를 바로 열면, **Then** RFP 관리 묶음이 펼쳐지고 협조 요청이 강조된다. (메뉴로 화면 이동)
- **Given** 펼친 메뉴, **When** 메뉴 접기를 누르고 새로 고치면, **Then** 메뉴는 접힌 채로 보인다. (메뉴 접기)
- **Given** 엔지니어로 보는 중, **When** 사용자 겹창에서 기본 승인자를 고르면, **Then** 머리글에 "기본 승인자 · 승인자"가 보이고 새로 고쳐도 유지된다. (사용자 바꾸기)
- **Given** 알림 단추, **When** 누르면, **Then** "예시" 꼬리표가 붙은 알림이 보이고 모두 읽음으로 하면 읽지 않은 수가 0이 된다. (알림은 예시로 보인다)

### 4. 머리글 분석 진행 표시 (목업 v4.60)

구현됨 (change `update-header-progress`, `shell/AnalysisProgress.tsx`). 목업의 "AI 응답 대기 중 (재시도 1/3)"과 끝남 안내의 "꼭 볼 것 n줄"은 실행 목록 응답에 칸이 없어 빼고, 멈춤 안내는 "n분째 진행이 없습니다"만 보인다. 사람이 취소한 검토는 알리지 않는다.

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 머리글 단추(`.anb`) | 둥근 진행 고리, "분석 n건 · p %" | `GET /runs`의 `stage = PROCESSING`인 검토, 진행률은 `components/progress.ts` 계산(검토 목록과 같음) | 처리 중 검토가 없으면 단추 없음. 하나라도 멈춤 안내 기준을 넘으면 주황(`.warn`) |
| 작은 창(`.anp`) | 검토마다: 검토 번호·이름, 단계 이름 + 세부("1,186 / 3,397줄"), 진행 막대, 지난 시간, 멈춤 안내, [보기] | `review_no`, `review_name`, `step`, `step_detail`, `started_at`, `step_updated_at` | [보기]는 처리 상태 화면(SCR-02) |
| 끝남 안내(`.antstw`) | "<검토 이름> 분석이 끝났습니다 · 판정 확인", 실패면 "분석이 멈췄습니다 · 실패 보기" | 이전에 처리 중이던 검토의 `stage` 변화 | 화면 오른쪽 위에 쌓임(아래 7) |

- 처리 중 검토가 있으면 5초마다 `GET /runs`를 다시 부른다(검토 목록·홈과 같은 주기). 없으면 부르지 않는다.
- 사용자를 바꿔도 모든 사람의 처리 중 검토를 보인다(분석은 공용 자원).

### 5. 요약 상자 (목업 v4.92 "AI 요약", Q1)

| 영역 | 보이는 항목 | 비고 |
|---|---|---|
| 상자(`.ais`) | "요약" + "코드가 씀" 꼬리표, 요약 시각, [다시 요약], 2~4문장, 문장 안 링크(검토·판정·탭으로 가기) | 검토 상세(SCR-08)와 홈(SCR-03)만. 다른 화면에는 두지 않는다 |

- 문장은 백엔드가 정해진 틀에 숫자·이름·날짜를 채워 만든다(CR-01·07). 같은 데이터면 같은 문장(CR-11).

- 요약 API가 실패하면 상자를 숨기지 않고 "요약을 만들지 못했습니다 · 다시 요약"을 보인다.

### 7. 알림 쌓기 (목업 v4.96)

공통 부품으로 구현됨 (`add-ui-foundation`, `useToast`). 화면마다 바꾸는 것은 그 화면 차례에.

### 수용 기준 (v4.96)

- **Given** 처리 중 검토 1건, **When** 아무 화면을 열면, **Then** 머리글에 "분석 1건 · p %"가 보이고, 누르면 작은 창에 그 검토의 단계 이름과 진행 막대가 보인다. (머리글 분석 진행 표시)
- **Given** 처리 중 검토가 없음, **When** 화면을 열면, **Then** 머리글에 진행 단추가 없다. (처리 중 없으면 숨김)
- **Given** 머리글에 보이던 처리 중 검토, **When** 분석이 끝나면, **Then** "분석이 끝났습니다" 알림이 오른쪽 위에 쌓인다. (끝남 안내)
- **Given** 10줄씩 나눈 판정 표, **When** 2쪽으로 넘기면, **Then** 첫 줄의 순번이 11이다. (순번이 이어짐)
- **Given** 알림 두 개가 거의 동시에 생김, **When** 화면을 보면, **Then** 두 알림이 위아래로 쌓여 보인다. (알림 쌓기)
