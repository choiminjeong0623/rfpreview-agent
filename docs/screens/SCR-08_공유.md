# SCR-08 검토 상세: 목업과 다르게 만든 것 (공유)

머리글만 먼저 만들었다(`add-review-info`). 탭·요약 칸·판정 표는 `update-review-screens`에서 목업대로 만든다.

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 머리글에 검토 정보를 고치는 단추가 없음 | "검토 정보 고치기" 단추와 창 | 승인된 스펙(`add-review-info`)이 "머리글에서 고치기"를 요구한다. 창 모양은 목업의 결재 상신 창(`.apw`)을 따른다. 칸 배치는 `views/detail.css`에 더했다 |
| 2 | "사업 Thai Binh 115·230 kV 변전소 신설"이 사업 상세 링크 | "사업 Thai Binh" 글자 | 사업 화면은 예시 |
| 3 | "상신 권장 10-28", "문서 추가", "115 kV 비교 제품" 고르기, 묶음·규격 체계, 결재자 | 비교 제품 고르기는 머리글에 있음(설비 묶음마다, SCR-08-5_공유.md), 결재자는 결재가 끝나면 보임. "묶음 A·B"는 판정 대상 문서의 묶음으로 보임(`update-document-info`). 상신 권장일·규격 체계는 없음. 문서 추가는 머리글 단추 대신 "문서 n개" 창 안에 있음(5번) | 상신 권장일은 규칙이 없다. 규격 체계는 문서마다 달라 머리글 한 줄에 넣지 않는다 |
| 5 | "문서 n개"를 누르면 문서 추가 창(받은 문서 목록 + 개정 문서 올리기) | 같은 자리를 누르면 문서 표 창(종류·분류 방법·묶음·판정 대상·요구사항 수). 창 아래 "문서 추가"(엔지니어·담당자 확인 단계만): docx 고르기 → 분류 추천·묶음 고르기 → "추가하고 다시 분석" (`add-document-addendum`, 11-01) | 문서를 더하면 같은 검토를 처음부터 다시 분석한다(처리한 문서는 다시 씀). 같은 줄의 확정·수정·반려는 이어받는다. 문서 빼기·바꾸기는 없다(정정본도 새 파일로 더하고 원본 판정은 사람이 반려) |
| 4 | 요약 칸 5개와 탭 9개 | 같음 (`update-review-screens` 묶음 1). 탭 줄을 머리글 위, 본문 안 맨 위에 둔다 | 탭별 차이는 SCR-08-x_공유.md |
| 6 | (목업에 없음) 비교 제품을 바꾼 뒤 기다리는 동안의 모습 | 다시 판정하는 동안 화면 가운데에 큰 "다시 판정 중…" 안내(묶음 이름·바꾼 제품)를 띄우고 뒤 화면을 덮어 다른 단추를 막음 (`update-rejudge-busy`) | 다시 판정은 몇 초 걸리는데 그사이 확정·채택을 누르면 사라질 판정에 동작이 걸린다(10-31 주말 검토) |
| 7 | (목업에 없음) 검토 도우미 | 머리글 오른쪽 "검토 도우미" 단추 → 화면 오른쪽에 붙는 창(질문, 상태 한 줄, 답 문장과 [n] 근거 조항 번호, 근거 조항·원문 위치, 접어 둔 찾은 방법) (`add-review-assistant`, 11-01; `update-assistant-panel`, 11-02: 부제·질문 반복 없앰, 상태 중립색 한 줄, 내부 번호 숨김, 0건 안내) [제안] | 효율 개선 제안 4번. 목업에 자리가 없어 탭을 늘리지 않고 옆 창으로 붙였다. 창을 열어 둔 채 판정 표를 볼 수 있다. AI는 읽기 도구만 쓰고, 코드가 근거 번호·숫자를 대조해 어긋난 문장은 뺀다 |
