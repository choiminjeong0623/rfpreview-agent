# 화면 명세: SCR-08-2 문서 읽기 점검 탭

- 연결 요구사항: FR-01·02(읽지 못한 곳, "구조 확인 필요"·"칸 확인 필요"), FR-05(단위 없는 값), FR-10(확인 이력), `review-workspace` 문서 읽기 점검 탭·상신 전 확인의 문서 읽기 점검, `review-run` 문서 읽기 점검 목록·확인, `document-intake` 그림 위치 기록
- 기준 목업: `Spec2Win_목업_v4.57.html#Detail` 문서 읽기 점검 탭 (`#read`), 결재 상신 창 상신 전 확인, Wait 상신 전 확인 결과
- 구현 방식: 실제 (`update-review-screens` 묶음 7)
- 사용 API: `GET /runs/{id}/read-checks`, `POST /runs/{id}/read-checks/{key}`, `DELETE /runs/{id}/read-checks/{key}?actor_id=`, `GET /runs/{id}/approval`(`read_unchecked`), `GET /runs/{id}/history`
- 예정 API: 없음

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 탭 이름 | "문서 읽기 점검" + 확인 안 한 건수(`.tabn`) | `checked_at`이 빈 줄 수 | 0이면 숫자 없음 |
| 머리(`.sech`) | "표 n · 그림 n · 단위 n · 위치 n", "확인 안 함 n건" / "모두 확인함" / 줄이 0개면 "읽지 못한 곳 없음" | `kind`, `checked_at` | |
| 안내(`.rdi`) | 목업 문장 그대로 | — | |
| 표(`table.mini.rdt`) 1칸 | 종류 아이콘 + 종류, 무엇 | `kind`, `what` | 아이콘: 표 table_chart, 그림 image, 단위 straighten, 위치 location_searching |
| 2칸 | 위치(굵게), 파일 이름, 문제(`.rdp`), 할 일(`.rdtodo`) | `loc`, `file_name`, `problem`, `todo` | 문장은 백엔드 코드가 만든다 |
| 3칸 | "직접 확인함" 단추 / "확인함" + 사람 · 시각 + "되돌리기" | `checked_by`, `checked_at` | 확인한 줄은 흐리게(`.done`) |
| 상신 창·결재 대기 | "문서 읽기 점검 미확인 n건"(주의, 설명 "빠진 요구사항이 있을 수 있습니다") / "문서 읽기 점검 모두 확인" | `read_unchecked` | 확인 필요 비율 줄 다음. 남아 있어도 상신할 수 있다 |

점검 줄을 만드는 규칙 (`pipeline/read_checks.py`, 순서 표 → 그림 → 단위 → 위치):

| 종류 | 무엇 | 원천 | 위치 글자 |
|---|---|---|---|
| 표 | 표 칸을 읽지 못함 | `doc_table.role_flag` (머리글 행을 못 찾음) | 표 이름(없으면 절) · a~b행 |
| 그림 | 그림 속 글자는 읽지 않음 | `doc_figure` (그림 단락) | 그림 설명(없으면 절) · n행 |
| 그림 | 문서를 읽지 않음 | `document.readable = FALSE` | 문서 전체 |
| 단위 | 단위를 모름 | `req_value.flag = UNIT_MISSING`, 표 하나(표 밖은 절 하나)마다 한 줄 | 표 이름 · No. a~b / 절 · a~b행 |
| 위치 | 절 번호가 끊김 | `section.structure_flag` | n절 · n행 |
| 위치 | 위치가 모호함 | 같은 문서에서 여러 단계 절 번호(6.3, 7.4.2)가 두 번 이상 | n절 · a행과 b행 |

## 동작

- "직접 확인함": `POST` → 줄이 "확인함"으로 바뀌고, 머리 표시와 탭 건수가 줄며, 이력에 "문서 읽기 점검 확인: <위치> (<무엇>)"이 남는다.
- "되돌리기": `DELETE` → 다시 "직접 확인함", 이력에 "문서 읽기 점검 확인 되돌림: …".
- 담당자 확인 단계의 엔지니어만 누를 수 있다. 아니면 단추가 눌리지 않고 마우스를 올리면 이유가 보인다.

## 화면 상태

- 데이터 없음(점검 0줄): 안내 문장과 표 대신 초록 칸 "모든 문서를 끝까지 읽었습니다." + "표 칸 역할, 그림, 단위 없는 값, 끊기거나 겹친 절 번호를 살폈고 읽지 못한 곳이 없습니다. 직접 확인할 곳이 없습니다." 머리 표시는 "읽지 못한 곳 없음"(사람이 모두 확인한 "모두 확인함"과 구분, update-read-check-empty).
- 오류: 오류 문장 + "다시 불러오기". 확인 실패는 표 아래 오류 문장.

## 수용 기준 (Given / When / Then)

- **Given** 점검 줄 4개인 실행, **When** 엔지니어가 그림 줄의 "직접 확인함"을 누르면, **Then** "확인함"과 이름, 건수 3, 이력 줄. (점검 줄 확인)
- **Given** 확인한 줄, **When** "되돌리기"를 누르면, **Then** 다시 "직접 확인함", 건수 4. (점검 확인 되돌리기)
- **Given** 승인자로 연 화면, **When** 탭을 열면, **Then** 단추가 눌리지 않고 "엔지니어만 확인할 수 있습니다". (고칠 수 없을 때 확인 단추)
- **Given** 점검 줄 0개인 실행(합성 데이터시트), **When** 탭을 열면, **Then** "모든 문서를 끝까지 읽었습니다", 머리 "읽지 못한 곳 없음", 탭 건수 없음. (읽지 못한 곳이 없는 검토)
- **Given** 확인 안 한 줄 4개, **When** 결재 상신 창을 열면, **Then** "문서 읽기 점검 미확인 4건"이 주의로 보인다. (상신 창의 점검 미확인)
