# 화면 명세: SCR-11 분석 실패 상세

- 연결 요구사항: CR-12(AI 오류는 정해진 횟수만 재시도, 실패하면 멈춤과 실패 단계 기록), `review-workspace` 분석 실패 화면
- 기준 목업: `Spec2Win_목업_v4.57.html#Fail`
- 구현 방식: 실제 + 예시 영역 (`update-review-screens` 묶음 12). 화면 CSS는 목업 Fail CSS 그대로(`frontend/src/mockup/Fail.css`)
- 사용 API: `GET /runs/{id}`(`failed_step`, `error_message`, `started_at`, `finished_at`, 결과 수, `llm_model`), `GET /runs/{id}/documents`, `GET /runs`(다른 실패), `GET /runs/{id}/approval`(결재자)
- 예정 API: 다시 시도(멈춘 단계부터), 멈춘 곳 원문 위치, 단계별 처리 기록

## 화면 구성

| 영역 | 보이는 항목 | API 칸 | 비고 |
|---|---|---|---|
| 머리 줄(`.fid`) | 검토 번호, "처리 실패", 마감, 등록 시각, 담당, 결재자 | 검토 정보 | |
| 제목(`.fh`) | 사업명 · 검토명, "다른 분석 실패 · …" | `GET /runs`에서 실패한 다른 검토 첫 번째 | |
| 알림(`.falert`) | "<단계> 단계에서 멈췄습니다", 시각 · 문서 수, 오류 문장 | `failed_step`, `finished_at`, `error_message` | |
| 진행 상황(`.fsteps`) | 문서 읽기 / 위험 조건 찾기 / 제품과 비교·판정 / 일탈·질의 목록 / 입찰 영향 정리 | `failed_step`, 결과 수 | 실패 묶음 앞은 끝남(결과 수), 실패 묶음은 "…에서 멈춤", 뒤는 대기 |
| 어떻게 계속할까요 | 예시 띠, 다시 시도 · 코드 규칙만으로 계속 · 남은 부분은 직접 확인 · 시스템 담당자에게 알리기, 나중에 · 실행 단추 | — | 예시. 실행 단추는 "예시 화면이라 처리하지 않았습니다" 알림만 |
| 지금 볼 수 있는 것 | 일탈 후보 · 판정 · 위험 조건 수, 한 줄 설명 | 결과 수 | 설명은 코드가 수로 만든다 |
| 문서 | 파일 이름, 문서 종류, 읽음 / 읽지 못함 / 멈춤 | `documents` | |
| 처리 기록 | 등록 · 분석 시작, 멈춘 단계와 오류 | `started_at`, `finished_at` | 시:분 |
| 문의용 정보 | 작업 번호, 멈춘 단계(코드), 발생, 모델, 오류, 복사 | | 복사하면 알림 |

## 수용 기준 (Given / When / Then)

- **Given** 위험 조건 찾기에서 실패한 검토, **When** 상세를 열면, **Then** 멈춘 단계와 오류, 진행 상황(끝남·멈춤·대기), 문서 이름. (분석 실패 상세)
- **Given** 실패 화면, **When** 방법을 고르고 실행 단추를 누르면, **Then** 예시 알림만 보이고 단계는 그대로. (계속하는 방법 예시)
