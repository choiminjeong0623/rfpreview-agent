## 2. 결정에 딸린 작은 정리 (갭 목록 추천 그대로)

- 머리글 분석 진행 표시, 표 순번, 알림 쌓기: 공통 부품으로 만든다(SCR-00 4장).
- 검토 상세: 머리글 정보 3묶음, "꼭 볼 것", 탭 5개 + 더 보기, 아래 행동 줄. "확인 필요 비율"은 결재 상신 창(SCR-08-10)에 남는다.
- 판정 결과 5종과 라벨은 그대로(`_공통규칙.md` 2장). 목업 판정 순서에서 "작성 필요"가 빠진 것은 "보증값 작성"을 맨 뒤로 보내는 것으로 맞춘다.
- 요구사항 유형은 API 7종 그대로(목업 운송·포장, 보증·서비스 쓰지 않음).
- 협조 요청: 담당 탭 건수, 검색 영역, RFP별 보기, [재요청]. 내보내기는 엑셀로 만든다. 요청하기 창은 예시 그대로.
- 제품표: 오른쪽 빠른 보기, RFP 검토 찾기 창. 칸별 근거 종류(성적서·카탈로그)와 옵션 값은 제품표에 칸이 없어 만들지 않는다.
- 사업 상세 "인계 패키지 보기", 홈 실패 알림 [재시도]는 이미 있는 API로 화면만 고친다.
- 데이터시트에서 여는 인계 패키지 창은 만들지 않는다. 데이터시트에는 이미 "영업에 넘기기"가 있고, 패키지는 결재 승인 뒤 제출본 탭·사업 상세에서 연다.
- TBE 준수표·데이터시트·분석 실패·결재 대기·협조 요청·사업 현황·사업 상세·검토 등록·제품 상세·입찰 상세·팀 현황의 요약 상자는 만들지 않는다(Q1).
- 제출본 버전(v1·v2): 이번에는 만들지 않는다. 결재 기록 순서로 "1차·2차 상신"만 보인다(SCR-08-8).

## 3. 새로 필요한 API (구현 change에서 만든다)

| API | 쓰는 화면 | change 이름 (제안) |
|---|---|---|
| `GET /runs/{id}/documents/{file_no}/lines?from=&to=` 원문 줄 범위(최대 40줄). 올린 파일은 서버 업로드 폴더에 내용 해시로 남아 있으므로, 분석 때와 같은 방법으로 다시 읽어 같은 줄 번호로 돌려준다. 파일이 없으면 DB에 남은 줄(절 제목·요구사항 문장·표 행)만 돌려주고 `partial: true` | SCR-08-12 | `add-judgment-view` |
| `GET /runs/{id}/summary` 검토 요약 문장(코드 틀) | SCR-08 | `add-screen-summary` |
| `GET /home/summary?user_id=` 홈 요약 문장(코드 틀) | SCR-03 | `add-screen-summary` |
| `POST /runs/{id}/actions` 동작 `QUERY_SENT`·`QUERY_UNSENT` (질의 후보 판정), 판정 응답 `query_sent_at` | SCR-08-1, SCR-08-12 | `add-query-sent` |
| 다시 분석 결과 줄 수 `RunSummary.revision`(바뀜·추가·사라짐, 반영 시각, 추가 문서 이름) | SCR-08, SCR-08-1 | `add-revision-notice` |
| `GET /assignments`의 `role`을 생략하면 모든 부서 | SCR-13 | `update-todo-search` |
| `GET /assignments/export` 협조 요청 엑셀 | SCR-13 | `update-todo-search` |

그 밖의 v4.96 변경은 지금 API로 된다(화면만 고침).
