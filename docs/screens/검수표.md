목업 v4.96과 앱을 같은 너비(1600px)로 나란히 찍고, 화면 영역(작업 영역 안에서 너비 30 % 넘고 높이 20px 넘는 블록의 class)이 목업에 있는데 앱에 없는지, 같은 영역의 위→아래 순서가 같은지 코드로 비교했다. 값·글자는 비교하지 않는다.

## v4.57 대조 (2026-10-28)

목업과 앱을 같은 너비(1600px)로 찍어 나란히 놓고 비교한 결과다 (2026-10-28).

- 찍는 법: 백엔드(8000)와 `npm run dev`(5173)를 켠 뒤 `cd frontend && node scripts/compare-mockup.mjs`. 결과는 `frontend/compare-out/SCR-xx.png`(왼쪽 목업, 오른쪽 앱)이며 커밋하지 않는다.
- 검토 상세 계열은 실행 번호가 필요하다. `RUN_ID`(담당자 확인 단계), `WAIT_ID`(결재 대기), `FAIL_ID`(처리 실패), `PROC_ID`(처리 중)를 주지 않으면 최근 실행 200건에서 단계로 고른다. 이번에는 판정이 있는 합성 문서 실행(RUN_ID=728), 결재 대기 712, 처리 실패 75를 썼다.
- 값(사업명·숫자·문장)은 목업 예시와 DB의 합성 데이터가 달라 비교하지 않는다. 배치, 영역, 단추, 칸 이름, 상태 표시만 본다.
- 목업 파일은 바깥 주소를 막고 열어 아이콘 글꼴이 글자(예: `ho`, `de`)로 보인다. 앱은 아이콘이 보인다. 차이로 세지 않는다.

판정: **같음** = 배치와 요소가 같다. **의도한 차이** = `SCR-xx_공유.md`에 적은 차이만 있다. **고침** = 이번 대조에서 찾아 고쳤다. **남음** = 아직 다르다.
