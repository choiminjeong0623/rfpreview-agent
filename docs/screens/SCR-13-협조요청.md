# 화면 명세: SCR-13 협조 요청 현황

- 연결 요구사항: FR-11(유형별 담당자 전달), `role-assignment`(할 일 상태, 협조 요청 메일 발송), `review-workspace` 협조 요청 현황 화면
- 기준 목업: `Spec2Win_목업_v4.57.html#Todo`. **v4.96부터 `Spec2Win_목업_v4.96.html`이 기준**(맨 아래 "v4.96 바뀐 점")
- 구현 방식: 실제 + 예시 창 (`update-review-screens` 묶음 13, `update-role-handoff-mail`). 화면 CSS는 목업 Todo CSS 그대로(`frontend/src/mockup/Todo.css`)
- 사용 API: `GET /assignments?role=COST|QUALITY|SALES`(모든 검토의 그 부서 요청, 검토 번호·파일 이름·보낸 기록·회신 기록 포함), `POST /runs/{id}/assignments/send`(엔지니어가 보내기·다시 보내기), `PUT /assignments/{id}`(엔지니어가 회신 받음 표시·되돌리기)
- 메일은 시스템이 보낸다: 엔지니어가 판정을 확정하면(연결된 판정이 모두 사람 확인됨) 아직 안 보낸 요청을 부서별로 한 통씩, 채택한 제안 포인트는 채택할 때. 판정이 없는 요청은 이 화면의 [보내기]
- 예정 API: 직접 요청 만들기
- v4.96 구현됨 (change `update-todo-search`, 2026-11-01): 세 부서 요청을 `GET /assignments`(role 생략) 한 번으로 받아 화면에서 거름, [재요청]은 `POST /runs/{id}/assignments/send`에 `resend: true`, 내보내기는 `POST /assignments/export`(`role`, `assignment_ids`). 목업과 다른 곳은 `SCR-13_공유.md` 11~15

## 메일

- 제목 `[협조 요청] <검토 번호> <사업명>`, 받는 사람은 부서 주소(`RFP_MAIL_COST`·`RFP_MAIL_QUALITY`·`RFP_MAIL_SALES`).
- 본문: 제출 마감, 회신 기한, 요청마다 [종류](팀 가정) · 요구사항 · 원문 위치. 엑셀 첨부(No., 요청 종류, 요구사항, 원문 위치, 팀 가정, 회신 칸).
- 개발·시연은 Mailpit(<http://localhost:8025>)에서 받은 메일을 본다. 밖으로 나가지 않는다.

## 수용 기준 (Given / When / Then)

- **Given** 품질 담당에게 간 형식시험 요청, **When** 엔지니어가 품질 담당 탭을 고르면, **Then** "안 보냄" 또는 "회신 대기" 줄과 검토 번호, 파일 이름이 든 위치, 상태별 수. (수신 부서별 요청 현황)
- **Given** 메일 보낸 지 24시간이 넘은 요청, **When** 화면을 열면, **Then** "24시간 넘게 회신 없음", 상세 진행에 "다시 연락 필요". (24시간 넘게 미확인)
- **Given** 안 보낸 요청, **When** 엔지니어가 [보내기]를 누르고 상세 창에서 회신 요지를 적고 "회신 받음 표시"를 누르면, **Then** 줄이 "회신 받음"으로 흐려지고 회신 요지와 진행의 "회신 받음"이 보인다. (받는 담당자의 확인)
- **Given** 발송 실패한 요청, **When** 엔지니어가 열면 "발송 실패"와 [다시 보내기], 품질 담당이 열면 단추가 없다. (발송 실패 다시 보내기와 담당자는 읽기만)
- **Given** 요청하기 창, **When** 적고 보내면, **Then** 예시 알림만, 요청 수 그대로. (요청하기 예시)

### 수용 기준 (v4.96)
