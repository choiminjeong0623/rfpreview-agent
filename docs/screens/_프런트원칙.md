# 프런트 원칙

백엔드가 OpenSpec과 AGENTS.md 5·6장 규칙으로 만들듯, 프런트도 이 문서의 규칙으로 만든다.
화면 하나를 고치거나 새로 만들 때 이 문서와 `_공통규칙.md`(화면 상태·라벨·권한), `_디자인.md`(목업 CSS)를 함께 본다.
정한 change: `add-ui-foundation` (2026-11-01).

## 1. 일하는 순서

1. 목업(기준 판 `mockup/Spec2Win_목업_v4.96.html`)에서 화면을 본다.
2. 화면 명세 `SCR-xx-<이름>.md`를 먼저 쓰거나 고친다(`_템플릿.md`). 목업과 다르게 만들 곳은 `SCR-xx_공유.md`.
3. OpenSpec change를 만들고 `review-workspace` Scenario로 수용 기준을 옮긴다.
4. 공통 부품(6장)으로 화면을 만들고, Scenario마다 e2e(`frontend/e2e/<change 이름>.spec.ts`)를 쓴다.
5. API 응답 칸을 바꿨으면 `npm run gen:api`.

## 2. 폴더

| 폴더 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| `src/styles/tokens.css` | 색·간격·글자 크기·그림자 토큰 (5장) | 화면 규칙 |
| `src/mockup/` | 목업 CSS 원본 (고치지 않음, `_디자인.md` 1장) | 우리가 쓴 CSS |
| `src/ui/` | 공통 부품과 `ui.css` (6장). 화면 하나만 쓰는 것은 넣지 않는다 | API 호출 |
| `src/components/` | 여러 화면이 같이 쓰는 도우미: `useLoad`, 라벨(`labels.ts`), 형식(`format.ts`), 판정·결재 계산 | 화면 |
| `src/shell/` | 앱 틀: 메뉴, 머리글, 주소(`router.ts`), 사용자(`session.tsx`) | 화면 내용 |
| `src/views/` | 화면 하나 = 파일 하나(`Home.tsx`). 탭이 많은 화면은 폴더(`views/detail/JudgeTab.tsx`) | 여러 화면 공용 |
| `src/views/examples/`, `src/examples/` | 백엔드 없는 예시 화면과 예시 데이터(`SCR-xx.ts`) | 실제 데이터 |
| `src/api.ts` | API 호출 함수 전부. 화면은 `fetch`를 직접 부르지 않는다 | 화면 상태 |
| `src/api.gen.ts` | 응답 타입 (자동 생성, 손으로 고치지 않음) | |

## 3. 상태 관리

- **서버 데이터는 `useLoad`(`components/useLoad.ts`)로 받는다.** `const { data, error, reload } = useLoad(() => api.x(id), [id])`. 늦게 온 앞선 응답은 버린다. 처리 중처럼 계속 바뀌는 것은 `useRepeat(active, reload)`로 5초마다.
- 고친 뒤에는 그 화면의 `reload()`를 부른다. 응답을 손으로 고쳐 넣지 않는다(서버가 정답).
- **화면 안 상태는 컴포넌트 `useState`.** 거르기·쪽 번호·고른 줄처럼 주소를 공유하거나 뒤로 가기로 돌아와야 하는 것은 주소(`#/reviews/12?f=…`)에 둔다.
- 화면 사이에 나누는 것은 지금 사용자(`useSession`)와 알림(`useToast`) 둘뿐이다. 새 전역 상태를 만들려면 change의 design.md에 이유를 적는다.
- TanStack Query는 쓰지 않는다(이유는 change `add-ui-foundation` design.md 2). **다시 볼 기준:** 같은 데이터를 3개 이상 화면이 동시에 부르거나, 낙관적 갱신이 필요해질 때.

## 4. 이름

- 부품·화면: `PascalCase` 파일 하나에 같은 이름의 부품(`DataTable.tsx` → `DataTable`). 화면 부품 이름은 화면 이름(`ReviewList`), 탭은 `<이름>Tab`, 창은 `<이름>Dialog`.
- 훅: `useXxx`. 도우미 함수 파일: `camelCase.ts`.
- 식별자는 영어, 주석·화면 문구는 한국어 (AGENTS.md 6장).
- CSS 클래스: 목업 클래스는 그대로 쓴다. 우리가 더하는 클래스는 짧은 머리말로 겹침을 막는다: 공통 부품 `ui*`, 앱 틀 `sh-*`·`sb-*`, 화면은 그 화면 CSS 파일 안에서만.
- 라벨(판정 결과·유형·단계)은 `components/labels.ts`에서만 정한다. 화면에서 글자를 새로 쓰지 않는다(`_공통규칙.md` 2장).

## 5. 디자인 토큰

- 색·간격·글자 크기·둥글기·그림자는 `src/styles/tokens.css`의 변수로 쓴다: `color: var(--c-muted)`, `gap: var(--s-2)`.
- 값은 목업 v4.96 CSS에서 읽은 값 그대로다. 새 값이 필요하면 먼저 목업에서 찾고, 없으면 `tokens.css`에 이름을 붙여 더한다.
- `npm run lint`가 우리가 쓴 CSS·TS(`src/` 중 `mockup/`, `tokens.css`, `api.gen.ts` 빼고)에서 `#RRGGBB`·`rgb(a)(` 를 찾으면 실패한다(`scripts/check-tokens.mjs`).
- 상태 색은 뜻으로 고른다: 빨강 문제(일탈·실패), 주황 확인 필요, 파랑 정보·진행, 초록 끝남·준수, 회색 그 밖. 팀 가정은 `--c-purple`.
- 줄바꿈은 낱말(띄어쓰기) 단위다: `body`에 `word-break: keep-all; overflow-wrap: break-word`(`ui/ui.css`). 칸보다 긴 낱말(파일 이름·URL)만 낱말 안에서 끊긴다. 글이 긴 칸이 있는 표는 `table-layout: fixed`와 `colgroup`으로 칸 폭을 정해, 긴 파일 이름 칸이 설명 칸을 누르지 않게 한다.

## 6. 공통 부품 (`src/ui/`)

모양은 `#/dev/ui`(부품 견본 화면, 메뉴에는 없음)에서 본다. **새로 만들거나 고치는 화면은 이 부품을 쓴다.** 옛 화면은 고칠 때 바꾼다(4단계, 화면 하나씩).

| 부품 | 쓰는 법 | 규칙 |
|---|---|---|
| `PageTitle` | `<PageTitle title="검토 목록" sub="…">단추</PageTitle>` | 화면마다 `h1` 하나 |
| `Badge` | `<Badge tone="red">일탈 후보</Badge>` | tone은 5장 뜻대로 |
| `Button` | `<Button kind="primary" icon="check" disabledReason={reason}>` | 못 누르는 단추는 숨기지 않고 `disabledReason`으로 잠근다. `busy`면 보내는 중 |
| `Modal` | `{open && <Modal title onClose footer>…</Modal>}` | Esc·바깥·닫기로 닫힘, 첫 입력 칸에 초점, 닫히면 연 단추로 |
| `DataTable` | `columns`, `rows`(null이면 로딩), `error`·`onRetry`, `empty`, `page`·`size`·`total`·`onPage`·`onSize` | 맨 왼쪽 순번이 쪽을 넘겨도 이어진다. 거르기를 바꾸면 `page`를 1로 |
| `Loading`·`Empty`·`ErrorBox` | 표가 아닌 영역의 상태 | 문장은 `_공통규칙.md` 1장 |
| `useToast` | 누른 동작의 결과는 `toast.done('저장했습니다')`, 시스템 알림은 `toast.show(msg)`, 오류는 `toast.show(msg, 'error')` | `done`은 아래 가운데에 하나만 4초(행동 줄 위). `show`는 오른쪽 위에 쌓임, 오류는 닫을 때까지 (update-action-toast-place) |

## 7. 오류 처리

- API 오류는 `api.ts`가 `Error(서버 detail 문장)`로 던진다. 화면은 그 문장을 그대로 보인다(서버 문장이 한국어).
- **불러오기 실패**: 그 영역 안에 오류 문장 + [다시 불러오기] (`DataTable error`·`ErrorBox`). 화면 전체를 비우지 않는다.
- **동작 실패**(확정·저장·보내기): 누른 단추 옆이나 창 아래에 문장을 보이고 입력 값은 그대로 둔다. 화면 밖으로 나가는 결과(메일 보냄 등)는 알림으로도 알린다.
- **성공**: 짧은 성공 알림(`useToast`). 같은 문장이 이미 떠 있으면 하나만.
- 권한·단계 때문에 못 하는 것은 오류를 띄우지 않고 미리 단추를 잠근다(`disabledReason`).
- 네트워크가 끊기면 머리글이 알린다(앱 틀). 화면은 따로 처리하지 않는다.
- `catch`로 오류를 삼키지 않는다. 삼켜야 하면 그 자리에 이유를 주석으로 적는다.

## 8. 테스트

- 명세 Scenario마다 e2e 하나, 테스트 이름 = Scenario 이름 (AGENTS.md 3장).
- 실행 데이터가 필요하면 `e2e/helpers.ts`의 합성 문서(고객 원문 아님)를 쓴다. 부품만 보는 테스트는 `#/dev/ui`에서 한다(`e2e/ui-foundation.spec.ts`).
- 화면 명세 수용 기준 줄 끝 `(이름)`은 e2e `test('이름')`과 같게 쓴다. 한 테스트가 다른 이름의 시나리오·기준도 보면 `test(` 바로 위에 `// Scenario: 이름 / 이름`을 단다. 백엔드 테스트는 docstring `Scenario: 이름 / 이름 — 설명`.
- 이 이름으로 `docs/추적표.md`(FR → 스펙 → 화면 → 컴포넌트 → 테스트)가 만들어진다. 화면 명세나 테스트 이름을 바꾸면 `npm run trace`로 다시 만들어 함께 커밋한다. 새 화면·컴포넌트 파일은 `docs/추적_연결.json`에 적는다 (`add-spec-trace`).
- 화면을 바꾸면 `npm run compare:mockup -- SCR-xx`로 목업 v4.96과 나란히 찍어 보고 `compare-out/layout.json`의 빠진 영역을 확인한다. 의도한 차이는 `SCR-xx_공유.md`에, 결과는 `검수표.md`에.
- 끝내기 전: `npm run lint && npm run check:api && npm run check:trace && npm run build`.
