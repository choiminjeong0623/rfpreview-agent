# SCR-03 홈: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | "협조 대기"가 검토 단계 하나 | 담당자 확인 단계이면서 미확인 협조 요청이 남은 검토 | 저장하는 단계에는 협조 대기가 없다. 협조 요청 상태로 코드가 나눈다 |
| 2 | 분석 중 카드: "요구사항 찾기 88 %", "약 5분 남음" | "<처리 단계> n %", "처리 중" | 진행률은 처리 단계 순서로만 센다. 남은 시간은 알 수 없다 (SCR-02와 같음) |
| 3 | 실패 알림: 처음·마지막 발생, 자동 재시도 3회, 멈춘 위치 "733줄 중 412줄" | 멈춘 단계, 발생 시각, "정해진 횟수 모두 실패" | 저장한 값만 쓴다 (SCR-11_공유 2·7번과 같음) |
| 4 | 재시도 · 코드 규칙만으로 계속 단추가 눌림 | 잠김 | 다시 시도 API가 없다 (CR-12) |
| 5 | 판정 기준 변경 알림과 "영향받는 검토 다시 판정" 창 | 없음 | 제품표·규칙 변경을 추적하지 않는다. 바뀐 것이 없는 상태(알림 없음)와 같다 |
| 6 | 결재 대기 카드: 결재자 이름, 상신 시각 | "결재자 확인 중" | 검토 목록 API에 결재자가 없다. 카드를 누르면 결재 대기 화면에서 보인다 |
| 7 | 사업별 머리: 사업 번호, "사업 상세" 연결 | 사업에 연결된 검토만 사업 번호와 "사업 상세" 연결. 연결이 없으면 사업 이름, 고객사 · 국가만 | 사업 연결은 검토 등록에서 고른다 (`add-project-status`). 연결하지 않은 검토는 사업 화면이 없다 |
| 8 | 팀 업무: 사람 6명, 접속 상태, "도움 요청" | 앱 사용자, 역할, 접속 상태 없음 | 접속·도움 요청 기록이 없다. 하는 일은 역할에 따라 코드가 정한다 |
| 9 | 공지사항 · 시스템 공지 · 자료실 · 행사가 실제 글처럼 보임 | 같은 모양에 예시 띠 | 게시판·행사 API가 없다. 사람 이름은 역할로, 장소는 "예시 사업장"으로 바꿨다 |
| 10 | 엔지니어 화면만 있음 | 엔지니어는 내 검토, 다른 역할은 모든 검토 | 승인자·담당자에게도 홈이 필요하다. 승인자 할 일은 결재 대기 칸에서 본다 |
| 11 | 열마다 카드 전부 | 열마다 8장, 넘으면 "n건 더 · 검토 목록에서 보기" | 실제 데이터는 검토가 많다 |
