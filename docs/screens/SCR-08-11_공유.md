# SCR-08-11 일탈 목록·질의서 초안: 목업과 다르게 만든 것 (공유)

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 진행 막대가 정해진 속도로 100 %까지 | 응답이 올 때까지 90 %에서 멈췄다가 받으면 100 % | 실제로 서버가 파일을 만든다 |
| 2 | 질의서 단계 "질의 문장을 영어로 다듬는 중" | "원문 위치와 질의 문장 붙이는 중" | 내려받을 때 문장을 다시 쓰지 않는다 (CR-07, 문장은 저장된 초안 그대로) |
| 3 | 파일 이름 "일탈 목록 초안.docx" | "일탈 목록 초안_<검토 번호>.docx" | 여러 검토 파일을 구분한다 |
| 4 | 문장 칸은 고치면 바로 반영, 확정·빼기 없음 | 고치면 사유 칸 + "문장 저장", 그리고 "문장 확정"·"목록에서 빼기" | 문장 고치기·빼기는 사유가 필요하다(`POST /actions`). 목록 항목도 후보라 사람이 확정한다 (CR-08) |
| 5 | 위험 조건에서 나온 질의 문장 자리 없음 | 위험 조건 줄을 펼치면 그 질의 문장 | 위험 조건 질의는 판정 줄이 없어 판정 패널에 안 나온다 |
| 6 | 예전 화면의 목록 창(일탈·질의 목록 카드) | 뺌 | 목업에는 창이 없고 단추가 바로 파일을 만든다 |
| 7 | 고친 문장 상태 | "확정" | 백엔드는 고친 목록 문장을 확정으로 본다 (`output_item` EDIT → CONFIRMED) |
