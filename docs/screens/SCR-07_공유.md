# SCR-07 검토 등록: 목업과 다르게 만든 것 (공유)

목업의 등록 화면은 문서에서 프로젝트 이름·고객사·마감일·현장 조건·손실 단가를 **자동으로 뽑고**, Lot마다 검토를 나누고, 비교 제품과 결재선을 고른다.
지금 시스템에는 그 기능이 없어(자동 추출은 `add-review-info` Non-Goal, 원문 위치 CR-02와 빈칸 채우기 금지 CR-04 때문에 별도 change가 필요) 아래처럼 바꿨다.

| # | 목업 | 앱 | 이유 |
|---|---|---|---|
| 1 | 2단계 "자동 추출 확인 · 틀린 값만 고치기", 값마다 "자동 추출" 꼬리표와 원문 위치 | 2단계 "검토 정보 · 사업명 · 마감일", 직접 입력 | 자동 추출이 없다. 없는 원문 위치를 보이면 CR-02 위반 |
| 2 | 설치 고도, 최고 주위 온도, RFP 접수일, 손실 환산 단가 | 없음 | 현장 조건·단가는 처리 중 문서에서 찾아 판정·손실 환산에 쓴다. 접수일은 저장할 곳이 없다 |
| 3 | 사업 연결 "고객사·프로젝트 이름으로 추천" | 추천 없이 사람이 고름 | 자동 추출이 없다. 새 사업 만들기 / 진행 중인 사업에 추가는 목업과 같다 (`add-project-status`) |
| 4 | 파일 표에서 문서 종류·Lot 고르기, 묶음·언어 표시 | 문서 종류·묶음 고르기(규칙 추천으로 채움), 언어 표시, 판정 칸(판정 대상 여부·추천 이유) 추가. Lot 없음 | 판정할 문서는 사람이 시작 때 정한다(`add-document-confirm`, CR-08·09). 문서 종류는 목업 7종이 아니라 API 6종(명세서 [결정]). Lot은 스펙에 없다 |
| 5 | 3단계 Lot 카드와 비교 제품 추천 | 담당 엔지니어 카드 하나 | Lot 나누기는 Non-Goal. 비교 제품은 판정 때 코드가 고르고 검토 상세에서 바꿔 본다 |
| 6 | 결재자(필수)·견적·품질·영업 담당 고르기 | 없음 | 결재자는 결재 상신 때 고른다(`update-approval-flow`). 협조 담당은 역할별로 자동 전달한다(FR-11) |
| 7 | 이 고객과의 지난 입찰 | 없음 | 입찰 이력은 범위 밖(예시 화면) |
| 8 | "받은 메일 첨부에서 가져오기" | "서버에 둔 RFP에서 고르기" | 메일 연동이 없다. 서버 폴더(`data/private/rfp_docx`)에서 고르는 기존 기능을 이 자리에 둔다 |
| 9 | 다음·등록을 누르면 진행 막대 겹창 | 단추 글자가 "등록하는 중…" | 자동 추출이 없고 등록은 요청 하나라 기다릴 단계가 없다 |
| 10 | 등록 끝 문장 "비교 제품 … · 결재자 …" | "문서 n개 · 제출 마감 …" | 등록 때 비교 제품·결재자를 고르지 않는다 |
| 11 | (목업에 없음) 판정할 문서가 없을 때 | 1단계 파일 표에서 판정 대상(묶음 A·B)이 하나도 없으면 "판정 대상 문서가 없습니다…" 안내와 함께 "다음"을 막는다. 서버도 같은 경우 검토를 만들지 않고 거절한다 (`reject-unjudged-registration`) | 묶음 C만이면 약 10분 분석해도 판정·보증값이 0건이다(CR-09, 10-31 주말 검토) |
