## 공개본을 만들며 바꾼 것

이 저장소는 팀 저장소(비공개)의 2026-11-10 시점 코드를 바탕으로, 아래를 바꿔 **첫 커밋 하나로** 새로 시작했습니다.

### 1. 커밋 이력을 가져오지 않음

팀 저장소 이력(커밋 204개)에는 한때 커밋됐다가 지워진 고객 문장 실험 파일과 팀원 개인 메일 주소가 남아 있습니다([04 장애 분석 #9](04-incidents.md#9-고객-rfp-문장이-든-실험-파일이-커밋됨)). 이력을 다시 쓰는 대신 정리한 코드로 새로 시작했습니다. 공개 전에 팀 저장소 이력 전체를 검사한 결과, `.env` 커밋은 없었고 API 키 모양 문자열(Gemini·OpenAI·GitHub·AWS·개인 키)도 없었습니다.

### 2. 원본 RFP 파일 이름·문서 번호를 별칭으로

코드·테스트·스펙·문서 27곳에 나오던 원본 파일 이름과 사양서 번호를 `RFP01 Bidding Forms`, `RFP04 GIS Specification`처럼 **번호 + 문서 종류**만 남긴 별칭으로 바꿨습니다(`data/seed/document_catalog.csv` 1~22번 줄 등). 문서 종류 판별 규칙이 쓰는 낱말(bidding forms, specification, testing 등)은 별칭에 남겨 분류 동작은 같습니다. 원문 파일이 없으므로 공개본에서 원문 기반 테스트는 건너뜁니다.

### 3. 기존 팀 문서 대신 새 문서

기획서와 검토 문서(`docs/review/`), 목업 HTML에는 고객 RFP 문장을 짧게 인용한 곳이 있어 넣지 않았습니다. 대신 `docs/01`~`06`을 고객 문장 인용 없이 새로 썼습니다. 화면 명세(`docs/screens/`), 추적표, 기능 요구사항 명세서는 별칭 바꾸기 뒤 남겼습니다. 명세서의 수용 기준에 남은 영어 예문은 "Type Test Report / Required"처럼 업계 공통 문구입니다.

### 4. 현장 이력 데이터를 합성 표본으로

운영진 C/S 데이터 대신, 연결표가 쓰는 고장 8종을 새 문장으로 쓰고 해결 사례 19건(그중 1건은 "의심 사례" 시나리오용)을 만들었습니다. 해결 사례 문장마다 `[합성 사례]`를 붙였습니다. 이에 맞춰 테스트 기대값(해결 사례 수, 고장 설명 문장)을 바꿨습니다(`backend/tests/test_field_history.py`).

### 5. 제품 사진 제거

`frontend/public/product-photos/`를 빼고 사진 표(`productPhotos.ts`)를 비웠습니다. 화면은 사진이 없으면 사진 칸을 보이지 않습니다. 사진을 확인하는 E2E 한 건(`e2e/reference.spec.ts`)은 공개본에서 실패할 수 있습니다.
