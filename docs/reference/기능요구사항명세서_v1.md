## 2. 공통 규칙

모든 기능에 똑같이 적용합니다.

| ID | 규칙 | 내용 |
|---|---|---|
| CR-01 | 역할 나누기 [결정] | **숫자와 판정 규칙은 코드, 문장 읽기와 쓰기는 AI, 확정은 사람.** AI는 숫자 계산, 판정, 후보 고르기, 분기 선택, 확정을 하지 않음 |
| CR-02 | 근거 묶음 [결정] | 시스템이 만드는 모든 값은 `{값, 원문 위치, 신뢰도, 가정 여부}`를 함께 저장. 원문 위치가 없는 값은 결과로 내보내지 않고 "확인 필요" |
| CR-03 | 원문 위치 | `파일 번호 + 절(또는 표 이름) + 행 번호(또는 표의 행·칸)`. 같은 내용이 여러 곳에 있으면 위치를 모두 저장 |
| CR-04 | 지어내지 않음 [결정] | 없는 값은 비워 두고 "확인 필요". AI가 빈칸에 값을 만들지 않음 |
| CR-05 | 가림 표시 | [REDACTED] 등은 "값 없음"으로 저장하고 추측하지 않음 |
| CR-06 | 팀 가정 표시 | 가정 값(변압기 손실값, 제품표의 팀 합성 비교값 등)이 들어간 결과에는 화면·산출물에 항상 "팀 가정". 판정·보증값은 그 결과에 쓴 제품 칸이 팀 가정일 때 표시 |
| CR-07 | 숫자 일치 검사 | AI가 쓴 문장 속 숫자는 자리표시자로 두고 코드가 채움. 채운 뒤 근거 값과 다시 대조, 다르면 경고. 자리표시자 뒤 조사(은/는, 이/가, 을/를, (으)로, 과/와)는 채운 값의 끝 글자에 맞춰 코드가 고름(예: "GIS-145-40은") [결정]<br>**AI 답 검사 보강** [결정 11-01]: ① AI에 여러 줄을 묶어 물으면 답마다 줄 번호를 받아 번호로 맞춤(번호가 빠지거나 겹치면 다시 물음). ② 문장 초안은 주어진 자리표시자를 모두 써야 하고, 빠지거나 없는 자리표시자를 쓰거나 경쟁 제품 비교가 있으면 그 줄만 코드가 쓴 기본 문장으로 바꿈. ③ 위험 조건 설명의 숫자와 배수 말(두 배, 절반, twice 등)은 그 문장이 댄 근거 조각과 사실에 있는 것만 허용. ④ 근거 대조에서 버린 설명은 이유(없는 근거 ID / 근거에 없는 인용 / 근거에 없는 숫자)를 위험 조건에 남기고, 실행 기록에 "AI 설명 버림 n건"으로 보임 |
| CR-08 | 후보까지만 [결정] | 위험 조건, 일탈, 질의, 보증값, 제안 포인트는 모두 "후보". 확정은 사람(FR-10) |
| CR-09 | 판정 범위 [결정] | 적합성 판정과 보증값 후보 작성은 **묶음 A·B만**. 묶음 C·D는 추출·유형 표시·위험 조건 찾기까지 |
| CR-10 | 단위 환산 안 함 [결정] | 원문 단위 그대로 저장. 단위가 다르면 비교하지 않고 "확인 필요" |
| CR-11 | 재현성 | 같은 입력과 같은 사전·제품표에는 숫자·판정 결과가 늘 같음 |
| CR-12 | AI 오류 | 정해진 횟수만 재시도, 그다음 멈추고 "처리 실패 — 다시 시도". 처리 중인 검토는 사람이 취소할 수 있고(다음 진행 기록 때 멈춤), 실패·취소한 검토는 사람이 "다시 시도"하면 같은 파일·같은 분류로 처음부터 다시 돌리되 이미 처리한 문서는 다시 쓴다(NFR-05) [결정]. **이어서 다시 시도** [결정 11-01, C2]: 단계마다 흐름 상태를 DB에 저장해 두고, 다시 시도하면 끝난 단계는 건너뛰고 멈춘 단계부터 이어서 처리함(이미 낸 AI 설명을 다시 묻지 않음). 저장된 흐름이 없으면 처음부터<br>**오류 종류별 처리** [결정 11-01]: 연결 오류·시간 초과·서버 오류만 정해진 횟수 재시도. 답의 형식이 틀리면(검사 실패) 같은 질문을 되풀이해도 같은 답이 나오므로(temperature 0) 다시 묻지 않고, 묶음 질문은 바로 반으로 나눠 묻고, 위험 조건 설명은 "형식 오류"로 버리고, 문장 초안은 코드 기본 문장으로 바꿈. 키·권한·모델 설정 오류는 다시 묻지 않고 바로 멈추고 "AI 키 또는 모델 설정 오류 — 설정 확인"을 알림 |

## 3. 지키기·공통 기능 (Must)

### FR-01 문서 분류 (Must)

| 칸 | 내용 |
|---|---|
| ① 목적 | 문서 꾸러미(묶음)와 문서 종류를 알아야, 어떤 깊이로 처리할지(판정 여부)와 어느 규격 체계·제품군으로 볼지가 정해짐 |
| ② 입력 | docx 또는 PDF 파일, 파일명. **PDF** [결정 11-02]: 글자가 든 PDF는 쪽마다 글자 줄과 표를 읽어 docx와 같은 단락·표 행으로 바꾼 뒤 같은 단계로 처리. 글자가 없는(스캔한) PDF는 판독 불가 |
| ③ 출력 | `document` 행: 파일 번호, 묶음(A/B/C/D), 문서 종류(입찰 서식 / 요구 사양 / 구매 사양 / 시험 사양 / 공급사 사양·답안), 사업(project) ID, 언어, 주 규격 체계(IEC / IEEE·UL / KS·한전 ES), 판정 대상 여부, 원본·정정본 관계(같은 문서의 다른 판이면 짝 문서 ID) |
| ④ 규칙 | 코드: 파일명·첫 장의 정해진 표현으로 1차 판별. AI: 첫 장 요약으로 보조 판단. 둘이 다르면 "확인 필요". **문서 종류별 처리기** [결정 11-01, C1]: 문서 종류(입찰 서식·요구 사양·시험 사양·구매 사양·공급사 사양·물량표(BOQ)·모름)마다 처리기 표(코드)를 두고, 처리기가 AI 문장 구분·유형 질문에 넣을 문서 종류 설명 한 줄과 처리 뒤 점검 기준(예: 입찰 서식인데 표 칸 요구값 0줄, 공급사 사양인데 C/D/E 표시 0줄)을 정함. 추출 규칙은 공통 규칙에 종류별 규칙을 더함 [결정 11-02, C1 종류별 추출]: 공급사 사양(C/D/E 표시가 있는 문서)은 표의 조항 줄을 표시가 없어도 요구사항 후보로, 입찰 서식은 표 밖 서식 작성 안내 문장("fill out this form" 등)을 작성 규칙으로(위험 표현이 든 문장은 그대로). 물량표(BOQ: 품목·수량·단위 표)는 표 줄이 하나도 없으면 점검에 걸림 [결정 11-02, C1 새 종류]. 단선도의 기호·연결 해석은 범위 밖(그림 속 글자는 OCR로 읽음, [결정 11-02]). 점검에 걸리면 걸린 이유를 남기고 "확인 필요"로 둠. AI가 있고 AI 답이 점검 결과를 바꿀 수 있는 점검(요구사항 줄·시험 유형 줄)이면, 종류 설명 없는 일반 처리기로 **점검에서 떨어진 부분만** 한 번 다시 물음: AI가 요구사항을 모두 작성 규칙·설명으로 바꾼 절은 문장 구분을, 유형을 못 정한 줄은 유형을 다시 묻고, 나머지 절·줄은 첫 답을 그대로 씀. 표 칸·C/D/E 표시 점검은 AI 답과 상관없어 다시 묻지 않음 [결정 11-02, C1 줄 단위 다시 처리]. 어느 처리기를 쓸지·다시 처리할지는 코드가 정함(CR-01). 원본·정정본 쌍은 AI가 후보(제목·개정 표기·내용 겹침)를 내고 사람이 확인 [결정]. 사업 ID는 팀이 정한 묶음 표를 따름 (1·2 / 19~22 / 3~8은 확인 필요) |
| ⑤ 예외 | 이미지만 있는 문서(파일 8)는 "판독 불가"로 두고 이후 단계를 건너뜀. **OCR** [결정 11-02]: 글자 층이 없는(스캔한) PDF 쪽과 docx 그림 속 글자는 내 컴퓨터·서버의 OCR 엔진(Tesseract, 영어·한국어)으로 읽어 단락으로 더하고, 그 줄에서 나온 요구사항은 추출 방법 "OCR"·낮은 신뢰도·문서 "확인 필요"로 둠. 글자 신뢰도가 낮은 줄은 버림(CR-04). AI는 쓰지 않음(CR-01). OCR 엔진이 없으면 지금처럼 판독 불가. 도면 기호·연결의 뜻 해석은 범위 밖. 쌍 후보가 없으면 빈칸. 올린 문서 가운데 판정 대상(묶음 A·B이고 글자를 읽을 수 있음)이 하나도 없으면 분석을 시작하지 않고 등록을 거절한다. 등록 화면은 다음 단계로 넘어가지 않고 묶음을 바꾸거나 판정 대상 문서를 더하라고 안내한다(CR-09; 묶음 C만으로 약 10분 분석해도 판정 0건이라서) [결정]. **문서 추가**: 분석을 마친 검토(담당자 확인 단계)에 정정본·추가 문서(Addendum)를 더하면 처음 문서와 함께 같은 검토를 다시 분석한다. 처리한 문서는 다시 쓰고(AI를 다시 부르지 않음), 사람이 확정·수정·반려한 판정·위험 조건·보증값은 같은 줄(같은 요구값·비교 제품·비교 규칙)이면 이어받는다. 엔지니어만, 상신 전에만 [결정] |
| ⑥ 수용 기준 | **Given** 파일 1(RFP01 Bidding Forms) / **When** 분류 / **Then** 묶음 A, 입찰 서식, 판정 대상, 주 규격 체계 IEC<br>**Given** 파일 13(RFP13 Medium-Voltage Switchgear) / **When** 분류 / **Then** 묶음 C, 요구 사양, **판정 대상 아님**, 주 규격 체계 IEEE·UL<br>**Given** 파일 1과 파일 2(RFP02 Employers Requirement Requirement) / **When** 쌍 확인 / **Then** "데이터시트 항목 상당수 겹침" 쌍 후보로 표시(확정은 사람)<br>**Given** 파일 13 하나만 묶음 C 그대로 / **When** 검토 등록 / **Then** 검토를 만들지 않고 "판정 대상 문서 없음" 안내<br>**Given** 판정 1줄을 확정한 검토 / **When** 추가 문서를 더해 다시 분석 / **Then** 그 줄은 "확정" 그대로, 추가 문서의 줄은 "후보", 이력에 "문서 추가" 1건 |
| ⑦ 관련 | 기획서 4-3 묶음별 깊이 |

### FR-04 유형 표시 (Must)

| 칸 | 내용 |
|---|---|
| ① 목적 | 같은 표 안에서도 담당자가 갈리는 줄(기술 / 시험 / 비용 / 자격)을 나눠, 필요한 사람이 자기 몫만 보게 함. 규격 목록 화면을 따로 만들지 않고 "적용 규격·인증" 유형으로 대신함 [결정] |

AI에는 줄과 함께 그 줄이 속한 절(번호·제목), 표 이름, 표 안 구분 행 제목을 문맥으로 줌(유형은 문장만으로 정하기 어려움) [결정 11-01]. **사람 유형 고치기와 확정 예시** [결정 11-01, C3]: 엔지니어·승인자가 판정 상세·협조 요청 상세에서 주 유형을 고치면 근거 "사람"으로 남고 이력에 남음(담당 전달도 다시 만듦). AI에 물을 때 줄마다 다른 문서에서 사람이 고친 줄 가운데 뜻이 가장 가까운 것(문장 벡터 0.80 이상, 최대 2개)을 "사람이 고른 예"로 함께 줌(RAG). 정답지에 든 문장은 예시로 쓰지 않음(K13 채점 오염 방지). 예시는 참고일 뿐 유형은 여전히 AI 답과 규칙으로 정함 |

| ⑥ 수용 기준 | **Given** "Type Test Report / Required" / **Then** 주 유형 = 시험<br>**Given** "ISO 9001 or equivalent certificates / Required" / **Then** 주 유형 = 제조사 자격<br>**Given** 파일 1의 손실 환산 조항(8238행) / **Then** 주 유형 = 비용 영향, 보조 유형 = 기술 성능<br>**Given** 다른 문서에서 사람이 "시험"으로 고친 비슷한 줄 / **When** 규칙에 안 걸린 줄을 AI에 물음 / **Then** 그 줄 질문에 그 예시가 함께 들어감 |
| ⑦ 관련 | 사례 4, 5, 10. FR-11의 입력 |

### FR-05 값 정리 (Must)

| ⑥ 수용 기준 | **Given** "<0.5" / % / 19번 / **Then** 숫자 0.5, 기호 <, 단위 %, 원문 "<0.5" 보존<br>**Given** "1.1 x 125/√3" / **Then** 형태 = 계산식, 결과 ≈ 79.4, 단위 kV<br>**Given** "As per IEC:62271-100" / **Then** 형태 = 규격 위임, 규격 = IEC 62271-100, 판정은 "확인 필요"<br>**Given** 파일 13의 "104 deg F (40 deg C)" / **Then** 104 °F와 40 ℃를 각각 원문 단위로 저장, 서로 환산하지 않음 |

### FR-06 위험 조건 찾기 (Must)

| 칸 | 내용 |

## 4. 내세우기 기능 (Must)

### FR-13 손실 환산 계산 (Must)

| 칸 | 내용 |
|---|---|
| ① 목적 | 기술 값(변압기 손실)이 입찰 평가 가격을 바꾸는 지점을 계산으로 보여 줌. 손실이 적으면 평가에서 유리하다는 강점의 근거가 됨 |
| ② 입력 | RFP 손실 환산 조항의 단가(파일 1 8239~8241행: 무부하 4,500 / 부하 3,200 / 보조 1,300 $/kW), product_master의 손실값(팀 가정) |

| ④ 규칙 | 코드만. 가산액 = Σ(단가 × 손실값). 손실값을 바꾸면 다시 계산. 결과는 "비용 영향" 유형으로 견적 담당에게(FR-11), 손실 환산 우위 후보로 FR-14에 넘김 |
| ⑤ 예외 | 손실값이 없으면 계산하지 않고 확인 필요. 단가 단위가 $/kW가 아니면 확인 필요 |
| ⑥ 수용 기준 | **Given** 단가 4,500 / 3,200 / 1,300, 손실값 60 / 300 / 8 kW(팀 가정) / **Then** 270,000 + 960,000 + 10,400 = **1,240,400 $**, 손 계산과 일치, "팀 가정" 표시<br>**Given** 손실값 없음 / **Then** 확인 필요 |
| ⑦ 관련 | 사례 5. K8 |

| 칸 | 내용 |
|---|---|
| ① 목적 | 기술 검토 엔지니어가 다른 부서에 필요한 줄을 손으로 골라 메일로 보내던 일과 누락을 줄임 |

AI가 없거나 실패해도 메일은 코드 문장으로 나감. 질문은 "AI 작성" 표시와 함께 본문·엑셀에 넣고 요청에 저장해 협조 요청 화면에서 봄 |

| ⑥ 수용 기준 | **Given** 비용 영향 유형 줄(손실 환산 조항) / **Then** 견적 담당 "내 할 일"에 1건<br>**Given** 채택된 제안 포인트 1건 / **Then** 영업 담당에게 전달 기록 1건<br>**Given** 품질 담당 요청 1건이 걸린 판정을 엔지니어가 확정 / **Then** 품질 담당 주소로 메일 1통, 요청은 "메일 보냄"<br>**Given** 이미 보낸 요청 / **When** 다른 판정 확정 / **Then** 다시 보내지 않음<br>**Given** 후보 칸이 없는 데이터시트 / **When** 엔지니어가 [영업에 넘기기] / **Then** 영업 주소로 엑셀 1통, 넘긴 기록 1건<br>**Given** 후보 칸이 남은 데이터시트 / **Then** 넘기지 않고 "후보 n칸을 먼저 확정"<br>**Given** 결재 승인된 검토 / **When** 인계 패키지 보내기 / **Then** zip 1개(일탈 목록·질의서·TBE·데이터시트)를 붙인 메일 1통<br>**Given** 견적 담당 요청 2건 / **When** 메일을 보냄 / **Then** 요청마다 견적 관점 확인 질문 1문장("AI 작성"), 숫자가 든 질문은 코드 기본 문장 |
| ⑦ 관련 | 사례 4. 화면 시안 "견적 담당 내 할 일". 시연은 이 화면 1개 [결정]. 협조 요청 화면(SCR-13)은 보낸 기록과 회신. 강사님 피드백 10-29(협업 부서는 사내 메일로 받음), minjeong 결정 10-31(시스템이 직접 발송). 시연은 확인용 메일 서버(Mailpit)만. 영업 인계는 목업 v4.57 데이터시트 "영업에 넘기기"와 계획 문서(10-31) 3장 '인계 패키지' |

### FR-12 공학 규칙 검산 (Should)

### FR-17 검토 도우미 (읽기 전용, Should, 11-01 추가)

| 칸 | 내용 |
|---|---|
| ① 목적 | 수천 줄 요구사항을 표 거르기만으로 찾기 어렵다(실제 입찰 양식 4,515줄). 엔지니어가 "시험 성적서를 요구하는 조항만 보여 줘"처럼 물으면 근거 줄을 원문 위치와 함께 찾아 준다. 10-29 강사님 피드백 "의심 부분 먼저", "근거 보기가 포인트" |
| ② 입력 | 분석이 끝난 검토 하나, 엔지니어의 질문(500자 이하) |
| ③ 출력 | 답 문장(AI가 씀)과 문장마다 근거 줄(요구사항 원문 또는 판정, 원문 위치), 찾은 경로(어떤 도구로 무엇을 찾아 몇 줄 나왔는지), 근거와 맞지 않아 뺀 문장 수 |
| ④ 규칙 | 도우미가 쓸 수 있는 도구는 읽기 세 가지뿐: 요구사항 글자 찾기(유형으로 거르기 가능), 판정 찾기(판정 값·항목·글자), 요구사항 한 줄 보기. 값을 바꾸거나 판정·확정하는 도구는 주지 않는다(CR-01·08). AI는 어느 도구로 무엇을 찾을지 고르고(최대 3번) 답 문장을 쓴다. 도구 고르기는 찾는 길일 뿐 판정·값을 정하지 않는다 [결정]. 코드가 답을 검증한다: 문장마다 근거 번호가 이번 질문에서 도구가 돌려준 줄이어야 하고, 문장의 숫자는 그 근거 원문에 있어야 한다(CR-07). 어긋난 문장은 뺀다. AI 오류는 정해진 횟수만 재시도(CR-12) |
| ⑤ 예외 | 원문 위치가 없는 근거는 내지 않고, 근거가 남지 않은 문장은 뺀다(CR-02). 남는 문장이 없으면 "근거를 찾지 못했습니다". AI 키가 없거나 AI가 끝내 답하지 못하면 질문 글자로 요구사항을 찾은 결과만 보인다(문장 없음). 분석 중·실패한 검토에는 묻지 못한다. 질문과 답은 저장하지 않는다 [결정] |
| ⑥ 수용 기준 | **Given** "The maximum ambient temperature for the GIS enclosure shall be 40 °C."가 있는 검토 / **When** "주변 온도 조건"을 물으면 / **Then** 답 문장과 그 줄의 원문 위치<br>**Given** AI가 도구가 주지 않은 근거 번호를 댄 문장 / **Then** 그 문장은 빠지고 "뺀 문장 1개"<br>**Given** AI 문장에 근거에 없는 숫자 / **Then** 그 문장은 빠짐<br>**Given** AI 키 없음 / **When** "ambient temperature"를 물으면 / **Then** 글자가 맞는 요구사항 줄과 위치만, 답 문장 없음 |
| ⑦ 관련 | 효율 개선 제안 4번(11-01, minjeong "효율 개선 나머지와 사전 추가 제안까지"). 보류(Could)의 "절 단위 검색"을 대신하지 않는다(절 목록 화면 아님) |
