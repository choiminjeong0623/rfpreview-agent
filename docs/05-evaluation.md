# 05. 평가 결과

## 읽는 법

- **실제로 잰 숫자만** 적었습니다. 사람이 손으로 할 때와 비교한 단축률처럼 재지 않은 것은 주장하지 않습니다.
- 숫자마다 **정답을 누가 정했는지**를 밝혔습니다. "사람"은 팀원이 확인한 정답, "코드"는 문서 안의 표시(예: 공급사가 줄마다 적은 준수 표시)로 코드가 만든 정답, "Claude 초안"은 AI가 만들고 사람이 아직 확인하지 않은 정답입니다. Claude 초안 기준 숫자는 근거가 약합니다([04 장애 분석 #8](04-incidents.md#8-ai가-만든-정답으로-ai를-채점해-결론이-뒤집힘)).
- 지표는 시스템 안의 "정답지·채점" 화면과 `rfp-db` 명령으로 코드가 계산합니다. 실험 스크립트는 `experiments/`에 있습니다.

## 1. 실제 RFP 1건을 처음부터 끝까지

실제 입찰 서식(데이터시트 49종이 든 문서) 1건, 모델 `gemini-3.8-flash`, 2026-11-03 실행 기록.

| 항목 | 값 | 의미 |
|---|---|---|
| 처리 시간 | **6분 16초** (문서 읽기·추출 4분 29초, 임베딩 57초, 판정 23초, 초안 6초) | 문서를 올리고 결과를 보기까지 |
| AI 비용 (추정) | **708원** (AI 호출 97회, 재시도 0) | 단가는 팀 가정 (1달러 = 1,500원) |
| 찾은 요구사항 | **4,891줄** | 엔지니어가 처음부터 읽던 양 |
| 제품과 비교한 줄 | 4,515줄 | |
| └ 자동 준수 | 68줄 | |
| └ 보증값 후보를 채운 칸 | **1,710칸** | 반복 입력을 줄임 |
| └ 사람이 꼭 볼 줄 | 2,737줄 = 일탈 후보 13 + 질의 후보 6 + 확인 필요 2,718 | 일탈·질의 19건은 원문 위치와 함께 맨 먼저 보임 |
| 일탈·질의 문장 초안 | 8건, 숫자 검사 모두 통과 | |
| 공학 검산 | 15건 중 위반 1건 (최대 순간 전류 100 kA ↔ 계산 125 kA) → 질의 후보 | 사람이 놓치기 쉬운 계산 불일치 |
| 기술 제안 포인트 후보 | 16건 | |

**솔직하게 볼 점.** "확인 필요" 2,718줄 중 **2,366줄(87 %)은 항목 사전에 없는 항목**이라 제품표의 어느 값과 비교할지 정하지 못한 줄입니다. 시스템은 이 줄을 추측하지 않고 이유별로 모아 보입니다(ADR-002의 대가). 일탈 후보 13건 중 3건(정격 전류)은 카탈로그 값으로, 10건은 팀 가정 비교값과 경계값("<0.5" 대 "0.5")에서 나왔습니다.

## 5. 측정의 한계

- 유형 22줄은 일부러 어려운 줄을 많이 넣은 표본이라 82 %를 문서 전체 정확도로 읽으면 안 됩니다. 같은 줄에서 전후를 비교했으므로 개선 방향은 믿을 만합니다.
- 공급사 답안 K1 100 %는 AI를 끄고 잰 값이며, 정답(공급사 표시 줄)과 규칙의 정의가 비슷해 높게 나오기 쉬운 구조입니다.
- 사람 확인을 한 두 사람은 입찰 실무자가 아닌 팀원입니다.
- 합성 문서 결과는 "우리 데이터 범위 안에서는 정확하다"의 근거이지 일반 성능이 아닙니다.
- AI 결과는 실행마다 조금씩 다를 수 있어, AI 켬 수치는 한 번 잰 값입니다.
